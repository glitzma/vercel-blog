The JavaScript configuration and plugin snippets here target Tailwind CSS 3. Tailwind CSS 4 uses CSS-first configuration; explicitly load a compatible legacy config with `@config` rather than assuming automatic discovery. [Upgrade guide](https://tailwindcss.com/docs/upgrade-guide).

**Tailwind plug-in mechanism (addUtilities/addComponents)** belongs to
👉 **The watershed of "from being able to use Tailwind → to being able to build a component library/standard system"**

# 1\. What is the plug-in mechanism for? {#一、插件机制是干嘛的}

In one sentence:

> **Use JS to batch generate Tailwind classes instead of handwriting CSS**

You can:

* Define a set of **utilities**
* Define a set of **components**
* Read design variables in `theme()`
* Automatic support for `hover / dark / responsive`

# 2\. Basic structure of plug-in {#二、插件基本结构}

```js
// tailwind.config.js
import plugin from 'tailwindcss/plugin'

export default {
  theme: { extend: {} },
  plugins: [
    plugin(function ({ addUtilities, addComponents, theme }) {
      // 写插件逻辑
    })
  ]
}
```

# 3\. addUtilities (tool class) {#三、addutilities-工具类}

## When to use it? {#什么时候用}

👉 **Single function, freely combinable atomic capabilities**

Such as:

* `.safe-top`
* `.text-shadow`
* `.scrollbar-hide`

## 1️⃣ The simplest example {#_1️⃣-最简单例子}

```js
addUtilities({
  '.safe-top': {
    paddingTop: 'env(safe-area-inset-top)'
  }
})
```

```html
<div class="safe-top"></div>
```

## 2️⃣ Support responsive / hover / dark {#_2️⃣-支持响应式-hover-dark}

```js
addUtilities(
  {
    '.text-shadow': {
      textShadow: '0 2px 4px rgba(0,0,0,.2)'
    }
  },
  ['responsive', 'hover', 'dark']
)
```

```html
<div class="hover:text-shadow dark:text-shadow"></div>
```

## 3️⃣ Get value from theme (core) {#_3️⃣-从-theme-中取值-核心}

```js
addUtilities(
  {
    '.bg-primary-gradient': {
      background: `linear-gradient(
        90deg,
        ${theme('colors.primary.500')},
        ${theme('colors.primary.700')}
      )`
    }
  }
)
```

📌 **This step = plug-in + design system integration**

## 4️⃣ Batch generation of utilities (common techniques) {#_4️⃣-批量生成-utilities-常用技巧}

```js
const sizes = {
  sm: '4px',
  md: '8px',
  lg: '16px'
}

addUtilities(
  Object.entries(sizes).map(([key, value]) => ({
    [`.blur-${key}`]: { filter: `blur(${value})` }
  }))
)
```

Use:

```html
<div class="blur-md"></div>
```

# 4\. addComponents (component class) {#四、addcomponents-组件类}

## When to use it? {#什么时候用-1}

👉 **A complete set of fixed structure styles**

Such as:

* Button
* Card
* Alert
* Tag

## 1️⃣ Button component example (core) {#_1️⃣-button-组件例子-核心}

```js
addComponents({
  '.btn': {
    padding: '8px 16px',
    borderRadius: theme('borderRadius.md'),
    fontWeight: '500'
  },
  '.btn-primary': {
    backgroundColor: theme('colors.primary.500'),
    color: '#fff',
    '&:hover': {
      backgroundColor: theme('colors.primary.700')
    }
  }
})
```

```html
<button class="btn btn-primary"></button>
```

📌 **btn = structure**
📌 **btn-primary = skin**

## 2️⃣ Responsive components {#_2️⃣-响应式组件}

```js
addComponents({
  '.card': {
    padding: '16px',
    '@screen md': {
      padding: '24px'
    }
  }
})
```

## 3️⃣ Dark Mode component {#_3️⃣-dark-mode-组件}

```js
addComponents({
  '.card': {
    backgroundColor: '#fff',
    '.dark &': {
      backgroundColor: '#111'
    }
  }
})
```

# 5\. addUtilities vs addComponents (key comparison) {#五、addutilities-vs-addcomponents-重点对比}

| dimensions | addUtilities | addComponents |
| ----- | ------------ | ------------- |
| Positioning | Atomic capabilities | Component packaging |
| Combinatoriality | Strong | Weak |
| Is there semantics | Almost none | Strong |
| Suitable for scenarios | Functional classes | Component library |

📌 **Rule of Thumb**

> Detachable → utilities
> Don’t want to dismantle → components

# 6\. addBase (by the way) {#六、addbase-顺带讲}

### Used to change the default label style {#用来改默认标签样式}

```js
addBase({
  'h1': { fontSize: theme('fontSize.xl') },
  'h2': { fontSize: theme('fontSize.lg') }
})
```

📌 Commonly used in:

* reset
* markdown style

# 7\. Practical combat: Make an "enterprise-level button plug-in" {#七、实战-做一个「企业级按钮插件」}

```js
// plugins/button.js
import plugin from 'tailwindcss/plugin'

export default plugin(({ addComponents, theme }) => {
  addComponents({
    '.btn': {
      display: 'inline-flex',
      alignItems: 'center',
      justifyContent: 'center',
      borderRadius: theme('borderRadius.md'),
      padding: '8px 16px',
      fontWeight: '500'
    },
    '.btn-primary': {
      backgroundColor: theme('colors.primary.500'),
      color: '#fff',
      '&:hover': {
        backgroundColor: theme('colors.primary.700')
      }
    },
    '.btn-danger': {
      backgroundColor: theme('colors.danger.500'),
      color: '#fff'
    }
  })
})
```

```js
// tailwind.config.js
import button from './plugins/button'

plugins: [button]
```

# 8\. Best practices for combining with Vue components {#八、和-vue-组件结合的最佳实践}

### The Tailwind plug-in is responsible for "style rules" {#tailwind-插件负责「样式规则」}

### Vue components are responsible for "structure + logic" {#vue-组件负责「结构-逻辑」}

```vue
<button class="btn" :class="`btn-${type}`">
  <slot />
</button>
```

# 9\. Common pitfalls (you will definitely encounter them) {#九、常见坑-你一定会遇到}

### 1️⃣ Will classes generated by plug-ins also be purged? {#_1️⃣-插件生成的类也会被-purge}

✅ **No** (plug-ins are injected during build)

### 2️⃣ How to choose plug-in vs @apply? {#_2️⃣-插件-vs-apply-怎么选}

* Public system → plug-in
* local component → @apply
