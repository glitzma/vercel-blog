## 1\. What are `null` and `undefined` in TS? {#一、null-和-undefined-在-ts-中是什么}

In **TypeScript**:

```ts
null; // 一个值，表示“空”
undefined; // 一个值，表示“未定义”
```

them **Both a value and a type** ：

```ts
let a: null = null;
let b: undefined = undefined;
```

## 2\. Key premise: `strictNullChecks` {#二、关键前提-strictnullchecks}

**99% of projects** are now enabled:

```json
{
  "compilerOptions": {
    "strict": true
  }
}
```

Equivalent to:

```json
{
  "strictNullChecks": true
}
```

### The essential difference between on/off {#开-关的本质区别}

#### ❌ Not opened (old project) {#❌-未开启-老项目}

```ts
let s: string;

s = null; // ✅ 不报错
s = undefined; // ✅ 不报错
```

👉 **Extremely dangerous**, the type is in name only

#### ✅ On (Modern TS project, default) {#✅-开启-现代-ts-项目-默认}

```ts
let s: string;

s = null; // ❌
s = undefined; // ❌
```

**Conclusion**:

> `null` and `undefined` **are no longer subtypes of all types**

## 3\. Correct use of `null` / `undefined` {#三、正确使用-null-undefined-的方式}

### 1️⃣ Explicitly declare that it is nullable {#_1️⃣-显式声明可空}

```ts
let s: string | null;
let t: string | undefined;
let u: string | null | undefined;
```

```ts
s = null;
t = undefined;
```

👉 **Must use union type**

### 2️⃣ Optional vs undefined in object properties {#_2️⃣-对象属性中的可选-vs-undefined}

#### Optional attribute `?` {#可选属性}

```ts
interface User {
  name: string;
  age?: number;
}
```

Equivalent to:

```ts
age: number | undefined;
```

**But not equivalent to `null`**

```ts
const u1: User = { name: "Tom" }; // ✅
const u2: User = { name: "Tom", age: 18 }; // ✅
const u3: User = { name: "Tom", age: null }; // ❌
```

👉 **`?` = may not exist, not null**

### 3️⃣ `undefined` in function parameters {#_3️⃣-函数参数中的-undefined}

```ts
function foo(x?: number) {}
```

Equivalent to:

```ts
function foo(x: number | undefined) {}
```

```ts
foo();
foo(undefined);
foo(1);
```

## 4\. The actual usage convention of `null` vs `undefined` (very important) {#四、null-vs-undefined-的实际使用约定-非常重要}

### 🔹 Common conventions in the industry (strongly recommended) {#🔹-业界常见约定-强烈推荐}

| Scenario | Which one to use | Reason |
| ------------ | ----------- | ------------ |
| Variable not initialized | `undefined` | JS native semantics |
| Parameters optional | `undefined` | `?` Syntax |
| Object field missing | `undefined` | JSON convention |
| Actively "null" | `null` | Explicitly express "null" |
| The backend returns a null value | `null` | Common in databases |

### Example {#示例}

```ts
let currentUser: User | null = null; // 当前无用户
```

Than

```ts
let currentUser: User | undefined;
```

**Semantics are clearer**

## 5\. Common pitfalls (must be avoided on the front end) {#五、常见坑-前端必踩}

### ❌ Pitfall 1: Direct access to possibly null values {#❌-坑-1-直接访问可能为-null-的值}

```ts
function printLength(s: string | null) {
  console.log(s.length); // ❌
}
```

### ✅ Correct way: narrow type (type guard) {#✅-正确方式-缩小类型-类型守卫}

```ts
function printLength(s: string | null) {
  if (s !== null) {
    console.log(s.length); // ✅
  }
}
```

or:

```ts
if (s) {
} // ⚠️ 会排除 '' 0 false
```

### ❌ Pit 2: DOM API {#❌-坑-2-dom-api}

```ts
const el = document.getElementById("app");
el.innerHTML = "hi"; // ❌
```

### ✅ Correct writing method {#✅-正确写法}

```ts
const el = document.getElementById("app");

if (el) {
  el.innerHTML = "hi";
}
```

Or assert (which you're pretty sure exists):

```ts
const el = document.getElementById("app")!;
```

## 6\. `!` non-empty assertion (use with caution) {#六、-非空断言-慎用}

```ts
el!.innerHTML = "hi";
```

Meaning:

> "I guarantee it is not null / undefined"

⚠️ **Won’t check for you at runtime**

## 7\. Optional chaining & null value merging (TS + ES2020 artifact) {#七、可选链-空值合并-ts-es2020-神器}

### 1️⃣ Optional chain `?.` {#_1️⃣-可选链}

```ts
user?.profile?.name;
```

### 2️⃣ Null value merging `??` {#_2️⃣-空值合并}

```ts
const name = user.name ?? "匿名";
```

Comparison:

```ts
||   // 会把 '' 0 false 当成假
??   // 只关心 null / undefined
```

## 8\. Summarize one sentence (just remember it) {#八、总结一句话-记住就行}

> **TS does not allow you to "pretend null/undefined does not exist"**

You must:

- declare with union type
- Use judgment to narrow down
- Use `?.` / `??`
- Use `!` with caution
