# Modules vs namespaces {#模块vs命名空间}

- [namespace-and-module](https://blog.higan.me/namespace-and-module-in-typescript/)

## 1. module {#_1-模块}

### 1.1 Global module {#_1-1-全局模块}

- By default, when you start writing code in a new TypeScript file, it is in the global namespace
- Using the global variable space is dangerous because it conflicts with code naming within the file.We recommend using the file module mentioned below

`foo.ts`

```ts
const foo = 123;
```

`bar.ts`

```ts
const bar = foo; // allowed
```

### 1.2 File module {#_1-2-文件模块}

- File modules are also called external modules.If you have `import` or `export` at the root level of your TypeScript file, it will create a local scope within that file
- Module is the abbreviation of external module in TS, focusing on code and reuse
- Modules execute in their own scope, not in the global scope
- Variables, functions, classes, etc. in a module are not visible externally unless you export it
- If you want to use variables exported from a module, you need to import them

```ts
export const a = 1;
export const b = 2;
export default "hello ";
```

```ts
import name, { a, b } from "./1";
console.log(name, a, b);
```

### 1.3 Module specifications {#_1-3-模块规范}

- AMD: Don't use it, it only works in the browser;
- `SystemJS`: This was a good experiment and has been replaced by ES modules;
- ES Modules: It's not ready.
- It would be a good idea to use the `module`: `commonjs` option instead of these modes

## 2. namespace {#_2-命名空间}

- When the amount of code is large, in order to avoid namespace conflicts, similar functions, classes, and interfaces can be placed in the namespace.
- The namespace can wrap the code and expose only the objects that need to be accessed externally. The namespace can be exported through `export`
- Namespace is an internal module, mainly used to organize code and avoid naming conflicts.

### 2.1 Internal division {#_2-1-内部划分}

```ts
export namespace zoo {
  export class Dog {
    eat() {
      console.log("zoo dog");
    }
  }
}
export namespace home {
  export class Dog {
    eat() {
      console.log("home dog");
    }
  }
}
let dog_of_zoo = new zoo.Dog();
dog_of_zoo.eat();
let dog_of_home = new home.Dog();
dog_of_home.eat();
```

```ts
import { zoo } from "./3";
let dog_of_zoo = new zoo.Dog();
dog_of_zoo.eat();
```

### 2.2 Principle {#_2-2-原理}

- In fact, a namespace is essentially an object. Its function is to organize a series of related global variables into the attributes of an object.

```ts
namespace Numbers {
  export let a = 1;
  export let b = 2;
  export let c = 3;
}
```

```ts
var Numbers;
(function (Numbers) {
  Numbers.a = 1;
  Numbers.b = 2;
  Numbers.c = 3;
})(Numbers || (Numbers = {}));
```

## 3. Files, modules and namespaces {#_3-文件-模块与命名空间}

### 3.1 Files and modules {#_3-1-文件和模块}

- Each `module` is different `src\table1.ts`

```ts
export module Box {
  export class Book1 {}
}
```

`src\table2.ts`

```ts
export module Box {
  export class Book1 {}
}
```

`src\table3.ts`

```ts
export module Box {
  export class Book1 {}
}
```

### 3.2 Space {#_3-2-空间}

- `namespace` is different from `module`, `namespace` is unique in the global space

`src\table1.ts`

```ts
namespace Box {
  export class Book1 {}
}
```

`src\table2.ts`

```ts
namespace Box {
  export class Book1 {}
}
```

`src\table3.ts`

```ts
namespace Box {
  export class Book1 {}
}
```
