# RAG Learning Plan: A 4-Week Guide for Beginners {#rag-learning-plan}

This plan is for learners who have never written code and want to understand RAG first. It follows **4 weeks, 5 sessions per week, and about 30 minutes per session**, roughly 10 hours in total. A “day” means a learning session, so you can work at your own pace.

By the end, you should be able to explain the RAG workflow, manually simulate knowledge-base questions and answers, and identify where to look when an answer goes wrong. Building an automated RAG program can be a goal for the later coding stage.

This plan now includes **20 lessons**. Click a study day below to open its concepts, examples, exercises, and expandable answers. Keep the [practice pack](./rag-course/materials) for A–H sources, ten test questions, and record templates; begin with [Lesson 1](./rag-course/01.llm-capabilities).

## 1. Understand What RAG Does {#what-rag-does}

**RAG (Retrieval-Augmented Generation) retrieves relevant information and then gives that information and the question to a language model to generate an answer.** This usually does not require retraining the model. Think of it as an open-book exam: retrieval finds the relevant pages, and the model reads them and organizes an answer.[Microsoft's explanation of the fundamentals](https://learn.microsoft.com/en-us/azure/foundry/concepts/retrieval-augmented-generation?view=foundry-classic)

It helps to divide the workflow into two parts:

1. **Prepare the information**: collect documents → organize the content → split it into suitable chunks → build an index that supports searching.
2. **Answer a question**: receive the question → retrieve relevant chunks → put the question and chunks into a prompt → generate an answer with sources.

Vector search is a common approach, and keyword search can also support RAG. RAG helps ground answers in information, but it does not guarantee that every answer is correct.

## 2. A Routine for Each Session {#study-routine}

- **10 minutes to understand**: read about one concept and find an everyday analogy.
- **15 minutes to practice**: complete a task using your notes or the sample material below.
- **5 minutes to reflect**: write down “what I learned, an example, and what I still do not understand.”

Use the other two days each week for rest or review. If you cannot explain a weekly checkpoint yet, repeat the relevant exercises before moving on.

| Week | Focus | Outcome |
| --- | --- | --- |
| Week 1 | Language models, prompts, context, and the basic RAG workflow | A RAG workflow diagram you can explain |
| Week 2 | Document chunks, embeddings, retrieval, and sources | A small knowledge base with chunk identifiers and sources |
| Week 3 | Manually simulate retrieval and generation | A reusable question-answering prompt and records of 5 experiments |
| Week 4 | Evaluate answers, locate problems, and improve the workflow | A 10-question test set and a one-page review |

## 4. Week 2: Understand How Information Is Found {#week-2}

| Session | What to understand | Exercise |
| --- | --- | --- |
| [Day 6](./rag-course/06.prepare-documents) | Document quality affects retrieval; titles, dates, and sources help assess evidence | Select 3–5 short public documents or your own non-sensitive notes and record a title and date for each |
| [Day 7](./rag-course/07.chunking) | Chunking splits documents; tiny chunks may lose context, while large chunks may include irrelevant content | Split a short article by paragraph and by topic, then compare which works better for questions |

## 5. Week 3: Manually Simulate RAG {#week-3}

This week, you retrieve information manually and then ask an existing AI conversation tool to answer from the selected chunks. The exercise makes each step visible; later, a program can replace manual retrieval.

| Session | What to understand | Exercise |
| --- | --- | --- |
| [Day 11](./rag-course/11.ask-answerable-questions) | A clear question helps you select relevant information | Write 5 questions covering direct lookup, different wording, combined information, and missing information |
| [Day 12](./rag-course/12.check-retrieved-evidence) | Retrieval quality and answer quality should be examined separately | Before generating answers, manually select chunks for each question and record why you chose them |
| [Day 13](./rag-course/13.evidence-based-prompts) | A prompt organizes the question, evidence, and response requirements | Use the template below to produce one answer with sources |
| [Day 14](./rag-course/14.missing-and-conflicting-evidence) | Missing evidence calls for acknowledging uncertainty; conflicting documents need an explanation | Provide irrelevant chunks and then conflicting documents, checking whether the model invents facts or chooses without justification |
| [Day 15](./rag-course/15.auditable-rag-experiment) | Keeping experiment records makes comparisons possible | Complete 5 questions and record the question, selected chunks, model answer, and your assessment |

### Sample Documents for Practice {#sample-documents}

The following material is entirely fictional and intended for learning. Each row can be treated as a chunk with a source identifier.

| Identifier | Source | Content |
| --- | --- | --- |
| A | Library opening-hours notice, October 2026 edition | Monday–Friday: 9:00–21:00; Saturday–Sunday: 9:00–17:00 |
| B | Library borrowing rules, October 2026 edition | Each reader may borrow up to 3 books at a time; the loan period is 14 days per book |
| C | Renewal notice, October 2026 edition | Books not reserved by another reader may be renewed once before the due date for another 7 days |
| D | Temporary closure notice, October 12, 2026 | The library will be closed throughout October 18, 2026, for equipment maintenance |
| E | Library borrowing rules, archived 2025 edition | Each reader may borrow up to 2 books at a time; this edition has been replaced by the 2026 rules |

Try asking: “Can I visit at 18:00 on Sunday?” “How many books can I borrow at once?” “Is the library open on October 18, 2026?” “What is the daily overdue fine?”

### A Prompt You Can Use {#prompt-template}

Copy the instructions below, then add your question and selected information:

> Answer the question using the information below, and identify the supporting chunks after each key conclusion.
>
> If the information is insufficient, explain what is missing rather than guessing.
>
> If the documents conflict, explain the conflict. Choose an applicable version only when the documents explicitly state their effective dates or replacement relationship.
>
> Question: enter your question.
>
> Information: paste the selected chunks, keeping their identifiers, sources, and dates.

**Checkpoint**: observe an evidence-supported answer, a response to missing information, and an explanation of conflicting sources. Check that citations actually support the conclusions. The sample has no overdue-fine information, so it cannot establish an amount.

## 6. Week 4: Evaluate and Improve {#week-4}

| Session | What to understand | Exercise |
| --- | --- | --- |
| [Day 16](./rag-course/16.build-a-test-set) | Test questions should include easy, difficult, and unanswerable cases | Prepare 10 questions: 4 direct lookups, 2 paraphrases, 2 combined or conflicting cases, and 2 cases with missing information |
| [Day 17](./rag-course/17.evaluate-retrieval) | Retrieval evaluation asks whether enough evidence was found | Identify the evidence needed for each question and check whether retrieval covers it |
| [Day 18](./rag-course/18.evaluate-answers) | Answer evaluation considers correctness, support, citations, and handling of missing information | Assess each answer using the record below |
| [Day 19](./rag-course/19.hybrid-search-and-reranking) | Hybrid retrieval combines keywords and semantics; reranking sorts candidates again | Manually collect candidates with both approaches, merge them, and rank them again; change one factor at a time before comparing |
| [Day 20](./rag-course/20.improve-from-failures) | Failed cases should guide improvements | Repeat the same 10 questions, compare results, and record the 3 most common problems and possible improvements |

### A Simple Evaluation Record {#evaluation-table}

Copy the table and add a row for each test question. Use “not applicable” when a question has no evidence that can support an answer.

| Question | Required evidence | Enough evidence found? | Answer correct? | Citations support the conclusion? | Missing or conflicting information handled appropriately? | Improvement |
| --- | --- | --- | --- | --- | --- | --- |
| Example: how many books can I borrow at once? | B; if E is also retrieved, identify the replacement relationship | Yes / no | Yes / no | Yes / no / not applicable | Yes / no / not applicable | Record observations |

First locate the problem in a specific stage:

- **The documents contain no answer**: add information or explicitly state that information is insufficient.
- **The documents contain an answer, but it was not found**: inspect chunking, question wording, and retrieval methods.
- **The answer was found, but the model responded incorrectly**: inspect context completeness, conflicting material, and prompt clarity.
- **The answer seems correct, but its citations do not support it**: verify each conclusion against the original text rather than merely checking for citation markers.

**Checkpoint**: complete records for 10 questions and use at least one failed case to explain “what went wrong, what changed, and whether the result improved.” This small test set is for learning and does not represent every real-world use case.

## 7. A Glossary to Consult {#glossary}

| Term | Initial understanding |
| --- | --- |
| LLM | A large language model that interprets input and generates text |
| Prompt | Instructions and input content given to a model |
| Context | Information available to the model for its current response |
| Chunk | A passage split out of a document |
| Embedding | A numerical text representation used to compare semantics and other features |
| Index | A data structure built to find information efficiently |
| Top-k | The first k ranked candidate results; they are not necessarily relevant enough |
| Reranking | Sorting the candidates from initial retrieval again |

## 8. Resources and Next Steps {#resources-and-next-steps}

During Weeks 1–2, focus on [Microsoft's RAG fundamentals course](https://learn.microsoft.com/zh-cn/training/modules/rag-fundamentals/), reading about the fundamentals, data preparation, retrieval, and evaluation in that order. Consult the glossary for unfamiliar English terms.

During Weeks 3–4, optionally read [LlamaIndex's introduction to RAG](https://developers.llamaindex.ai/python/framework/understanding/rag/) to understand loading, indexing, storing, querying, and evaluation. Save installation and code for the programming stage. The reading order and exercises are recommendations from this plan.

After four weeks, if you want to build an automated project, continue with:

1. Python variables, lists, dictionaries, loops, and functions.
2. Reading text files and understanding API requests and JSON.
3. A minimal workflow using simple search: find chunks → pass them to a model → answer.
4. Vector retrieval, evaluated using the same 10-question test set.
5. Frameworks, reranking, and more complex retrieval strategies as actual problems require them.
