How does it achieve "extremely fast HMR".

## 🚀 1. Why is Vite’s HMR so fast? {#🚀-1-为什么-vite-的-hmr-能这么快}

The core idea of Vite:

### **🧠 There is no need to rebuild the bundle, but the actual changed files are updated in a targeted manner** {#🧠-不需要重新构建-bundle-而是定向更新实际变动文件}

Webpack：

* File changed → Webpack rebuilds part of the bundle → Send patch → Replace module

Vite：

* The file has been changed → **The browser re-requests the ESM version of this file**
* If there are dependencies → only update the dependency chain, not package

> So the fundamental reason why Vite HMR is fast: **Natural ESM, no bundle, no diff, no patch.**

## 📦 2. HMR core module structure {#📦-2-hmr-核心模块结构}

#### Table of contents (approximately) {#目录-大致}

```
vite/
 ├─ server/
 │   ├─ index.ts              → 创建 dev server（核心）
 │   ├─ ws.ts                 → WebSocket 通信
 │   ├─ hmr.ts                → HMR 的依赖跟踪 & 更新逻辑
 │   ├─ moduleGraph.ts        → 模块依赖图（最关键）
 │   ├─ plugins/
 │       ├─...
 │   ├─ transformRequest.ts   → 单文件的编译/转换
 │   └─...
```

Core components:

1. **ModuleGraph module graph** (tracking module dependencies)
2. **Watcher file listener** (chokidar)
3. **WS WebSocket System** (push update events to the browser)
4. **Hot update handler: server.handleHMRUpdate()**
5. **Client HMR Runtime** (/vite/client)

## 🕸 3. ModuleGraph - the brain of HMR {#🕸-3-modulegraph-——-hmr-的大脑}

Vite maintains a graph structure for each module:

```ts
class ModuleNode {
  url: string
  importedModules: Set<ModuleNode>
  importers: Set<ModuleNode>
}
```

Example:

```
A.js  → import B.js
B.js  → import C.js
```

ModuleGraph will log:

* B's importers = {A}
* C's importers = { B }

➡️ When C changes → B needs to be notified
➡️ If B does not have an HMR receiver → Notify A again (bubbling up)

## 📡 4. After file changes (HMR entire link) {#📡-4-文件变化后-hmr-整条链路}

Now comes the most critical part: **How does HMR really move?**

## ✨ Step 1: Monitor file changes (chokidar) {#✨-第-1-步-监听文件变化-chokidar}

In `server/index.ts`:

```ts
watcher.on('change', (file) => {
  server.handleHMRUpdate(file)
})
```

When you edit a file, such as `src/App.vue`:

```
File changed: src/App.vue
```

## ✨ Step 2: handleHMRUpdate() handles updates {#✨-第-2-步-handlehmrupdate-处理更新}

Key function: `server.handleHMRUpdate(file)`

It will:

1. Find the corresponding ModuleNode
2. Execute the module's plugin `hmr` hook (e.g. Vue plugin)
3. Collect modules in the dependency chain that accept updates
4. Send update events via WebSocket

## ✨ Step 3: Determine which modules "accept updates" {#✨-第-3-步-确定哪些模块-接受更新}

HMR has two processing methods:

#### ✔ There is `import.meta.hot.accept()` {#✔-有-import-meta-hot-accept}

→ Partial hot update (only refresh relevant modules)

#### ❌ No HMR processor {#❌-没-hmr-处理器}

→ Reverse search for “importers” based on dependencies
→ Find the nearest HMR boundary
→ If not found → Fully refresh the page

For example:

```
A.vue → import B.js → import C.js
```

If `C.js` is changed:

1. Does C.js accept?
   ❌ No

2. Does its importer B.js accept it?
   ❌ No

3. Look up again A.vue
   ✔ HMR accept with Vue

➡️Finally update A.vue (trigger Vue partial update)

## ✨ Step 4: WebSocket Push Update Message {#✨-第-4-步-websocket-推送更新消息}

Code from `ws.ts`:

```ts
ws.send({
  type: 'update',
  updates: [{ path, timestamp }]
})
```

Vite uses `ws://localhost:5173` to create a WebSocket, which only sends JSON:

```json
{
  "type": "update",
  "updates": [
    {
      "path": "/src/components/MyComp.vue",
      "timestamp": 1679999999999
    }
  ]
}
```

## ✨ Step 5: Browser side (client HMR runtime) {#✨-第-5-步-浏览器端-客户端-hmr-runtime}

The HMR client runs at:

```
vite/client
```

Main logic:

1. Receive WebSocket push
2. Dynamically call `import(path + "?t=timestamp")` based on `path`
3. Replace module
4. Execute `import.meta.hot.accept()` callback

Example (simplified):

```js
socket.onmessage = async (msg) => {
  if (msg.type === 'update') {
    for (const update of msg.updates) {
      import(update.path + '?t=' + update.timestamp)
    }
  }
}
```

Very straightforward: **Just re-import the file!**

No patches, no diffs, no bundles - so fast.

## ✨ Step 6: If no module accepts the update → Full page refresh {#✨-第-6-步-如果没有模块接受更新-→-整页刷新}

```js
location.reload()
```

This is why sometimes HMR fails and automatically refreshes the page.

## 🧩 5. Why is Vite so fast?(Summary) {#🧩-5-为什么-vite-这么快-总结}

#### Because: {#因为}

* Use browser native ESM (No Bundle)
* Whichever file is changed will be updated.
* HMR is an accurate update based on dependency graph
* The client only needs to re-import the new module
* No patch, no rebuild, no pre-bundle required

This is the fundamental reason why Vite can be hot updated in seconds.
