Here is one for you **Production-grade, ready-to-use virtual module (virtual:env) plug-in that automatically injects environment variables** , completely simulates something like:

```js
import env from 'virtual:env'

console.log(env.API_URL)
```

It will automatically read:

* `.env`
* `.env.local`
* `.env.development`
* Or any custom env file you define

And generate a virtual module `virtual:env` for any code to import directly.

This type of plug-in is very useful in real projects.

## 🚀 Final effect {#🚀-最终效果}

You can write in any file:

```js
import env from 'virtual:env'

console.log(env)
```

Output example:

```json
{
  "NODE_ENV": "development",
  "VITE_API_URL": "https://api.xxx.com",
  "VITE_TITLE": "My App"
}
```

This module is automatically generated and requires no manual maintenance.

## 🔥 1. Complete plug-in code (plug-in file: `plugins/virtualEnv.js`) {#🔥-一、插件完整代码-插件文件-plugins-virtualenv-js}

This code can be copied and used directly. It is complete, runnable, and includes caching, HMR, and automatic env file parsing.

```js
import fs from 'node:fs'
import path from 'node:path'
import dotenv from 'dotenv'

export default function virtualEnvPlugin(options = {}) {
  const VIRTUAL_MODULE_ID = 'virtual:env'
  const RESOLVED_ID = '\0' + VIRTUAL_MODULE_ID

  const { envDir = process.cwd() } = options

  let envData = {}

  // 读取所有环境文件
  function loadEnvFiles(mode) {
    const files = [
      `.env`,
      `.env.local`,
      `.env.${mode}`,
      `.env.${mode}.local`
    ]

    envData = {}

    for (const file of files) {
      const filePath = path.resolve(envDir, file)
      if (fs.existsSync(filePath)) {
        const parsed = dotenv.parse(fs.readFileSync(filePath, 'utf-8'))
        Object.assign(envData, parsed)
      }
    }

    // 只暴露 VITE_ 开头的变量
    const clientEnv = {}
    for (const k in envData) {
      if (k.startsWith('VITE_') || k === 'NODE_ENV') {
        clientEnv[k] = envData[k]
      }
    }

    return clientEnv
  }

  return {
    name: 'vite-plugin-virtual-env',

    configResolved(config) {
      // Vite 的 mode（development / production）
      this.mode = config.mode
      this.clientEnv = loadEnvFiles(this.mode)
    },

    resolveId(id) {
      if (id === VIRTUAL_MODULE_ID) {
        return RESOLVED_ID
      }
    },

    load(id) {
      if (id === RESOLVED_ID) {
        return `
          // generated by vite-plugin-virtual-env
          export default ${JSON.stringify(this.clientEnv, null, 2)}
        `
      }
    },

    // Env 文件变动 → 自动 HMR
    handleHotUpdate(ctx) {
      const envFiles = [
        '.env',
        `.env.${this.mode}`,
        '.env.local',
        `.env.${this.mode}.local`
      ]

      const changed = envFiles.some((f) => ctx.file.endsWith(f))

      if (changed) {
        this.clientEnv = loadEnvFiles(this.mode)

        ctx.server.ws.send({
          type: 'update',
          updates: [
            {
              type: 'js-update',
              path: '/@id/' + RESOLVED_ID,
              acceptedPath: '/@id/' + RESOLVED_ID,
              timestamp: Date.now()
            }
          ]
        })

        return []
      }
    }
  }
}
```

## 📌 2. Use in `vite.config.js` {#📌-二、在-vite-config-js-中使用}

```js
import virtualEnvPlugin from './plugins/virtualEnv.js'

export default defineConfig({
  plugins: [
    virtualEnvPlugin()
  ]
})
```

## 📁 3. Usage examples {#📁-三、使用示例}

Assuming your `.env.development`:

```
VITE_API_URL=https://api.dev.com
VITE_APP_NAME=Dev App
SECRET_KEY=xxx
```

In your code you use:

```js
import env from 'virtual:env'

console.log(env)
```

Actual result (only `VITE_` and `NODE_ENV` are exposed):

```json
{
  "NODE_ENV": "development",
  "VITE_API_URL": "https://api.dev.com",
  "VITE_APP_NAME": "Dev App"
}
```

## 🔄 4. Support HMR {#🔄-四、支持-hmr}

When you modify `.env` or `.env.local`, the page will **automatically refresh the virtual module** (the entire page will not be refreshed).

For example, change `.env.local`:

```diff
-VITE_APP_NAME="Dev App"
+VITE_APP_NAME="Dev App Updated"
```

The browser will receive:

```
update: virtual:env
```

No need to restart the dev server.

## ⚙️ 5. Why does Vite limit exposure to only the `VITE_` prefix? {#⚙️-五、为什么-vite-要限制只暴露-vite-前缀}

Vite’s official policy is also:

```
只有 VITE_ 前缀的变量才会暴露给浏览器
```

This is a **security policy** to avoid leaking sensitive variables to the client.

You can decide whether to strictly limit it, which can be customized in the plug-in:

```js
if (k.startsWith('CLIENT_'))
```

## 🧠 6. Summary of plug-in principles (important) {#🧠-六、插件原理总结-重要}

Virtual module process:

1. `resolveId('virtual:env')` → return `\0virtual:env`
2. `load('\0virtual:env')` → return env JS content
3. The browser can directly get the generated module when importing
4. `.env` file update → handleHotUpdate → ws notification → HMR reload virtual module

This is the most beautiful part of Vite’s architecture:
**Virtual module + HMR + automatic dependency graph refresh**
