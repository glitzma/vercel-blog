## 1\. Commonly used Composition API Hooks in Vue3 {#一、vue3-常用-composition-api-hooks}

The core of Vue3 is **Composition API**, and logic reuse revolves around `setup()`.

### 1️⃣ Responsive related {#_1️⃣-响应式相关}

#### ① `ref`

Create basic types of responsive data.

```js
const count = ref(0)
```

Features:

* Access using `.value`
* Automatic unpacking in templates

Applicable scenarios:

* basic type
* Need to replace the entire value

#### ② `reactive`

Create objects reactive.

```js
const state = reactive({ name: 'vue' })
```

Features:

* Cannot be deconstructed directly (responsiveness will be lost)
* Suitable for complex objects

#### ③ `computed`

Computed properties.

```js
const total = computed(() => count.value * 2)
```

Features:

* cache
* dependency tracking
* Support getter/setter

#### ④ `watch`

Monitor data changes.

```js
watch(count, (newVal, oldVal) => {})
```

Advanced usage:

```js
watch(
  () => state.name,
  (val) => {},
  { immediate: true, deep: true }
)
```

Common parameters:

* immediate
* deep
* flush: 'post' | 'pre' | 'sync'

#### ⑤ `watchEffect`

Automatically collect dependencies.

```js
watchEffect(() => {
  console.log(count.value)
})
```

Difference:

| watch        | watchEffect |
| ------------ | ----------- |
| Manually specify dependencies | Automatically collect dependencies |
| can get oldValue | not |

Suitable for side effect scenarios.

### 2️⃣ Life cycle Hooks {#_2️⃣-生命周期-hooks}

Vue3 lifecycle must be used in `setup()`.

#### Mounting phase {#挂载阶段}

| Vue3 | Description |
| --------------- | --- |
| `onBeforeMount` | Before mounting |
| `onMounted` | After mounting |

```js
onMounted(() => {
  console.log('DOM ready')
})
```

#### update stage {#更新阶段}

| Vue3 | Description |
| ---------------- | --- |
| `onBeforeUpdate` | Before update |
| `onUpdated` | After updated |

#### Unloading phase {#卸载阶段}

| Vue3 | Description |
| ----------------- | --- |
| `onBeforeUnmount` | Before unmounting |
| `onUnmounted` | After unmounting |

Commonly used for:

* clear timer
* Cancel monitoring
* Release resources

#### Error catching {#错误捕获}

```js
onErrorCaptured((err, instance, info) => {})
```

Similar to React’s ErrorBoundary.

#### KeepAlive related {#keepalive-相关}

| Hook | Description |
| --------------- | -- |
| `onActivated` | Activated |
| `onDeactivated` | Deactivated |

Applies to:

* Page cache recovery
* Refresh data

### 3️⃣ Component Communication Hooks {#_3️⃣-组件通信-hooks}

#### `defineProps`

```js
const props = defineProps({
  msg: String
})
```

#### `defineEmits`

```js
const emit = defineEmits(['change'])
```

#### `defineExpose`

Exposed to the parent component.

#### `provide / inject`

Cross-level communication.

```js
provide('key', value)
inject('key')
```

Suitable for:

* form component
* theme system
* Plug-in mechanism

### 4️⃣ Other high-frequency Hooks {#_4️⃣-其他高频-hooks}

#### ① `nextTick`

Executed after DOM update.

```js
await nextTick()
```

#### ② `useAttrs`

Get the transparent transmission properties.

#### ③ `useSlots`

Get the slot.

#### ④ `getCurrentInstance`

Get the component instance (for advanced scenarios).

## 2\. Overall process of Vue3 life cycle {#二、vue3-生命周期整体流程}

Vue3 life cycle process:

```
setup
↓
onBeforeMount
↓
onMounted
↓
onBeforeUpdate
↓
onUpdated
↓
onBeforeUnmount
↓
onUnmounted
```

## 3\. Vue2 vs Vue3 life cycle comparison (high-frequency interviews) {#三、vue2-vs-vue3-生命周期对比-面试高频}

| Vue2          | Vue3            |
| ------------- | --------------- |
| beforeCreate  | setup           |
| created       | setup           |
| beforeMount   | onBeforeMount   |
| mounted       | onMounted       |
| beforeUpdate  | onBeforeUpdate  |
| updated       | onUpdated       |
| beforeDestroy | onBeforeUnmount |
| destroyed     | onUnmounted     |

Key points:

- 👉 Vue3 not created
- 👉 setup instead of beforeCreate + created

## 4\. Bonus points for advanced answers {#四、高级回答加分点}

#### 1️⃣ The essence of life cycle execution timing {#_1️⃣-生命周期执行时机本质}

The essence is based on:

* effect
* scheduler
* job queue

Vue3 update mechanism:

* Component updates are asynchronous batch processing
* Based on microtask queue

#### 2️⃣ watch flush timing {#_2️⃣-watch-flush-时机}

```js
flush: 'pre'   // 默认，DOM更新前
flush: 'post'  // DOM更新后
flush: 'sync'  // 同步执行
```

Advanced scenario:

* Manipulate DOM → use post
* Do synchronization logic → sync

#### 3️⃣ setup execution timing {#_3️⃣-setup-执行时机}

* Executed when the component instance is created
* Earlier than onBeforeMount
* None this

## 5\. Summary of practical experience {#五、实战经验型总结}

- The core is ref/reactive/computed/watch.
- Use watchEffect to control side effects.
- Asynchronous requests are usually onMounted.
- Use onActivated for a large number of component caching scenarios.
- Complex form encapsulation uses provide/inject extensively.
- When optimizing performance, attention will be paid to the timing of use of watch flush and nextTick.
