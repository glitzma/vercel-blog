## 1\. Basic Cognition {#一、基础认知类}

### 1️⃣What is the execution time of setup?What is the difference between created? {#_1️⃣-setup-执行时机是什么-和-created-有什么区别}

🎯 Investigation: Life cycle understanding

💎 Advanced answer:

* setup is executed when the component instance is created
* Earlier than onBeforeMount
* Equivalent to Vue2’s beforeCreate + created
* no this
* Complete responsive creation before template rendering

Bonus points:

> The essence of setup is the initialization phase before effect dependency collection.

### 2️⃣ What is the difference between ref and reactive?How to choose? {#_2️⃣-ref-和-reactive-区别-怎么选}

🎯 Examination: Responsive Understanding

💎 Answer structure:

| compare | ref | reactive |
| ------ | ------ | -------- |
| Data type | Any | Object only |
| Access method | .value | Direct access |
| Replace the entire object | Supported | Not recommended |

High-level summary:

> Use ref for basic types
> Use reactive for structurally stable objects
> The object that needs to be replaced as a whole takes priority ref

### 3️⃣ Why can’t reactive be deconstructed directly? {#_3️⃣-reactive-为什么不能直接解构}

🎯 Investigation: Responsive Loss Principle

💎 Reason:

* After destructuring, it becomes an ordinary variable
* Disengage from Proxy
* Lost dependency tracking

Solution:

```js
toRefs()
```

### 4️⃣What is the difference between computed and watch? {#_4️⃣-computed-和-watch-区别}

🎯 Examination: Side Effects vs Derived State

💎 Advanced comparison:

| computed | watch |
| -------- | ----- |
| Return value | None returned |
| Cache | Yes |
| Suitable for derived data | Suitable for side effects |

In one sentence:

> computed is a declarative derivation
> watch is an imperative side effect

### 5️⃣ What is the difference between watch and watchEffect? {#_5️⃣-watch-和-watcheffect-区别}

🎯 Examine dependency collection mechanism

| watch       | watchEffect |
| ----------- | ----------- |
| Manually declare dependencies | Automatically collect dependencies |
| can get oldValue | cannot |
| Precise control | Easier |

Advanced supplements:

> watchEffect is essentially an effect that is executed immediately.

## 2\. Advanced understanding category {#二、进阶理解类}

### 6️⃣What is the use of flush in watch? {#_6️⃣-watch-的-flush-有什么用}

🎯 Examine the scheduling mechanism

```js
flush: 'pre'   // 默认
flush: 'post'  // DOM更新后
flush: 'sync'  // 同步
```

High level answer:

> DOM operation logic must use post, otherwise the updated DOM will not be obtained.

### 7️⃣ Why is Vue3 update asynchronous batch processing? {#_7️⃣-为什么说-vue3-更新是异步批处理}

🎯 Examine the scheduling mechanism

Answer structure:

* Component updates are based on effects
* The update task enters the job queue
* Unified execution in microtasks
* Avoid re-rendering

### 8️⃣ What is the principle of nextTick? {#_8️⃣-nexttick-原理是什么}

🎯 Examine micro-task understanding

Advanced answer:

> The essence of nextTick is to wait for the current update queue flush to complete.

### 9️⃣ What is the internal essence of the life cycle? {#_9️⃣-生命周期内部本质是什么}

🎯 Examine underlying cognition

Answer:

> The essence is effect callbacks registered at different stages.

### 🔟 Who is earlier, onMounted or watchEffect? {#🔟-onmounted-和-watcheffect-谁更早}

Answer:

* setup
* watchEffect (execute immediately)
* onMounted (after DOM is mounted)

## 3\. Scenario questions (high frequency) {#三、场景题-高频}

### 1️⃣1️⃣ When must watch be used instead of computed? {#_1️⃣1️⃣-什么时候必须用-watch-而不是-computed}

💎 Answer:

* send request
* write localStorage
* Manipulating the DOM
* Log reporting

In one sentence:

> If you have side effects, you must use a watch.

### 1️⃣2️⃣ How to avoid watch infinite loop? {#_1️⃣2️⃣-如何避免-watch-死循环}

Common reasons:

* Modify the monitored value in watch

Solution:

* Use conditional judgment
* Use flush post
* separated state

### 1️⃣3️⃣ How to monitor reactive deep changes? {#_1️⃣3️⃣-如何监听-reactive-深层变化}

```js
{ deep: true }
```

But advanced additions:

> The deep monitoring performance is poor, and the state is split first.

### 1️⃣4️⃣ How to handle data refresh in KeepAlive scenario? {#_1️⃣4️⃣-keepalive-场景怎么处理数据刷新}

Use:

```js
onActivated()
```

Common scenarios:

* List page cache
* tab page

### 1️⃣5️⃣ Will the watch be automatically destroyed after the component is uninstalled? {#_1️⃣5️⃣-组件卸载后-watch-会自动销毁吗}

Answer:

✅ Will automatically clean up

Because:

> watch is bound to the current component effect scope.

## 4\. Architecture-level issues (widening the gap) {#四、架构级问题-拉开差距}

### 1️⃣6️⃣ What is effectScope? {#_1️⃣6️⃣-什么是-effectscope}

Advanced answer:

> effectScope is the mechanism used by Vue3 to manage the collection of side effects.
> The component itself is an effectScope.

Purpose:

* Create scope manually
* Destroy effects in batches

### 1️⃣7️⃣ Why do combined functions not leak memory? {#_1️⃣7️⃣-为什么组合式函数不会内存泄漏}

Answer:

* Because the inner watch belongs to the current component scope
* Component uninstallation and automatic cleaning

### 1️⃣8️⃣ Why does Vue3 perform better than Vue2? {#_1️⃣8️⃣-为什么-vue3-性能比-vue2-好}

Answer structure:

* Proxy instead of defineProperty
* Accurate dependency collection
* static boost
* patch flag
* Compilation optimization

### 1️⃣9️⃣ How to avoid repeated dependency collection in Vue3? {#_1️⃣9️⃣-vue3-如何避免重复依赖收集}

Answer:

* Use activeEffect
* Use dependency map structure
* Deduplication collection

### 2️⃣0️⃣ How to design large-scale useXXX hooks? {#_2️⃣0️⃣-如何设计大型-usexxx-hooks}

Advanced answer structure:

* State layer (ref/reactive)
* Side Effect Layer (watch)
* Life cycle layer (onMounted)
* Externally exposed layer (return)

Example:

```js
function useTable() {
  const data = ref([])
  const loading = ref(false)

  const fetchData = async () => {}

  onMounted(fetchData)

  return { data, loading }
}
```

## 5\. What is your understanding of Vue3 hooks? {#五、你对-vue3-hooks-的理解}

> Vue3 hooks are essentially a responsive side effect system built on effect + scheduler.
>
> ref/reactive is responsible for state,
> computed is responsible for derivation,
> watch is responsible for side effects,
> The essence of the life cycle is the effects registered at different stages.
>
> All updates go through an asynchronous dispatch queue to avoid repeated rendering.
>
> In large projects, we use useXXX combined functions for logic reuse, and use effectScope to manage the side effect life cycle.
