## 1\. Responsive Hooks - core business layer {#一、响应式-hooks-——-业务核心层}

### 1️⃣ ref - basic status & replaceable value {#_1️⃣-ref-——-基础状态-可替换值}

#### ✅ Actual combat scenarios {#✅-实战场景}

#### Scenario 1: Form control value {#场景1-表单控件值}

```js
const keyword = ref('')
```

Reason:

* basic type
* Need to be replaced entirely
* Two-way binding

#### Scenario 2: DOM reference {#场景2-dom-引用}

```js
const inputRef = ref(null)

onMounted(() => {
  inputRef.value.focus()
})
```

👉 ref is necessary in DOM scenes

#### Scenario 3: loading / visible control {#场景3-loading-visible-控制}

```js
const loading = ref(false)
const dialogVisible = ref(false)
```

For all Boolean control classes, ref is preferred.

### 2️⃣ reactive - complex object state management {#_2️⃣-reactive-——-复杂对象状态管理}

#### ✅ Actual combat scenarios {#✅-实战场景-1}

#### Scenario 1: Complex form {#场景1-复杂表单}

```js
const form = reactive({
  name: '',
  age: '',
  address: {
    city: ''
  }
})
```

Reason:

* The object structure is stable
* Need deep responsiveness

#### Scenario 2: Large page state container {#场景2-大页面状态容器}

For example:

* Complex filter conditions
* Table pagination
* Statistics panel

```js
const state = reactive({
  filter: {},
  pagination: {},
  list: []
})
```

👉 Suitable for "state container style" writing.

### 3️⃣ computed —— derived state {#_3️⃣-computed-——-派生状态}

#### ✅ Actual combat scenarios {#✅-实战场景-2}

#### Scenario 1: Filter data {#场景1-筛选数据}

```js
const filteredList = computed(() =>
  list.value.filter(item => item.name.includes(keyword.value))
)
```

Advantages:

* Automatic caching
* Avoid double counting

#### Scenario 2: Permission control {#场景2-权限控制}

```js
const canEdit = computed(() =>
  userRole.value === 'admin'
)
```

👉 It is strongly recommended to use computed instead of watch for the permission class.

## 2\. watch / watchEffect - side effect control layer {#二、watch-watcheffect-——-副作用控制层}

### 4️⃣ watch——precise monitoring {#_4️⃣-watch-——-精准监听}

#### ✅ Scenario 1: Interface linkage {#✅-场景1-接口联动}

```js
watch(page, () => {
  fetchList()
})
```

Pagination changes → auto-request.

#### ✅ Scenario 2: Routing changes {#✅-场景2-路由变化}

```js
watch(
  () => route.params.id,
  (id) => {
    fetchDetail(id)
  }
)
```

Commonly used in detail pages.

#### ✅ Scenario 3: Deep monitoring of complex objects {#✅-场景3-深度监听复杂对象}

```js
watch(
  () => form,
  () => saveDraft(),
  { deep: true }
)
```

Applies to:

* Automatically save drafts
* Real-time synchronization

### 5️⃣ watchEffect - automatic dependency collection {#_5️⃣-watcheffect-——-自动依赖收集}

#### ✅ Scenario 1: Automatic request on the first screen {#✅-场景1-首屏自动请求}

```js
watchEffect(() => {
  fetchDetail(route.params.id)
})
```

No need to declare dependencies manually.

#### ✅ Scenario 2: Log/Burying System {#✅-场景2-日志-埋点系统}

```js
watchEffect(() => {
  trackPage(route.path)
})
```

Automatically triggered by dependency changes.

## 3\. Practical combat of life cycle Hooks {#三、生命周期-hooks-实战}

### 6️⃣ onMounted —— High frequency use {#_6️⃣-onmounted-——-高频使用}

#### ✅ Scenario {#✅-场景}

* Initialization interface
* Initialize chart
* Register to listen

```js
onMounted(() => {
  fetchList()
  window.addEventListener('resize', handleResize)
})
```

### 7️⃣ onUnmounted —— Resource release {#_7️⃣-onunmounted-——-资源释放}

#### ✅ Scenario {#✅-场景-1}

```js
onUnmounted(() => {
  window.removeEventListener('resize', handleResize)
  clearInterval(timer)
})
```

👉 High frequency memory leak point.

### 8️⃣ onActivated / onDeactivated —— KeepAlive

#### ✅ Scenario: List page caching {#✅-场景-列表页缓存}

```js
onActivated(() => {
  refreshIfNeeded()
})
```

In:

* tab page
* Multi-level caching system
* Mobile multi-page switching

Very common.

## 4\. Component Communication Hooks Practical Combat {#四、组件通信-hooks-实战}

### 9️⃣ provide / inject - complex component system {#_9️⃣-provide-inject-——-复杂组件体系}

#### ✅ Scenario 1: Form component encapsulation {#✅-场景1-表单组件封装}

Parent component:

```js
provide('formContext', form)
```

Subcomponents:

```js
const form = inject('formContext')
```

Commonly found in:

* Form verification system
* Form item registration mechanism
* Complex UI component library encapsulation

#### ✅ Scenario 2: Theme system {#✅-场景2-主题系统}

```js
provide('theme', themeConfig)
```

### 🔟 defineExpose - component external API {#🔟-defineexpose-——-组件对外api}

Applies to:

* Pop-up component
* form component
* chart component

```js
defineExpose({
  open,
  close
})
```

Parent components can be called via ref.

## 5\. Advanced Scenarios (Extra Points) {#五、高级场景-加分点}

### 1️⃣ Timing of using watch flush {#_1️⃣-watch-flush-使用时机}

```js
watch(data, callback, { flush: 'post' })
```

#### Usage scenarios: {#使用场景}

* Depends on DOM updates
* Chart refresh
* Need to get updated dimensions

### 2️⃣ nextTick usage scenarios {#_2️⃣-nexttick-使用场景}

```js
await nextTick()
```

#### Used for: {#用于}

* Need to get the real DOM size
* Manipulate scroll bars
* Input box focus

### 3️⃣ getCurrentInstance - plug-in development {#_3️⃣-getcurrentinstance-——-插件型开发}

Applies to:

* Get proxy
* Global mounting method
* Frame layer encapsulation

👉 Use business code as little as possible.

## 6\. "Combined function" model in enterprise-level projects (really advanced) {#六、企业级项目中的-组合式函数-模式-真正高级}

#### Encapsulate useXXX hooks {#封装-usexxx-hooks}

For example:

```js
function usePagination() {
  const page = ref(1)
  const pageSize = ref(10)

  return { page, pageSize }
}
```

In the project you can say:

> We abstract the business logic into useXXX hooks to form a reusable logic layer, such as:
>
> * useTable
> * useForm
> * useRequest
> * usePermission
> * useResizeObserver

👉 This is the advanced front-end flag.

## 7\. Which Vue3 hooks are most used in your project? {#七、你们项目中-vue3-hooks-用得最多的是什么}

> The core is ref / reactive for state management.
> computed does derived data,
> watch controls side effects,
> onMounted does initialization,
> onUnmounted controls resource release,
> In large systems, a logical reuse system is formed by encapsulating useXXX hooks.
>
> Performance-sensitive scenarios will focus on watch flush timing and effect batch update mechanism.

## 8\. Add an architecture level {#八、加一段架构级}

> Vue3 hooks are essentially a responsive side effect system built on effect + scheduler.
> All life cycles and watches are essentially different scheduling timings of effects.
