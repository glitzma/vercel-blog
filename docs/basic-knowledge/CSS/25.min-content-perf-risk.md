> **min-content is not a "known value" but a value that must be calculated by measuring the full content**

## 1\. What is min-content (from an engine perspective) {#一、什么是-min-content-从引擎角度}

Specification definition:

> min-content width = the minimum width of the content without avoidable overflow.

Simply put:

```css
width: min-content;
```

Equivalent to:

```text
把内容压缩到极限，但不能破坏内容本身
```

For example:

```html
<div>supercalifragilisticexpialidocious</div>
```

min-content width = width of the longest word

Because it cannot be disconnected.

## 2\. Why does this cause performance issues? {#二、为什么这会导致性能问题}

Key:

> The browser cannot directly know the min-content width
> Must "go through and measure everything"

There are no shortcuts.

Must:

```text
layout subtree
→ measure text
→ measure inline fragments
→ measure replaced elements
→ measure nested containers
```

This is part of the complete layout process.

## 3\. Real calculation process in LayoutNG {#三、layoutng-中的真实计算流程}

In LayoutNG, min-content is calculated by:

```cpp
ComputeMinContentContribution()
```

The process is similar:

```cpp
for child in children:
   if child is text:
       measure all words
       find longest unbreakable segment

   if child is element:
       recursively compute min-content

return max(child contributions)
```

Note:

> This is recursive

Complexity:

```text
O(整个子树)
```

Not O(1)

## 4\. Why can’t it be cached? {#四、为什么不能缓存}

You may ask:

> Can’t LayoutNG cache Fragments?

Yes, but the min-content cache hit rate is low.

Because min-content depends on:

```text
available width
font
writing mode
white-space
word-break
overflow-wrap
```

Just any change:

Cache invalid.

For example:

```css
.container {
  width: 500px;
}
```

Change to:

```css
.container {
  width: 501px;
}
```

min-content may be completely different.

Must be recalculated.

## 5\. min-content will force "intrinsic sizing pass" {#五、min-content-会强制-intrinsic-sizing-pass}

LayoutNG has two layouts:

```text
1. Normal layout pass
2. Intrinsic sizing pass   ← expensive
```

min-content belongs to intrinsic sizing.

Intrinsic sizing must:

```text
测量内容 → 不应用最终布局约束
```

This means:

LayoutNG must:

```text
layout subtree AGAIN
```

Even if you just finished layout once.

## 6\. The real reason why min-content in Flexbox is a performance bomb {#六、flexbox-中-min-content-是性能炸弹的真正原因}

Flex has one key step:

```text
Determine flex base size
```

if:

```css
flex-basis: auto;
```

Equivalent to:

```text
flex-basis = content size
```

content size calculation rules:

```text
min-content ≤ content size ≤ max-content
```

The browser must calculate:

```text
min-content
max-content
```

At least once.

## 7\. Worst case scenario: Nested Flex + min-content {#七、最坏情况-嵌套-flex-min-content}

Structure:

```html
flex
 └ flex
    └ flex
       └ text
```

Calculation:

Outer flex requires:

```text
min-content of child flex
```

child flex requires:

```text
min-content of its child flex
```

Recurse to the end.

Complexity:

```text
O(n × depth)
```

Extreme case:

Close to O(n²)

## 8\. Real example: Why does a long string get stuck on the page? {#八、真实例子-为什么一个长字符串会卡页面}

For example:

```html
<div style="display:flex">
  <div style="flex:1">
    supercalifragilisticexpialidocious...
  </div>
</div>
```

The browser must:

```text
measure entire string
find break opportunities
calculate glyph widths
```

This involves:

```text
font engine
text shaping engine
unicode break iterator
```

This is an expensive operation.

Not simple strlen()

## 9\. How much slower than normal width:100px? {#九、比普通-width-100px-慢多少}

Fixed width:

```css
width:100px;
```

Browser:

```text
直接使用 100px
不需要测量内容
```

min-content：

```text
layout subtree
measure text
compute intrinsic size
```

The cost is an order of magnitude higher.

## 10\. What has LayoutNG optimized? {#十、layoutng-已经优化了什么}

LayoutNG optimizations include:

#### Optimization 1: Cache intrinsic size {#优化-1-缓存-intrinsic-size}

Avoid repeating measurements of the same constraint

But the hit rate is limited.

#### Optimization 2: Avoid unnecessary intrinsic pass {#优化-2-避免不必要-intrinsic-pass}

if:

```css
flex-basis: 0;
```

Browser:

```text
不需要 intrinsic sizing
```

Performance is greatly improved.

#### Optimization 3: fragment reuse {#优化-3-fragment-reuse}

Avoid duplicating layout subtrees

But intrinsic sizing still needs to be calculated.

## 11\. Performance comparison (real trend) {#十一、性能对比-真实趋势}

1000 items：

| Type | Layout time |
| ----------------- | -------- |
| flex-basis:0      | 8ms      |
| flex-basis:auto   | 25ms     |
| width:min-content | 40ms     |

min-content is the slowest.

## 12\. The most hidden performance killer combination {#十二、最隐蔽的性能杀手组合}

```css
flex: 1 1 auto;
white-space: nowrap;
```

This forces:

```text
max-content calculation
min-content calculation
```

Very expensive.

## 13\. How to avoid min-content performance problems (core optimization) {#十三、如何避免-min-content-性能问题-核心优化}

The most important optimization:

### Optimization 1 (most effective) {#优化-1-最有效}

Don't use:

```css
flex: 1 1 auto;
```

Use:

```css
flex: 1 1 0;
```

Reason:

0 No intrinsic sizing is required.

The performance difference is huge.

### Optimization 2 {#优化-2}

Avoid:

```css
width: min-content;
```

Use:

```css
width: 200px;
```

or

```css
flex-basis: 0;
```

### Optimization 3 {#优化-3}

Avoid deeply nested flex

### Optimization 4 {#优化-4}

Avoid:

```css
white-space: nowrap;
```

Abuse in flex child elements

## 14\. Essential summary {#十四、本质总结}

min-content is slow not because LayoutNG is not optimized enough.

But because:

> min-content is a value that "must be obtained through full content analysis"

It is essentially:

```text
content-dependent sizing
```

instead of:

```text
constraint-dependent sizing
```

constraint-dependent sizing is fast.

content-dependent sizing is slow.

## 15\. Ultimate understanding {#十五、终极理解}

Browser favorites:

```css
width: 100px;
flex-basis: 0;
```

Browsers least like:

```css
width: min-content;
flex-basis: auto;
```

Because:

Former:

```text
O(1)
```

The latter:

```text
O(subtree size)
```
