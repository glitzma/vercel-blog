## 1\. What is Radix UI?Understand in one sentence {#一、radix-ui-是什么-一句话理解}

- **Radix UI = Headless, accessibility-first React interactive component primitives**

It provides:

* ✅ Behavioral logic (open / close / focus)
* ✅ Keyboard interaction
* ✅ ARIA Properties
* ✅ Status management
* ❌ No styles provided

👉 **It is the "interaction layer", not the "UI layer"**

## 2\. Why is Radix UI important? {#二、为什么-radix-ui-很重要}

If you write a Dialog yourself, you need to deal with:

* ESC close
* focus trap
* Tab loop
* aria-modal
* screen reader
* Portal

👉 Radix does it all for you, and **WAI-ARIA compliant**

## 3\. Core design philosophy of Radix UI {#三、radix-ui-的核心设计哲学}

### 1️⃣ Headless (no style) {#_1️⃣-headless-无样式}

```tsx
<DialogContent className="bg-white rounded" /-
```

Styling is completely under your control

### 2️⃣ Compound Components {#_2️⃣-compound-components-组合组件}

```tsx
<Dialog>
  <DialogTrigger />
  <DialogContent />
</Dialog>
```

* The parent component provides context
* Subcomponent consumption context
* **Strong constraints and strong semantics**

### 3️⃣ Status controllable / uncontrollable {#_3️⃣-状态可控-不可控}

```tsx
<Dialog open={open} onOpenChange={setOpen} />
```

Or:

```tsx
<Dialog defaultOpen />
```

### 4️⃣ Accessibility First (not an afterthought) {#_4️⃣-accessibility-first-不是事后补}

Every API at Radix is designed around accessibility.

## 4\. Radix UI component classification {#四、radix-ui-组件分类}

#### Overlay class (most important) {#overlay-类-最重要}

* Dialog
* AlertDialog
* Popover
* Tooltip
* DropdownMenu
* ContextMenu

👉 **90% of interactions come from here**

#### Form & Input

* Checkbox
* RadioGroup
* Switch
* Slider
* Select

#### Navigation

* Tabs
* Accordion
* NavigationMenu

## 5\. Core Mechanism 1: Trigger/Content {#五、核心机制一-trigger-content}

```tsx
<Popover>
  <PopoverTrigger>Open</PopoverTrigger>
  <PopoverContent>Content</PopoverContent>
</Popover>
```

Inside Radix:

* Trigger control open
* Content response open
* State is shared via context

## 6\. asChild (very important) {#六、aschild-非常重要}

#### Why asChild? {#为什么要-aschild}

```tsx
<DialogTrigger>
  <Button />
</DialogTrigger>
```

❌ Will wrap an extra layer of DOM

#### Correct way {#正确方式}

```tsx
<DialogTrigger asChild>
  <Button />
</DialogTrigger>
```

👉 **No new DOM, only inject behavior**

The bottom layer uses `Slot`

## 7\. Portal (solve hierarchical issues) {#七、portal-解决层级问题}

```tsx
<DialogPortal>
  <DialogContent />
</DialogPortal>
```

* Render to body
* Avoid z-index hell

## 8\. Radix’s State & Data Attributes {#八、radix-的-state-data-attributes}

Radix will automatically inject:

```html
data-state="open"
data-disabled
data-side="top"
```

You can use Tailwind directly:

```tsx
className="
  data-[state=open]:animate-in
  data-[state=closed]:animate-out
"
```

👉 **This is the key to shadcn/ui animation**

## 9\. Controlled vs. Uncontrolled (must understand) {#九、受控-vs-非受控-一定要懂}

#### Uncontrolled (simple) {#非受控-简单}

```tsx
<Dialog defaultOpen />
```

#### Controlled (recommended in business) {#受控-推荐在业务中}

```tsx
<Dialog open={open} onOpenChange={setOpen} />
```

## 10\. Take Dialog as an example (complete deconstruction) {#十、以-dialog-为例-完整解构}

```tsx
<Dialog>
  <DialogTrigger asChild>
    <Button>Open</Button>
  </DialogTrigger>

  <DialogContent>
    <DialogHeader>
      <DialogTitle>Title</DialogTitle>
      <DialogDescription>Desc</DialogDescription>
    </DialogHeader>
  </DialogContent>
</Dialog>
```

Radix is responsible for:

* open status
* ESC
* focus trap
* aria-describedby

shadcn/ui is responsible for:

* className
* animation
* structural encapsulation

## 11\. Common misunderstandings {#十一、常见误区}

- ❌ Radix is used as a UI library
- ❌Write business logic in Trigger
- ❌ Ignore data-state
- ❌ No need for asChild

## 12\. The relationship between Radix UI + shadcn/ui {#十二、radix-ui-shadcn-ui-的关系}

| Radix | shadcn/ui     |
| ----- | ------------- |
| Interaction primitives | Style encapsulation |
| Unstyled | Tailwind |
| a11y  | Design System |
| Behavior | Vision |

## 13\. When do you “know Radix UI”? {#十三、你什么时候算-会-radix-ui}

You can:

* Handwriting Dialog/Popover/Tabs
* Correct use of asChild
* Use data-state to write animations
* Encapsulate instead of using Radix directly
