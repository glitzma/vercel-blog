## Conclusion {#结论}

> - **Hooks cannot be written in conditions, it is not a grammatical restriction,**
> - **But because React uses "call order" to align Hook state to Fiber.**

Once the order is unstable, **The state will be dislocated and cannot be restored.**

## 2\. How does Hooks “position itself”? {#二、hooks-是怎么-定位自己-的}

We already know:

```txt
Fiber.memoizedState
  └─ hook1 → hook2 → hook3 → null
```

Each render:

```txt
currentHook  → 指向旧链表
workInProgressHook → 构建新链表
```

#### There is only one positioning rule: {#定位规则只有一个}

> **The Nth call to useX() corresponds to the Nth hook node**

no key
no name
No AST
only order

## 3\. Conditional statements directly destroy this unique rule. {#三、条件语句直接破坏了这个唯一规则}

### 1️⃣ Normal situation (stable order) {#_1️⃣-正常情况-顺序稳定}

```ts
useState()   // hook #1
useEffect()  // hook #2
useMemo()   // hook #3
```

Each render is:

```txt
##1 → #2 → #3
```

✔ Correct

### 2️⃣ Conditional Hook (the order is unstable) {#_2️⃣-条件-hook-顺序不稳定}

```ts
useState()       // hook #1

if (cond) {
  useEffect()    // ❌ 有时执行，有时不执行
}

useMemo()        // hook ? ❌
```

#### render #1（cond = true）

```txt
##1 useState
##2 useEffect
##3 useMemo
```

#### render #2（cond = false）

```txt
##1 useState
##2 useMemo   ❌ 本来是 #3
```

## 4\. Source code level dislocation process (the part you care about) {#四、源码级错位过程-你关心的部分}

#### updateWorkInProgressHook simplified version: {#updateworkinprogresshook-简化版}

```ts
function updateWorkInProgressHook() {
  const nextCurrentHook = currentHook.next

  const newHook = clone(nextCurrentHook)

  currentHook = nextCurrentHook
  workInProgressHook.next = newHook
  workInProgressHook = newHook
}
```

React **By default you will call the next Hook** every time.

#### When you skip a Hook: {#当你跳过一个-hook}

* `currentHook` is not moving forward
* `workInProgressHook` but keeps moving forward
* **The linked list is directly misaligned**

## 5\. What will be caused by misalignment?(real disaster) {#五、错位会导致什么-真实灾难}

#### Misalignment is not as simple as "executing one less effect" {#错位不是-少执行一个-effect-这么简单}

##### Example: {#例子}

```ts
const [a, setA] = useState(1)
if (cond) {
  useState(2)
}
const [b, setB] = useState(3)
```

#### Result: {#结果}

* `b` might get `2`
* `setB` operates on the wrong queue
* update lane wrongly tied fiber
* ❌ Behavior is unpredictable

👉 **This is no longer a bug, it’s state pollution**

## 6\. Why doesn’t React use “name/key” to mark Hook? {#六、为什么-react-不用-名字-key-来标记-hook}

You will definitely think of this issue at this level.

#### Theoretically possible, but the cost is extremely high: {#理论上可以-但代价极高}

1️⃣ Each render requires:

* Parse AST
* Create key mapping
* diffHook structure

2️⃣ render is no longer:

```txt
Component(props) → JSX
```

And becomes:

```txt
Component → 解析 → 调度
```

👉 **This directly negates Fiber’s “rerunable render” design**

## 7\. Why doesn’t Vue have this problem? {#七、为什么-vue-没这个问题}

#### Vue effect：

```ts
watchEffect(() => {
  if (cond) {
    console.log(a.value)
  }
})
```

✔ No problem because:

* Effect is **dynamic dependency collection**
* not in order
* Regardless of location
* Not relying on render

👉 **The inevitable result of the two models**

## 8\. StrictMode dual execution, why hasn’t it exploded yet? {#八、strictmode-双执行-为什么还没炸}

Because:

* mount → unmount → mount
* Complete sequence every time
* **Not “one less Hook”**

## 9\. The real rule (not “can’t write if”) {#九、真正的规则-不是-不能写-if}

> - ❌ Misunderstanding: Hooks cannot be written in if
> - ✅ Correct understanding: **The calling sequence of Hooks must be completely consistent in each render**

So these are **allowed**:

```ts
useEffect(() => {
  if (cond) {
    // 可以
  }
}, [cond])
```

```ts
const value = cond ? useMemo(...) : other
// ❌ 不允许（顺序不稳定）
```

## 10\. The ultimate one-sentence summary (for you this kind of principle school) {#十、终极一句话总结-给你这种原理派}

 **Hooks rules are not restrictive to developers,**

 Instead, Hooks uses "sequence" in exchange for:

 * No identification required
 * No need to compile
 * Interruptible render
 * Extremely low runtime cost

This is a very "React-y" deal.
