- **Vue3: "Dependency-driven" centered on effect**
- **React: "Re-execution driver" centered on render + Hooks**

## 1\. Comparison in one sentence (establish your mind first) {#一、一句话对比-先立心智}

| Dimensions | Vue3 | React |
| ----- | ------------ | ------------------- |
| Core units | `effect(fn)` | `render(Component)` |
| Update model | Exact dependency trigger | Rerun the entire function |
| Responsive granularity | Attribute level | Component level |
| Side Effect Scheduling | scheduler | Scheduler + Fiber |
| Data flow | pull (who uses it, who collects it) | push (setState push) |

## 2\. Vue3 effect {#二、vue3-effect}

### 1️⃣The essence of effect {#_1️⃣-effect-的本质}

```ts
effect(() => {
  console.log(state.count)
})
```

**What happened:**

1. `effect(fn)` Push (activeEffect)
2. `state.count` → getter
3. `track(target, key)`
4. Create a mapping of **key → effect**

```txt
state.count
   ↓
Set(effect)
```

### 2️⃣ Trigger update {#_2️⃣-触发更新}

```ts
state.count++
```

1. setter
2. `trigger(target, 'count')`
3. Find dependency effects accurately
4. execute or scheduler(effect)

👉 **Will not affect effects that do not use count**

### 3️⃣The core advantages of Vue effect {#_3️⃣-vue-effect-的核心优势}

* **Depends on automatic collection**
* **Extremely fine particle size**
* **effect ≠ render**
* computed / watch are essentially effects

## 3\. React Hooks: A completely different idea {#三、react-hooks-彻底不同的思路}

### 1️⃣The core of React is not Hook, but render {#_1️⃣-react-的核心不是-hook-是-render}

```jsx
function App() {
  const [count, setCount] = useState(0)
  return <div>{count}</div>
}
```

⚠️ Key points:

> **Component function itself = render effect**

### 2️⃣ What happened to setState {#_2️⃣-setstate-发生了什么}

```ts
setCount(1)
```

1. Create update
2. Enter Fiber updateQueue
3. Scheduler
4. **Re-execute the entire component function**

```txt
render(App)
  ├─ useState
  ├─ useEffect
  ├─ JSX
```

👉 React **I don’t know if you use count**
👉 It chooses: **I will run it all**

### 3️⃣The essence of Hooks {#_3️⃣-hooks-的本质}

#### Hooks ≠ Responsive {#hooks-响应式}

```ts
useState
useEffect
useMemo
```

The essence is:

```ts
hook[i]
```

* Depends on **calling order**
* Rely on **Fiber.memoizedState**
* Each render order must be consistent

## 4\. Dependency comparison: automatic vs manual (the most essential difference) {#四、依赖对比-自动-vs-手动-最本质差异}

### Vue computed

```ts
computed(() => a.value + b.value)
```

* Automatic track in getter
* a / b change → trigger

### React useMemo

```ts
useMemo(() => a + b, [a, b])
```

* Your handwriting depends on
* Less writing = bug
* Writing too much = performance issues

🧠 **React gives you control**

## 5\. effect vs useEffect (similar names, completely different semantics) {#五、effect-vs-useeffect-名字相似-语义完全不同}

|           | Vue `effect` | React `useEffect` |
| --------- | ------------ | ----------------- |
| Positioning | Responsive Core | Side Effects Hook |
| Whether to render | ❌ | ❌ |
| Whether to rely on collection | ✅ Automatic | ❌ Manual |
| Scheduling timing | Synchronization/microtask | After commit |
| Whether it can be nested | ✅ | ❌ |

⚠️ **Don’t use useEffect as watch**

## 6\. Comparison of scheduling models (scheduler) {#六、调度模型对比-scheduler}

### Vue

```txt
setter → trigger → scheduler → jobQueue
```

* effect has scheduler
* computed is lazy
* watch can flush sync / post

### React

```txt
setState
 → Scheduler（lane）
 → render（可中断）
 → commit（不可中断）
```

* render can be interrupted
* commit must be completed
* Concurrency from Fiber

## 7\. Why is React capable of concurrency but Vue doesn’t emphasize it? {#七、为什么-react-能并发-vue-不强调}

#### Vue problem {#vue-的问题}

* The effect granularity is too fine
* Dependencies are complex
* High disruption costs

#### Choice of React {#react-的选择}

* **Coarse-grained render**
* render can be rerun
* Native support for interrupt/retry

👉 **This is the design premise of Fiber**

## 8\. Closure problem: Almost none in Vue, but everywhere in React {#八、闭包问题-vue-几乎没有-react-到处都是}

### React closure trap {#react-闭包陷阱}

```ts
useEffect(() => {
  setInterval(() => {
    console.log(count)
  }, 1000)
}, [])
```

👉 count is always the initial value

#### Vue won’t {#vue-不会}

```ts
watchEffect(() => {
  console.log(count.value)
})
```

## 9\. One-to-one correspondence at the source code level (core comparison) {#九、源码级一一对应-核心对照}

| Vue3      | React               |
| --------- | ------------------- |
| `effect`  | `renderWithHooks`   |
| `track` | handwritten deps |
| `trigger` | `dispatchAction`    |
| scheduler | Scheduler           |
| Dep Map   | Fiber.memoizedState |

## 10\. Summary {#十、总结}

- **Vue3 is "reactive engine + compiler"**
- **React is "re-runnable pure functions + scheduling system"**

**It’s not who is more advanced, but the choices are different.**
