If we start from **"What will happen if global variables are not used?"**, you will find that this is an **almost forced choice**.

> **Hooks uses global variables, not to be lazy, but to ensure:
> render is rerunable, interruptible, zero intrusive, and zero compilation cost.**

## 1\. What "global variables" are used by Hooks? {#一、hooks-到底用到了哪些-全局变量}

There are only these cores:

```ts
let currentlyRenderingFiber = null
let workInProgressHook = null
let currentHook = null
```

Add one more:

```ts
ReactCurrentDispatcher.current
```

👉 **All Hooks work through these "implicit contexts"**

## 2\. Why can’t it be passed by parameters? {#二、为什么不能用参数传递}

An ideal API might be:

```ts
function useState(ctx, initial) { ... }

function App(props, ctx) {
  const [a, setA] = useState(ctx, 0)
}
```

Or more "implicitly":

```ts
function App(props, ctx = useHooksContext()) { ... }
```

#### Does it look clean? {#看起来是不是很干净}

## 3\. The first fatal problem of parameter passing: API is polluted {#三、参数传递的第一个致命问题-api-被污染}

One of React's core goals is to:

> **Component function = ordinary JS function**

```ts
Component(props) → JSX
```

If parameters are introduced:

* Every component needs to receive `ctx`
* Each Hook must be passed explicitly
* User mental complexity skyrockets

👉 **This directly goes against React’s design philosophy**

## 4\. The second fatal problem: render cannot be "transparently rerun" {#四、第二个致命问题-render-无法-透明重跑}

The core premise of Fiber is:

> **render is a discardable, retryable pure function**

If the Hook context relies on parameters:

```ts
render(Component, ctx)
```

You must ensure:

* ctx is consistent across multiple renders
* ctx lifecycle synchronized with Fiber
* ctx traceable on interrupt/resume

👉 **You are actually "Handwriting Fiber"**

## 5\. The third fatal problem: "zero compilation" cannot be achieved {#五、第三个致命问题-无法做到-零编译}

If global variables are not used, the only remaining options are:

#### 1️⃣ Compile time injection {#_1️⃣-编译期注入}

```ts
useState() 
↓ 编译
useState(__hookCtx, ...)
```

This means:

* A compiler is required
* DSL must be locked
* Breaking JS direct writing

👉 **React explicitly rejects this path**

## 6\. The "hidden advantage" of global variables: interrupt friendly {#六、全局变量的-隐藏优势-中断友好}

You already understood Fiber’s execution model:

```ts
renderWithHooks
  set currentlyRenderingFiber
  execute Component()
  clear globals
```

#### What happens when there is an interruption? {#中断时会发生什么}

* render is discarded
* Global variables are reset directly
* **No semi-finished product will be left**

If it is a parameter:

* You want to save ctx
* To roll back
* to replay

👉 **Complexity increases exponentially**

## 7\. Why is the “overall situation” safe? {#七、为什么-全局-却是安全的}

This is an easily misunderstood point.

#### Not the "real global state" {#并不是-真正的全局状态}

Instead:

> **"Dynamic scope" during render**

```ts
renderWithHooks() {
  set globals
  Component()
  clear globals
}
```

* single thread
* Only render one Fiber at the same time
* No concurrent write conflicts

👉 **logically safe**

## 8\. Vue effect comparison (helping you align) {#八、vue-effect-对照-帮你对齐}

| Vue3         | React                   |
| ------------ | ----------------------- |
| activeEffect | currentlyRenderingFiber |
| effect(fn)   | renderWithHooks         |
| track implicit | Hooks implicit |
| Compilation enhancements | Runtime conventions |

👉 Both are **"implicit contexts"**, just in different positions.

## 9\. What will happen if global variables are not used forcibly? {#九、如果强行不用全局变量-会怎样}

You will get a frame:

* Component signature is tainted
* Hook API is complex
* render is no longer a pure function
* Interruption/concurrency cost explosion
* Compiler must be introduced

👉 **This is not React anymore**

## 10\. Summary {#十、总结}

> **Hooks uses global variables in order to use "minimum runtime cost".
> In exchange for "maximum scheduling freedom" and "the cleanest user API".**

This isn't an implementation detail, it's a **core design choice**.
