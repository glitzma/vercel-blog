### 1️⃣2️⃣ How to implement batch updates in React? {#_1️⃣2️⃣-react-如何实现批量更新}

React is not implemented through simple timers, but through priorities and task queues.

Follow-up question:

* What is the difference between React 17 and 18?
* Why was there no batch processing in setTimeout before?

| Features | React 17 | React 18 |
| --- | --- | --- |
| **Batch Update Scope** | Lifecycle and composition events only.| **Comprehensive automatic batch processing** (including Promise, setTimeout, native events).|
| **Rendering Mode** | Synchronous, uninterruptible rendering.| **Concurrent Rendering**, interruptible and slicable.|
| **Main API** | `ReactDOM.render` | `ReactDOM.createRoot` (new API must be used to enable new features).|
| **NEW FEATURES** | None.| Introduce `useTransition`, `useDeferredValue` to handle non-urgent updates.|
| **Suspense** | Only code splitting is supported.| Supports server-side rendering (SSR) and data retrieval.|

Why doesn't React 17 (and before) batch in setTimeout?

The fundamental reason behind this is the loss of **Execution Context**.

 Core mechanism: the "switch" of synchronization

In React 17, batch updates are based on **Synthetic Event System** realized.

* When the user clicks the button, React will first set an internal flag (such as `isBatchingUpdates`) to `true`.
* Then execute your `onClick` function.
* After the function is executed, React sets the flag back to `false` and triggers a re-render.

Why does `setTimeout` "escape"?

When `setTimeout` is written in your code, the execution sequence is as follows:

1. React enters click event processing and turns on "batch mode".
2. When `setTimeout` is encountered, the callback function inside is pushed into the browser's **Event Queue** for asynchronous waiting.
3. The `onClick` synchronization code ends, React **turns off** the batch mode and completes rendering.
4. **A long time later**, the callback in `setTimeout` is triggered, and at this time React's batch switch has been turned off.
5. every call `setState` , React found that it was not in batch mode, so it had to **forced immediately** Carry out a complete rendering process.
