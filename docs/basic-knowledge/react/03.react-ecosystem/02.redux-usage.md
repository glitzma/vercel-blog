## 1\. First give you a learning panorama {#一、先给你一个学习全景图}

### The evolution of Redux (very important) {#redux-的演进脉络-很重要}

1. **Redux (Classic)**

   * createStore
   * reducer / action
   * middleware（thunk、logger）
2. **React-Redux**

   * `<Provider />`
   * `connect`
3. **Hooks Era**

   * `useSelector`
   * `useDispatch`
4. **Redux Toolkit (RTK, official recommendation)**

   * `configureStore`
   * `createSlice`
   * `createAsyncThunk`
   * Built-in immer + thunk
5. **RTK Query (server status)**

   * Request / cache / deduplication / invalidation

👉 Now **90% of Redux projects = Redux Toolkit + Hooks**

## 2\. The “essential problem” solved by Redux {#二、redux-解决的-本质问题}

> **Redux = Predictable global state management + explicit state change trajectory**

### What does Redux solve? {#redux-解决什么}

* Share state across components/cross levels
* Status changes can be tracked (time travel, logs)
* Extract **state change logic** from components

### What is Redux not suitable for? {#redux-不适合什么}

* form local state
* UI temporary state (hover / open)
* High frequency transient state (mousemove)

## 3\. The core idea of Redux (no need to write code first) {#三、redux-核心思想-先不用写代码}

### 1️⃣ Single data source (Single Store) {#_1️⃣-单一数据源-single-store}

```txt
UI → dispatch(action) → reducer → new state → UI
```

### 2️⃣ The status is read-only {#_2️⃣-状态是只读的}

* Cannot `store.state.xxx = 1`
* Only available via `dispatch`

### 3️⃣ Use pure functions to update status {#_3️⃣-使用纯函数更新状态}

```js
(state, action) => newState
```

These three articles = Redux’s “Constitution”

## 4\. Modern Redux (RTK) minimal mental model {#四、现代-redux-rtk-最小心智模型}

### What has Redux Toolkit done for you? {#redux-toolkit-帮你做了什么}

* Automatically combine reducers
* Automatically connect to thunk
* Automatic access to immer (you can "write mutable code")
* Works with DevTools out of the box

### There are only 4 things you really need to understand {#你真正要理解的只有-4-个东西}

```txt
Store
Slice
Dispatch
Selector
```

## 5\. Minimal RTK example from 0 to 1 (essence) {#五、从-0-到-1-的最小-rtk-示例-精华}

### 1️⃣ Create slice (state + reducer + action) {#_1️⃣-创建-slice-状态-reducer-action}

```js
import { createSlice } from '@reduxjs/toolkit'

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment(state) {
      state.value++
    },
    addBy(state, action) {
      state.value += action.payload
    }
  }
})

export const { increment, addBy } = counterSlice.actions
export default counterSlice.reducer
```

⚠️ **You can "change the state directly" here because of immer**

### 2️⃣ Create store {#_2️⃣-创建-store}

```js
import { configureStore } from '@reduxjs/toolkit'
import counterReducer from './counterSlice'

export const store = configureStore({
  reducer: {
    counter: counterReducer
  }
})
```

### 3️⃣ Inject React {#_3️⃣-注入-react}

```js
import { Provider } from 'react-redux'
import { store } from './store'

root.render(
  <Provider store={store}>
    <App />
  </Provider>
)
```

### 4️⃣ Use it in components {#_4️⃣-在组件里用}

```js
import { useSelector, useDispatch } from 'react-redux'
import { increment } from './counterSlice'

function Counter() {
  const value = useSelector(state => state.counter.value)
  const dispatch = useDispatch()

  return (
    <button onClick={() => dispatch(increment())}>
      {value}
    </button>
  )
}
```

## 6\. Implementation principles behind Redux {#六、redux-背后的实现原理}

### 1️⃣What is Store? {#_1️⃣-store-是什么}

Essentially:

```js
{
  getState,
  dispatch,
  subscribe
}
```

### 2️⃣What did dispatch do? {#_2️⃣-dispatch-干了什么}

```txt
dispatch(action)
  ↓
rootReducer(currentState, action)
  ↓
生成 newState
  ↓
通知所有 subscribers
```

### 3️⃣ How is React-Redux “accurately updated”? {#_3️⃣-react-redux-是如何-精准更新-的}

* Each `useSelector` is a subscriber
* Use **quote comparison/equalityFn**
* Fiber render phase triggers updates (rather than Redux active render)

- 👉 Redux **doesn’t care how React is updated**
- 👉 React-Redux **doesn’t care how reducer is calculated**

## 7\. Asynchronous: Why use thunk / createAsyncThunk {#七、异步-为什么用-thunk-createasyncthunk}

### Redux itself only supports synchronization {#redux-本身只支持同步}

```txt
dispatch({ type: 'ADD' })
```

### thunk allows dispatch to support functions {#thunk-让-dispatch-支持函数}

```js
dispatch((dispatch, getState) => {
  setTimeout(() => {
    dispatch(addBy(10))
  }, 1000)
})
```

### RTK’s standard asynchronous scheme {#rtk-的标准异步方案}

```js
export const fetchUser = createAsyncThunk(
  'user/fetch',
  async (id) => {
    const res = await fetch(`/api/user/${id}`)
    return res.json()
  }
)
```

Automatically generated:

* pending
* fulfilled
* rejected

## 8\. When should you use Redux? {#八、什么时候该用-redux}

### ✅Suitable {#✅-适合}

* User information/permissions
* Global configuration
* Complex business state machine
* Multi-page sharing status

### ❌ Not suitable {#❌-不适合}

* UI state (Modal/Tabs)
* form
* Simple father-son communication
