These examples use Zustand 5. The Hook returned by `create` does not accept a second custom equality argument; use `useShallow` to stabilize object selector results.

Zustand is a lightweight, boilerplate-free React state management library.It is simpler than Redux, more efficient than Context, and is very suitable for small to medium-sized projects.

## 1\. Zustand core concept {#一、zustand-核心理念}

#### ✅ Design philosophy {#✅-设计哲学}

* Minimalist API
* Based on Hooks
* No Provider (default)
* Support middleware
* Support TS friendly

Core idea:

> Use a global store + hook to selectively subscribe to state

## 2\. Basic introduction {#二、基础入门}

### 1️⃣ Installation {#_1️⃣-安装}

```bash
npm install zustand@5
```

### 2️⃣ Create the first Store {#_2️⃣-创建第一个-store}

```ts
import { create } from 'zustand'

const useCounterStore = create((set) => ({
  count: 0,
  increase: () => set((state) => ({ count: state.count + 1 })),
  decrease: () => set((state) => ({ count: state.count - 1 })),
}))
```

### 3️⃣ Used in components {#_3️⃣-组件中使用}

```tsx
function Counter() {
  const { count, increase, decrease } = useCounterStore()

  return (
    <>
      <div>{count}</div>
      <button onClick={increase}>+</button>
      <button onClick={decrease}>-</button>
    </>
  )
}
```

- ✔ Automatic subscription
- ✔ Automatically unsubscribe when components are uninstalled
- ✔ No Provider

## 3\. Advanced core skills {#三、进阶核心技巧}

### 🎯 1. Accurate subscription (avoiding invalid rendering) {#🎯-1-精准订阅-避免无效渲染}

```ts
const count = useCounterStore((state) => state.count)
```

Only listens to `count`, changes in other fields will not trigger re-rendering.

#### Matching and comparison {#搭配浅比较}

```ts
import { useShallow } from 'zustand/react/shallow'

const { count, increase } = useCounterStore(
  useShallow((state) => ({ count: state.count, increase: state.increase }))
)
```

### 🎯 2. Asynchronous operation (request interface) {#🎯-2-异步操作-请求接口}

```ts
const useUserStore = create((set) => ({
  user: null,
  loading: false,
  fetchUser: async () => {
    set({ loading: true })
    const res = await fetch('/api/user')
    const data = await res.json()
    set({ user: data, loading: false })
  }
}))
```

- ✔ Zustand does not limit async
- ✔ No thunk / saga concept

### 🎯 3. Middleware usage {#🎯-3-中间件使用}

#### persist (local storage) {#persist-本地存储}

```ts
import { persist } from 'zustand/middleware'

const useStore = create(
  persist(
    (set) => ({
      theme: 'light',
      toggle: () => set((s) => ({ theme: s.theme === 'light' ? 'dark' : 'light' })),
    }),
    {
      name: 'app-storage',
    }
  )
)
```

#### devtools (debugging) {#devtools-调试}

```ts
import { devtools } from 'zustand/middleware'

const useStore = create(
  devtools((set) => ({
    count: 0,
    inc: () => set((s) => ({ count: s.count + 1 }), false, 'inc')
  }))
)
```

Can be viewed in Redux DevTools.

### 🎯 4. Split modules (large projects) {#🎯-4-拆分模块-大型项目}

Recommended structure:

```
store/
 ├── index.ts
 ├── user.ts
 ├── cart.ts
 └── theme.ts
```

#### Module merge {#模块合并}

```ts
import { create } from 'zustand'
import { createUserSlice } from './user'
import { createCartSlice } from './cart'

export const useStore = create((...a) => ({
  ...createUserSlice(...a),
  ...createCartSlice(...a),
}))
```

- ✔ Similar to Redux slice
- ✔ Clearer
- ✔ High maintainability

## 4\. Advanced practical skills {#四、高级实战技巧}

### 🔥 1. get() reads the latest status {#🔥-1-get-读取最新状态}

```ts
const useStore = create((set, get) => ({
  count: 0,
  double: () => {
    const current = get().count
    set({ count: current * 2 })
  }
}))
```

### 🔥 2. subscribe monitoring (non-component environment) {#🔥-2-subscribe-监听-非组件环境}

```ts
const unsubscribe = useStore.subscribe((state, previous) => {
  if (state.count !== previous.count) {
    console.log('count changed:', state.count)
  }
})
// Call unsubscribe() when the listener is no longer needed.
```

Applies to:

* Logging system
* websocket
* External module listening

### 🔥 3. immer middleware (complex object) {#🔥-3-immer-中间件-复杂对象}

```ts
// Install the optional dependency first: npm install immer
import { immer } from 'zustand/middleware/immer'

const useStore = create(
  immer((set) => ({
    user: { name: '', age: 0 },
    updateName: (name: string) =>
      set((state) => {
        state.user.name = name
      }),
  }))
)
```

- ✔ Variable writing
- ✔ Internally automatic immutable

### 🔥 4. Reset Store {#🔥-4-重置-store}

```ts
const initialState = { count: 0 }

const useStore = create((set) => ({
  ...initialState,
  reset: () => set(initialState),
}))
```

## 5\. Summary of performance optimization {#五、性能优化总结}

#### ✅Must do {#✅-必做}

* Use selector
* Use shallow
* split store
* Avoid returning large objects directly

#### ❌Avoid {#❌-避免}

* Deconstruction of the entire state
* Write complex UI states in the store
* Put all states in one store

## 6\. Zustand vs Redux comparison {#六、zustand-vs-redux-对比}

| Comparison | Zustand | Redux |
| ---- | ------- | ----- |
| Learning cost | Low | High |
| Template code | Less | More |
| Middleware | Support | Strong |
| Suitable projects | Small/medium/medium-large | Medium-large |

## 7\. Enterprise-level best practices {#七、企业级最佳实践}

#### 1️⃣ Status layering {#_1️⃣-状态分层}

* UI state (local)
* Global shared state (Zustand)
* Server status (React Query)

Recommended combination:

* Zustand + React Query
* Zustand + Vite
* Zustand + Next.js

#### 2️⃣ Don’t abuse global state {#_2️⃣-不要滥用全局状态}

Judgment criteria:

* Sharing multiple components?
* Does it span pages?
* Is caching required?

Otherwise use useState.

## 8\. Summary of common pitfalls {#八、常见坑总结}

- ⚠ Initialized twice under StrictMode
- ⚠ persist needs to handle version upgrades
- ⚠ SSR needs to avoid state pollution
- ⚠ Pay attention to coverage issues with asynchronous concurrency

## 🔟 Ultimate summary {#🔟-终极总结}

Zustand is suitable for:

- ✔ Pursue simplicity
- ✔ Don’t want to write reducer
- ✔ Don’t want to configure complex middleware
- ✔ Want the ultimate development experience

One sentence summary:

> Small but beautiful, sufficient and powerful.
