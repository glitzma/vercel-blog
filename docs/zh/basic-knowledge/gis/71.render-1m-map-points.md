其实想考你三件事：

```
渲染技术
数据分层
性能架构
```


## 一、最基础方案：WebGL 渲染 {#一、最基础方案-webgl-渲染}

需要区分 DOM 节点数量与 Canvas/WebGL 中绘制的点数量：

```
为每个点创建 DOM/SVG 节点往往成本很高；Canvas 的绘制点不等于 DOM 节点
```

大规模可视点通常优先评估 WebGL 批量绘制，同时结合聚合、分块和可见范围裁剪；Canvas 也可用于合适规模和交互需求，不能仅凭数据条数断言必定崩溃。

常见库：

* Mapbox GL JS
* deck.gl

它们本质是：

```
WebGL → GPU 并行绘制
```

渲染流程：

```
数据 → Buffer → GPU → Shader → 渲染
```

GPU 可批量绘制大量点，但可承载规模取决于硬件、点样式、数据更新与交互开销。

例如：

```
deck.gl ScatterplotLayer
```

支持：

```
百万级点位
```


## 二、第二层优化：空间分层（LOD） {#二、第二层优化-空间分层-lod}

100 万点 **没必要全部画**。

地图通常采用：

```
LOD (Level Of Detail)
```

不同 zoom 层级加载不同数据。

例如：

| zoom | 数据  |
| ---- | --- |
| 5    | 城市级 |
| 8    | 区县  |
| 12   | POI |
| 16   | 单点  |

也就是：

```
远 → 少
近 → 多
```


## 三、第三层优化：Vector Tile（核心） {#三、第三层优化-vector-tile-核心}

大规模生产系统常采用分块或瓦片加载；是否适合一次载入完整 GeoJSON，应按文件体积、内存和更新需求测量。

而是：

```
Vector Tile
```

原理：

```
地图切成瓦片
```

```
z/x/y
```

每个 tile 只加载 **当前屏幕数据**。

例如：

```
屏幕最多 20 个 tile
```

每个 tile：

```
2000 点
```

最终：

```
20 * 2000 = 40000
```

而不是：

```
1000000
```

这就是互联网地图核心架构。

VectorTile 技术：

* Mapbox
* OpenLayers


## 四、第四层优化：点位聚合（Cluster） {#四、第四层优化-点位聚合-cluster}

当 zoom 很小的时候：

```
一个城市可能有 50000 点
```

用户根本看不清。

所以需要：

```
Cluster
```

例如：

```
5000点 → 1个圆
```

显示：

```
5000
```

放大后：

```
5000 → 20 cluster
```

再放大：

```
cluster → 单点
```

很多库内置：

* Mapbox GL JS
* deck.gl


## 五、第五层优化：数据分块加载 {#五、第五层优化-数据分块加载}

不要：

```
一次返回 100 万
```

应该：

```
分页 + tile
```

后端通常：

```
PostGIS
```

按 bbox 查询：

```
SELECT * 
FROM points
WHERE ST_Intersects(...)
```


## 六、第六层优化：GPU Instancing {#六、第六层优化-gpu-instancing}

GPU Instancing 是减少重复几何绘制调用的一种手段，并非所有点图层都必须采用：

```
Instanced Rendering
```

原理：

```
一次 draw call
渲染 N 个实例
```

而不是：

```
draw → 1000000 次
```

很多库内部已经实现：

* deck.gl


## 七、真实生产架构（标准答案） {#七、真实生产架构-标准答案}

一个 **百万点地图系统架构**：

```
数据层
   ↓
PostGIS
   ↓
Tile Server
   ↓
VectorTile
   ↓
MapboxGL / deck.gl
   ↓
WebGL GPU 渲染
```

优化策略：

```
VectorTile
LOD
Cluster
Instancing
```


## 八、标准答案 {#八、标准答案}

> 如果需要在地图上渲染 100 万点位，我通常会从三个层面优化：
>
> 渲染层按可见点数和交互需求选择 WebGL 批量绘制或 Canvas，避免把每个点都做成独立 DOM 节点。
>
> 第二是数据层，通过 VectorTile 按地图瓦片加载数据，避免一次加载全部数据。屏幕通常只会显示几十个 tile，每个 tile 只包含几千个点。
>
> 第三是可视化优化，比如在低 zoom 层级使用 cluster 聚合点位，在高 zoom 层级再展示真实点。
>
> 支持的图层可用实例化或其它批处理方式减少 draw call；流畅度仍须在目标设备上测量。



## 九、如果继续深挖（高级） {#九、如果继续深挖-高级}

可能会问：

#### 1 Mapbox GL 为什么快？ {#_1-mapbox-gl-为什么快}

答案：

```
VectorTile + WebGL
```


#### 2 GeoJSON 为什么慢？ {#_2-geojson-为什么慢}

因为：

```
一次加载全部
```


#### 3 deck.gl 为什么能支持百万点？ {#_3-deck-gl-为什么能支持百万点}

因为：

```
GPU Instancing
```
