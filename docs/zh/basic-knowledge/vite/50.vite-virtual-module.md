下面用一个教学插件演示环境变量虚拟模块。示例面向 Vite 5/6，开发时在环境文件变化后整页刷新；它不替代内置 env 系统。

```js
import env from 'virtual:env'

console.log(env.VITE_API_URL)
```

它会自动读取：

* `.env`
* `.env.local`
* `.env.development`
* 或者你定义的任何自定义 env 文件

并生成一个虚拟模块 `virtual:env` 供任意代码直接 import。

这类插件在真实项目里非常有用。

## 🚀 最终效果 {#🚀-最终效果}

你可以在任意文件中写：

```js
import env from 'virtual:env'

console.log(env)
```

输出示例：

```json
{
  "VITE_API_URL": "https://api.xxx.com",
  "VITE_TITLE": "My App"
}
```

这个模块是自动生成的，无需手动维护。

## 🔥 一、插件完整代码（插件文件：`plugins/virtualEnv.js`） {#🔥-一、插件完整代码-插件文件-plugins-virtualenv-js}

代码使用 Vite 的 loadEnv 处理文件优先级和变量展开，并将跨钩子状态保存在闭包中。

```js
import path from 'node:path'
import { loadEnv } from 'vite'

export default function virtualEnvPlugin(options = {}) {
  const id = 'virtual:env'
  const resolvedId = '\0' + id
  let config
  let envDir
  let clientEnv = {}

  function readEnv() {
    return loadEnv(config.mode, envDir, 'VITE_')
  }

  return {
    name: 'vite-plugin-virtual-env',
    configResolved(resolved) {
      config = resolved
      envDir = options.envDir
        ? path.resolve(config.root, options.envDir)
        : config.envDir
      clientEnv = readEnv()
    },
    resolveId(source) {
      if (source === id) return resolvedId
    },
    load(source) {
      if (source === resolvedId) {
        return 'export default ' + JSON.stringify(clientEnv)
      }
    },
    configureServer(server) {
      const files = new Set([
        '.env', '.env.local',
        '.env.' + config.mode, '.env.' + config.mode + '.local'
      ].map(file => path.resolve(envDir, file)))
      server.watcher.add([...files])
      const refresh = file => {
        if (!files.has(path.resolve(file))) return
        clientEnv = readEnv()
        const mod = server.moduleGraph.getModuleById(resolvedId)
        if (mod) server.moduleGraph.invalidateModule(mod)
        server.ws.send({ type: 'full-reload', path: '*' })
      }
      for (const event of ['add', 'change', 'unlink']) {
        server.watcher.on(event, refresh)
      }
      server.watcher.once('close', () => {
        for (const event of ['add', 'change', 'unlink']) {
          server.watcher.off(event, refresh)
        }
      })
    }
  }
}
```

## 📌 二、在 `vite.config.js` 中使用 {#📌-二、在-vite-config-js-中使用}

```js
import { defineConfig } from 'vite'
import virtualEnvPlugin from './plugins/virtualEnv.js'

export default defineConfig({
  plugins: [
    virtualEnvPlugin()
  ]
})
```

## 📁 三、使用示例 {#📁-三、使用示例}

假设你的 `.env.development`：

```
VITE_API_URL=https://api.dev.com
VITE_APP_NAME=Dev App
SECRET_KEY=xxx
```

你在代码中使用：

```js
import env from 'virtual:env'

console.log(env)
```

实际结果（只暴露 VITE_ 前缀的变量）：

```json
{
  "VITE_API_URL": "https://api.dev.com",
  "VITE_APP_NAME": "Dev App"
}
```

## 🔄 四、支持 HMR {#🔄-四、支持-hmr}

当这些环境文件新增、修改或删除时，插件重新读取数据、使已加载的虚拟模块失效，并触发整页刷新。

例如改 `.env.local`：

```diff
-VITE_APP_NAME="Dev App"
+VITE_APP_NAME="Dev App Updated"
```

浏览器会收到：

```
full-reload
```

这是本插件添加的行为；对 Vite 内置 env 的更改，仍应按官方文档重启开发服务器。

## ⚙️ 五、为什么 Vite 要限制只暴露 `VITE_` 前缀？ {#⚙️-五、为什么-vite-要限制只暴露-vite-前缀}

Vite 的官方策略同样是：

```
只有 VITE_ 前缀的变量才会暴露给浏览器
```

这是 **安全策略**，避免把敏感变量泄漏到客户端。

你可以自行决定要不要严格限制，插件里可以自定义：

```js
if (k.startsWith('CLIENT_'))
```

## 🧠 六、插件原理总结（重要） {#🧠-六、插件原理总结-重要}

虚拟模块的流程：

1. `resolveId('virtual:env')` → 返回 `\0virtual:env`
2. `load('\0virtual:env')` → 返回 env JS 内容
3. 浏览器 import 时直接得到生成的模块
4. `.env` 文件变化 → watcher → 模块失效（若存在）→ 整页刷新

这是 Vite 架构中最美妙的部分：
**虚拟模块 + HMR + 自动依赖图刷新**
