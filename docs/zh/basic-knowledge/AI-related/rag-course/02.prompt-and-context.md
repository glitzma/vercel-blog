# 第 02 课：Prompt 和 Context，怎样让模型理解你的要求 {#lesson-02}

把一段通知发给 AI，只说“帮我处理一下”，你可能会收到摘要，也可能收到一篇宣传文案。它们未必写得差，只是“处理”两个字没有告诉它你想要什么。

这就是学习 Prompt 的起点。先不用找所谓的万能提示词，把任务说清楚，往往就能解决一大半沟通问题。

## 你要它做什么，它手里又有什么 {#concepts}

Prompt 通常指给模型的输入或指令。Context 是它这次回答能用的上下文：你提供的资料、应用仍保留的对话内容、工具返回的结果，都可能在里面。指令本身也属于上下文，所以不要把两个词理解成互不相干的东西。

写输入时，可以先问自己两句：“我要它交出什么？”“它要依据哪段资料？”比如你要的是给新同学看的两点说明，依据是 B 的借阅规则。再补一句要保留的内容，整件事就具体了。

“你是一名专业图书管理员”可以影响语气，却没有提供本馆的借期。模型不会因为获得一个角色，就自动知道你的私人手册。缺资料时，写十遍“务必准确”也补不出那个数字。

## 同一段话，换个要求 {#case}

先用一个宽泛要求：“概括下面的借阅规则。”再试：“面向新生，用两点说明借阅规则，保留上限和借期，不添加其他规定。”两次都提供同一个 B，比较起来才知道差别来自指令。

第二次可接受的回答很短：最多同时借三本；每本借期十四天。如果多了一句“必须网上续借”，就回头找依据。B 没说这件事，格式整齐也不能让它变成事实。

这时你已经有两个检查点：形式是不是两点，事实有没有改变。把它们分开看，比凭感觉判断“这次回答更好了”更容易发现问题。

## 为什么不直接粘贴整本手册 {#context-size}

上下文有容量限制，具体多少取决于模型和应用。即使放得下，重要规则埋在活动新闻、目录和旧版本里，也会更难使用。先选短而相关、条件完整的资料，结果反而容易核对。对话越长，也不能默认应用永远保留全部历史。

今天只改一件事：用 B 分别要一句话和两点说明。记下是否都留下了三本、十四天，有没有多写规定。下一篇我们再讨论资料从哪里来。

::: details 可以用这两个点自查

一种合格的概括是“每位读者最多同时借三本，每本借期十四天”。两点写法也应保留同样事实。表达不同没关系；数字改变、事实遗漏或无依据补充，才需要修改。

:::
