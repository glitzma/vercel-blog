# 第 05 课：RAG、模型训练和 Agent 有什么关系 {#lesson-05}

读到这里，你可能已经见过三个词：训练模型、RAG、Agent。它们经常出现在同一篇介绍里，看久了容易觉得都在说“让 AI 更聪明”。拿图书馆助手来看，差别会清楚一些。

## 新规则一定要重新训练吗 {#training}

训练会调整模型参数，让它从数据中学习。微调也是训练，常用来让模型更适应某类任务、风格或输出方式。不过，把今年最多借三本这种经常变化的事实都靠训练更新，未必是问答系统最方便的维护方式。

RAG 则在回答时找资料。借阅规则变了，先维护文档和索引，让检索能找到新的 B。模型参数可能没有变化，却能依据这次给到的资料回答三本。你上传一份文件让它阅读，通常不能直接叫作训练。

训练与 RAG 可以一起用。例如微调让答案更符合某种格式，RAG 提供本次需要的规则。选择方法时，先看你要改善的是任务表现，还是给回答补上变化中的知识。

## 能回答规则，不等于能替你办事 {#agents}

问“讨论室最多预约多久”，G 给出两小时。问“帮我约今天下午两点的讨论室”，就还要查当前有没有空房、提交预约、确认结果。G 只有使用规则，不能证明某个时段现在可订。

Agent 通常涉及由模型选择接下来做什么、调用工具，并根据结果继续处理。固定的程序流程也能完成预约，所以不能把所有会调用 API 的系统都叫 Agent。你现在先关注有没有任务决策、工具执行和结果反馈。

一个 Agent 可以先用 RAG 查规则，再调用预约工具。普通 RAG 流程也可能通过 API 取资料。它们可以组合，区别在于讨论的是取证回答，还是更广的任务执行。

## 把这三个需求分清楚 {#practice}

想让答案始终按指定格式输出；想让答案依据最新借阅规则；想让助手完成一次预约。分别写下你会先检查什么，再用三分钟把区别讲给别人听。讲的时候保留图书馆例子，会比背术语容易。

::: details 可以这样判断

格式先从指令和示例试起，必要时再考虑微调；最新规则需要维护资料与检索；预约需要能执行操作的工具和相应流程，可能采用 Agent。方法并不互斥，也不必为了一个简单需求把三种都用上。

:::
