## 一、理解 Composite Layer {#一、理解-composite-layer}

- **浏览器把页面拆成多个图层，每个图层单独绘制，**
- **最后交给 GPU 只做“位移 / 透明度 / 变换”的合成。**

核心点：

* 图层内容稳定时可复用已栅格化的像素。
* 满足合成条件的 transform / opacity 动画可主要走 **Composite**。
* 内容、尺寸或其他绘制属性变化仍可能触发 Layout / Paint。


## 二、为什么要有 Composite Layer？ {#二、为什么要有-composite-layer}

#### ❌ 传统流程的问题 {#❌-传统流程的问题}

```
JS → Layout → Paint → Composite
```

动画每一帧都：

* 重新计算布局
* 重新绘制像素

👉 CPU 爆炸，FPS 掉到 20+


#### ✅ 引入合成层后的流程 {#✅-引入合成层后的流程}

```
首次：
Layout → Paint（生成位图）

动画中：
Composite（GPU 位移）
```

👉 **只在 GPU 做矩阵运算**


## 三、浏览器内部视角（非常关键） {#三、浏览器内部视角-非常关键}

#### 每个 Composite Layer 本质是： {#每个-composite-layer-本质是}

* 一张 **位图（Rasterized Bitmap）**
* 有自己的：

  * 位移矩阵
  * 透明度
  * Z 顺序

GPU 每一帧只做：

```text
matrix * bitmap → screen
```

⚡ 极快


## 四、哪些情况会创建 Composite Layer？（必背） {#四、哪些情况会创建-composite-layer-必背}

### 🚀 主动创建（你能控制） {#🚀-主动创建-你能控制}

```css
transform: translateZ(0);
transform: translate3d(0,0,0);
opacity < 1;
will-change: transform;
```


### 🌈 浏览器自动创建 {#🌈-浏览器自动创建}

* `position: fixed`
* `video / canvas / iframe`
* CSS 3D transform
* 有动画的 transform / opacity
* `overflow: scroll`（部分场景）


### ❌ 不会创建合成层 {#❌-不会创建合成层}

```css
left / top
width / height
margin / padding
background
color
```

这些都会回到：
👉 Layout / Paint


## 五、DevTools 实战验证 {#五、devtools-实战验证}

### 2️⃣ Demo 对比 {#_2️⃣-demo-对比}

#### transform 动画（只 Composite） {#transform-动画-只-composite}

```css
.box {
  transition: transform 0.5s;
}
```

👉 只有边框在动
👉 没有 Paint 闪烁


#### left 动画（全流程） {#left-动画-全流程}

```css
.box {
  transition: left 0.5s;
  position: relative;
}
```

👉 每帧：

* Layout
* Paint
* Composite


### 3️⃣ Performance 面板确认 {#_3️⃣-performance-面板确认}

你会看到：

* transform：🟦 Composite
* left：🟪 Layout + 🟩 Paint


## 六、Composite Layer 的代价 {#六、composite-layer-的代价}

### ⚠️ 不是越多越好 {#⚠️-不是越多越好}

#### 每个合成层： {#每个合成层}

* 占用 GPU 显存
* 增加合成成本

#### 滥用 will-change 的后果： {#滥用-will-change-的后果}

* 显存暴涨
* 页面反而变慢
* 移动端更明显

📌 **原则：用完就撤**

```css
.box {
  will-change: transform;
}
.box.done {
  will-change: auto;
}
```


## 七、为什么 opacity / transform 可以“跳过 Paint”？ {#七、为什么-opacity-transform-可以-跳过-paint}

#### 因为： {#因为}

* 不改变像素内容
* 只是改变：

  * 位移矩阵
  * alpha 值

👉 位图复用


## 八、Composite Layer 与 Layout Thrashing 的关系 {#八、composite-layer-与-layout-thrashing-的关系}

| 问题        | 解决方案      |
| --------- | --------- |
| 频繁 Layout | transform |
| 频繁 Paint  | 合成层       |
| 动画卡顿      | GPU 合成    |

📌 **Composite 是最终性能逃生舱**


## 九、框架视角 {#九、框架视角}

### React / Vue 为什么爱 transform？ {#react-vue-为什么爱-transform}

```jsx
<div style={{ transform: `translateX(${x}px)` }} />
```

* transform 通常不改变其他节点的布局几何信息。
* 是否避免重绘取决于图层与内容，需用 Performance 验证。
* JS 驱动动画仍执行主线程逻辑；框架不会让任意回调自动可中断。

浏览器合成优化与 React 调度是两个独立机制。


### React Fiber 和 Composite 的契合点 {#react-fiber-和-composite-的契合点}

* Fiber：组织组件工作，部分 render 工作可以让出控制权。
* Composite：浏览器将可复用的图层合成为输出画面。

两者可以改善不同阶段的开销，不能将合成层视为 Fiber 的调度单元。


## 十、总结 {#十、总结}

- Composite Layer 是浏览器为提升渲染性能引入的图层机制，
- 页面会被拆分成多个独立位图图层，
- 动画过程中如果只改变 transform 或 opacity，
- 浏览器可以跳过 Layout 和 Paint，
- 直接由 GPU 进行合成，从而获得更高帧率。
- 但合成层并非越多越好，过多会带来显存和合成开销。
