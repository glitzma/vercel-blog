## 一、什么是微前端 {#一、什么是微前端}

微前端允许多个团队独立开发部署应用，并在一个产品中组合它们。框架提供加载、生命周期、路由和通信；运行隔离主要减少意外污染，不自动构成恶意代码安全边界。

### 四、选择建议（按项目类型） {#四、选择建议-按项目类型}

<span id="五、总结-简短版"></span>


* 独立发布先验证路由归属、公共依赖、加载失败与回滚方案。
* 旧项目集成试验实际构建产物，不推断所有技术栈都无需改造。
* 不可信应用先设计不同源 iframe、sandbox、通信权限与服务端授权，不依赖 Proxy 或同源 iframe 作为安全边界。
* 首屏、切换性能和 SSR 支持按版本与实际设备测量。

## 二、路由 {#二、路由}

主应用负责入口与加载规则；子路由是否独立或同步 URL 取决于模式与配置。刷新、后退、深链接和卸载都需联调。

| 方案 | 路由处理 |
| --- | --- |
| qiankun | activeRule 激活应用，主子路由避免冲突 |
| micro-app | 虚拟路由及同步能力按版本配置 |
| Wujie | iframe history 与主 URL 同步可配置 |
| Module Federation | 宿主与远程模块的集成约定决定路由 |
| iframe | 独立 URL，通过通信同步主页面状态 |

## 三、web components {#三、web-components}

CustomElement 提供自定义标签与生命周期；ShadowDOM 提供 DOM 封装和样式作用域。自定义元素不一定创建 ShadowRoot，ShadowDOM 也不是权限或恶意脚本隔离边界。

## 四、如何样式隔离 {#四、如何样式隔离}

* 作用域前缀重写选择器；验证全局选择器、弹窗和动态样式。
* ShadowDOM 隔离多数选择器；继承属性、CSS 变量和外部弹窗另行处理。
* CSS Modules / BEM 通过约定减少命名冲突，不能防止恶意代码。
* iframe 提供独立文档样式环境；安全仍取决于源、sandbox 与通信授权。

## 五、如何通讯 {#五、如何通讯}

| 方案 | 常用通信 |
| --- | --- |
| qiankun | props 与 initGlobalState |
| micro-app | data、dispatch 与框架 API |
| Wujie | props、window.parent 与 bus |
| Module Federation | 导出的函数、组件或共享模块 |
| iframe | postMessage，验证 origin、source 和数据结构 |

明确协议版本、数据所有权、订阅清理与错误处理；前端身份不能代替服务端鉴权。
