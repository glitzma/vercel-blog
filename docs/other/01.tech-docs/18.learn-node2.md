##  nextTick

Callback ordering depends on where callbacks are scheduled and on event-loop phases, rather than a fixed priority chain. The nextTick queue is processed after the current operation returns; its ordering relative to Promise microtasks also depends on CJS/ESM execution context.

Save the following as a regular CommonJS file to observe ordering within an I/O callback:

```js
const fs = require('node:fs');

fs.readFile(__filename, () => {
  process.nextTick(() => console.log('nextTick'));
  Promise.resolve().then(() => console.log('promise'));
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate'));
});
// 此场景：nextTick → promise → immediate → timeout
```

Do not rely on a fixed order between setTimeout and setImmediate registered in the main module. Interpret timer behavior in the context of the Node version, including the change introduced in Node 20. [Node event loop](https://nodejs.org/learn/asynchronous-work/event-loop-timers-and-nexttick).

## stram

- A stream is an ordered set of byte data transmission means with a starting point and an ending point.
- Don't care about the overall content of the file, only focus on whether the data is read from the file, and the processing after reading the data
- Stream is an abstract interface implemented by many objects in Node.For example, the request object of an HTTP server is a stream, and stdout is also a stream.
- Streams are readable, writable, or both.All streams are instances of EventEmitter."Almost every Node program, no matter how simple, uses streams in some way."

stream.Readable readable stream

- fs.ReadStream reads files
- http.IncomingMessage client request or server response
- net.Socket socket object in tcp connection
- process.stdin standard input stream
- Gzip data compression

- There are two types of readable streams, with internal flowing (flowing) steps and non-flowing (pause) mode to read data.
- flowing mode uses the operating system's internal IO mechanism to read data and provide it to you as quickly as possible
- In non-flowing mode, the stream is in the pause step by default, and the read method must be explicitly called to read data.

> "Attention"
> If no data event handler is bound and there is no pipe() target and the stream is switched to flowing mode, data will be lost.

- Its biggest feature is that after one middleware has processed it, the corresponding data can be passed to the next middleware.

var express = require('express');

## etag

When there is a problem with the last modified time

```
1. 某些服务器不能精确得到文件的最后修改时间，这样就无法通过最后修改时间来判断文件是否更新了
2. 某些文件的修改非常频繁，在秒以后的时间内进行修改，Last-Modified只能精确到秒
3. 一些文件的最后修改时间改变了，但是内容并未改弯。我们不希望客户端认为这个文件修改
4. 如果同样的一个文件位于多个CDN服务器上的时候内容虽一样，修改时间不一样
```

ETag is the abbreviation of entity tag, a string generated based on the entity content, which can identify the status of the resource.When the resource sending changes, the ETag also changes.ETag is generated by the web server and then sent to the browser client.

1. If the client wants to determine whether the cache is available, it can first obtain the ETag of the document in the cache, and then send a request to the web server through If-None-Match to ask whether the cache is available.
2. The server receives the request and compares the ETag of the file in the server with the If-None-Match in the request header. If the values are the same, it means that the cache is still the latest. The web server will send a 304 Not Modified response code to the client to indicate that the cache has not been modified and can be used.
3. If they are different, the web server will send the latest version of the document to the browser client.

## How does the browser not send a request? {#浏览器如何不发请求}

The browser will cache the file into the Cache directory. When making the second request, the browser will first check whether the Cache directory contains the file. If it does, and it has not yet reached the Expires setting time, that is, the file has not expired, then the browser will directly read the file from the Cache directory without sending a request.

- Expires is the server response message header field. When responding to an http request, it tells the browser that the browser can directly fetch data from the browser cache before the expiration time without requesting again.
- Cache-Control has the same function as Expires. They both indicate the validity period of the current resource and control whether the browser directly fetches data from the browser cache or resends the request to the server to fetch data. If both are set at the same time, its priority is higher than Expires.
