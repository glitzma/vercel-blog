# Git manual {#git使用手册}

## Installation {#安装}

Official website download: <https://git-scm.com/downloads> After the download is complete, use the default installation.

After the installation is complete, find `Git` -> `Git Bash` in the start menu. If something similar to a command line window pops up, it means that Git is installed successfully!
The last step of setting is required, enter on the command line:

```bash
git config --global user.name "Your Name"
git config --global user.email "email@example.com"
```

Because Git is a distributed version control system, each machine must report its name: your name and email address.

## Create a repository (warehouse) {#创建版本库-仓库}

```bash
# 创建仓库
mkdir <仓库name> 

# 进入仓库
cd <仓库name>

# 此命令用于显示当前目录
pwd

# 把当前目录初始化成Git仓库
git init
```

> It is not necessary to create a Git repository in an empty directory. You can also choose a directory that already has something in it and directly `git init`.



## Add files to the repository {#添加文件到仓库}

Put the file in the warehouse directory, such as creating a new one `test.txt` file and then use `git add test.txt` The command tells Git to add the file to the cache and then use `git commit -m "提交描述"` Tell Git to commit the file to the repository.

```bash
# 添加指定文件或文件夹到缓存区，文件需添加后缀
git add <文件或文件夹name>                   # 单个文件
git add <文件或文件夹name> <文件或文件夹name>  # 多个文件

# 或 全部文件同时添加到缓存区
git add .

# 把文件从缓存区提交至仓库
git commit -m "提交描述"
```



#### Submit description specifications {#提交描述规范}

Entering clear instructions when submitting code is beneficial to version management. It is recommended to write the submission description with the following keywords

```bash
# 新建(add)
# 删除(rm)
# 更新(update)
# 改动(change)
# 实现
# 发布
# 修复
...
```

For example, after modifying the contents of `test.txt`, run the `git status` command to see the modified files, and then use `git add test.txt`,
`git commit -m "修改描述"` Submit the modified file to the warehouse, and it can be used again after submission. `git status` View current status.

```bash
# 显示 新增/删除/被改动等 的文件
git status
```



#### View version history {#查看版本记录}

```bash

```

> You can also use visualization tools to view Git version history:
> Right-click on the repository directory > `Git BUI Here`



#### Fallback version {#回退版本}

First of all, Git must know which version the current version is. In Git, `HEAD` is used to represent the current version, which is the latest submission 1094adb... (note that my submission ID is definitely different from yours), the previous version is `HEAD^`, and the previous version is `HEAD^^`. Of course, it is easier to write 100^ for the previous 100 versions, so it is written as `HEAD~100`.

```bash
# 回退到上一个版本
$ git reset --hard HEAD^
```

At this time, I checked the `git log` record and found that the original latest version was no longer available. What should I do if I want to go back to the original latest version?This requires knowing the version number of the latest version

``` bash
# 跳转到指定版本
git reset --hard <版本号前几位>
```

But what should I do if I don’t know the version number?Git provides a command `git reflog` to record each of your commands

```bash
git reflog
```

## Remote warehouse {#远程仓库}

#### SSH verification {#ssh验证}

To enable this machine to associate with a remote warehouse, SSH authentication is required for the first time.

* Step 1: Create `SSH Key`.In the user home (C:\Users\dell) directory, check if there is a .ssh directory.
  If so, check to see if there are two files `id_rsa` and `id_rsa.pub` in this directory. If they already exist, you can jump directly to the next step.
  If not, open Shell (open Git Bash under Windows) and create `SSH Key`:

```bash
# 创建SSH Key
ssh-keygen -t rsa -C "邮件地址"
```

* Step 2: Log in to GitHub, go to avatar in the upper right corner > settings > SSH and GPG keys >Add SSH Key, and paste the contents of the `id_rsa.pub` file in the key text box.

  

#### Associated with remote warehouse {#关联远程仓库}

After SSH verification is completed, create a warehouse on github. When creating the warehouse, remember to uncheck `Initialize this repository with a README`, and then run the local command:

```bash
# 关联远程仓库，仓库名一般使用origin
git remote add <仓库名> <远程仓库地址>

# 示例
git remote add origin git@github.com:xugaoyi/test.git
```

In the next step, you can push all the contents of the local library to the remote library

```bash
# 把文件推送到远程仓库
git push -u <仓库名> <分支名>

# 示例
git push -u origin master
```

Since the remote library is empty, when we push the `master` branch for the first time, we add the `-u` parameter. Git will not only push the content of the local `master` branch to the new remote `master` branch, but also associate the local `master` branch with the remote `master` branch, which can simplify the commands when pushing or pulling in the future.

> The premise is that the directory has `git init` initialized into a warehouse, and `git status` The status has not changed. If there is any change, first `git add .` Add to cache, `git commit -m '提交描述'` Submit it to the warehouse and execute the above command.
>
> If you checked `Initialize this repository with a README` when creating the warehouse, you need to first pull the `README.md` file to the local warehouse `git pull`
>
> Multiple remote warehouses can be associated. Be careful to give different remote warehouses different names. Submissions are submitted to different remote warehouses by name.



```bash
# 简化的推送命令
git push
```

## branch management {#分支管理}

#### Create a branch {#创建分支}

```bash
# 创建分支
git checkout -b <分支名>
```



#### View branches {#查看分支}

```bash
# 查看分支
git branch
```

When viewing branches, the * sign in front of the branch indicates the current branch.



#### switch branch {#切换分支}

```bash
# 切换分支
git checkout <分支名>
```



#### merge branches {#合并分支}

```bash
# 合并本地的分支
git merge <分支名>

# 合并远程的分支
git merge <远程仓库名>/<分支名>
```

**Note**, the specified branch is merged into the current branch, not the current branch is merged into the specified branch.

Generally, the current branch is switched to the **main branch**, and then the **sub-branch** is merged into the **main branch**.







#### delete branch {#删除分支}

```bash
# 删除分支
git branch -d <分支名>
```



#### Modify branch name {#修改分支名}

```bash
# 修改分支名
git branch -m <原分支名> <新分支名>
```
