> Summary:

### 1.2 MVP

> Summary:
> 1. The Presenter in MVP is somewhat similar to the controller, but the difference is that when the user performs a DOM modification operation, the behavior on the View triggers modification notifications to the Presenter. After the Model is modified and other Views are updated, the operation binding between the Presenter and the View is usually two-way. Changes in the View will generally trigger the Presenter's action, and the Presenter's action will also change the View.
> 2. View and Model are only used to provide view templates and data without performing any logical processing. Presenter is responsible for logical operations and has clear responsibilities.However, the content of the Presenter layer may become very heavy. In addition, the user's operations on the View will be fed back to the Presenter to modify the Model and update other corresponding parts of the View content.
 
 MVP is the same as MVC. M is Model, V is View, and p represents Presenter. It is somewhat similar to Controller, but the difference is that when the user performs DOM modification operations, he will start through the behavior on View, and then notify the Presenter of the modification to complete the subsequent Model.Modifications and other View updates. In MVC mode, user operations are controlled directly through the Controller. The operation binding between Presenter and View is usually two-way. Changes in View will generally trigger Presenter actions, and Presenter actions will also change View.

### 1.3 MVVM pattern {#_1-3-mvvm-模式}

MVVM can be considered an automated MVP framework, and uses ViewModel instead of Presenter. That is, the calling of data Model and the rendering of template content do not require our active operation, but ViewModel automatically triggers the completion, and any user operations are also driven by changes in ViewModel.

A great benefit of MVVM design is that the work of the Presenter in MVP is divided into multiple small instruction steps, and then bound to the corresponding elements, driven based on the corresponding data changes, automatically managing interactive operations, and also eliminating the need to view the event list in the Presenter. In addition, generally the ViewModel will automatically perform data binding when initialized, and reuse all similar operations in the page, which greatly saves our own code for content rendering and event binding.The code implemented using the MVVM pattern is as follows:

```html
<div id="A" q-on="click: change">
    <input type="text" q-value="text"><span q-html="text"></span>
</div>
```

```javascript
let viewModel = new VM({
    $el: document.getElementById('A'),
    data: {
        text: 'View 渲染完成'
    },
    method: {
        change(){
            this.text = '新的ViewA渲染完成';
        }
    }
})
```

It is much simpler overall. The rendering and data binding of template data can be controlled through special attributes such as q-html or q-click. These special element tag attributes are what we call Directive. Of course, different MVVM frameworks use different Directive prefixes, but the functions are similar.

```html
<form action="#" id="form">
    <label for="text" q-html="label"></label>
    <input type="text" q-value="value" q-model="value" q-mydo="number | getValue">
    <button q-on="click: submit"></button>
</form>
```

```javascript
let viewModel = new VM({
    $el: document.getElementById('form'),
    data: {
        label: '用户名',
        value: '输入初始值',
        number: 0
    },
    method: {
        submit () {
            // doSubmit
        }
    },
    directive: {
        mydo (value) {
            console.log(value);
        }
    },
    filter: {
        getValue () {
            return ++ value;
        }
    }
})
```
 
 In this code, the ViewModel automatically performs data filling, two-way data binding and event binding when it is initialized.Let's take a look at what is done by initializing ViewModel when executing new VM().
 
 First, javaScript will find the element `document.getElementById('form')` and start scanning the element node, and facilitate the attribute node attributes of this element and the attributes in all child nodes. Once it is facilitated to an attribute starting with q- in the name, it is considered to be a Directive defined by the MVVM framework, and the corresponding operation will be performed.For example, when the convenience reaches q-html="label", the label value in the default data object data when the ViewModel is initialized is assigned to the innerHTML of this element; when the traversal reaches `q-on="click:submit"`, the click event is bound to this element, and the event function is named submit; You can also customize the `q-mydo` command to facilitate calling the mydo method in Directive when accessing the node attribute. The input parameter is the return value of the getValue method in data. Here getValue() will automatically add 1 to the input number value and return it. The getValue function is generally called a filter.When the user operates on the View layer, the data of the ViewModel will be automatically changed. Then the ViewModel will detect the data changes, re-traverse the scan node attributes, execute the corresponding Directive, render the HTML view or do event binding.
 
 What you also need to know here is that the tag attributes starting with q- are called instructions, which are agreed by the framework. Different frameworks usually agree differently, for example `ng-、v- 、ms-` , I believe you have seen or even used it.The process of creating ViewModel and performing view rendering and event binding here is very simple. By expanding according to this idea, we can implement a simple MVVM framework by ourselves.Of course, there are far more things in the complete framework than this, such as rich `directive、filter、表达式、ViewModel` It has a complete API and even includes some browser compatibility processing.
 
 `directive、filter` What exactly is it?Let’s take a closer look at the relevant content of the MVVM framework design.
 
 > Directive.Translated into instructions, it is simply a custom execution function, for example: `q-html、q-calss、q-on、q-show、q-attr` etc. Encapsulate some basic reusable operation function APIs of DOM.
 
 > Filter.Also called filter, such as `bool、upperCase、lowerCase` etc. means that the user wants to process the incoming initial data and then hand the processing result to the Directive or the next Filter. For example, when the ViewModel is initialized, a Filter function is passed in that converts the timestamp time into a time format.
 
 > Expression design.Such as if...else, etc., which are similar to ordinary page template expressions on the front end. Their function is also to control the page content to be displayed according to specific conditions.
 
 > ViewModel design.It is the link where the incoming Model data is stored internally. Usually ViewModel also provides some basic operation APIs to facilitate developers to read or modify the data.
 
 > Data change detection, as we mentioned above, MVVM is usually driven by data changes, which requires two-way binding of data.Generally, if you want to change the Model according to changes in the View layer, you need to use some special elements (such as `<input>、<select>、<textarea>` elements) to trigger the modification of the content of the ViewModel object data in JavaScript. This is easier to understand.On the other hand, the ViewModel is modified. How to trigger the automatic update or new rendering of the View.This mechanism that automatically triggers other operations based on changes in data is what we call data change detection. The main methods to implement data change detection include manual trigger binding, dirty data detection, object hijacking, proxy, etc.Let’s analyze it in detail below
 
### 1.3.1 Data change detection example {#_1-3-1-数据变更检测示例}
 
#### Manually trigger binding {#手动触发绑定}

Manually triggering instruction binding is a relatively direct implementation method. The main idea is to define the get() method and set() method on the data object (of course other naming methods can also be used), and when calling, manually initiate the get() or set() function to obtain and modify the data. After the data is changed, the re-rendering function of the View layer in the get() and get() functions will be actively triggered.As mentioned earlier, the common main application of driving ViewModel changes based on the view View `<input>、<select>、<textarea>` In other elements, when the content changes, the operation is triggered to change the data of the ViewModel by listening to the DOM's change, select, keyup and other events.Let’s look at a simple example of two-way data binding

```html
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<title>data-binding-method-set</title>
</head>
<body>
<input q-value="value" type="text" id="input">
<span q-text="value" id="el"></span>
<script >
let elems = [document.getElementById('el'), document.getElementById('input')];
let data = {
    value: 'hello'
};

// 定义Directive
let directive = {
    text: function(text) {
      this.innerHTML = text;
    },
    value: function(value) {
      this.setAttribute('value', value);
    }
};

// 数据绑定监听
if(document.addEventListener){
    elems[1].addEventListener('keyup',function(e) {
        ViewModelSet('value', e.target.value);      
    }, false);
} else {
    elems[1].attachEvent('onkeyup', function(e) {
      ViewModelSet('value', e.target.value);
    }, false);
}

// 事件监听的第三个值,是可选的，默认为false，且只有在部分浏览器中支持，true表明该事件监听器绑定在捕获阶段（和目标阶段），false则表明绑定在冒泡阶段（和目标阶段）。

// 开始扫描节点
scan();

//设置页面2秒后自动改变数据更新视图
setTimeout(function() {
  ViewModelSet('value', 'hello world');
}, 1000)

function scan() {
  // 扫描带指令的节点属性
  for(let elem of elems){
      elem.directive = [];
      for (let attr of elem.attributes) {
          if (attr.nodeName.indexOf('q-') >= 0){
              // 调用属性指令
              directive[attr.nodeName.slice(2)].call(elem, data[attr.nodeValue]);
              elem.directive.push(attr.nodeName.slice(2));
          }
      }
  }
}

// 设置数据改变后扫描节点
function ViewModelSet(key, value) {
  data[key] = value;
  scan();
}
</script>
</body>
</html>
```

By loading and executing this page structure through the browser, changes in the ViewModel will automatically change the content of the input box. Similarly, changes in the input content will also drive changes in the ViewModel data.After we change the iewModel data through the ViewModelSet() method, we need to actively call the scan() method to re-scan the nodes on the HTML page and re-render the HTML structure where needed.

### 1.3.2 Dirty detection mechanism {#_1-3-2-脏检测机制}
 
> Summary:
> Different from manually triggering binding, dirty detection only scans elements that may be modified, which improves the efficiency of scanning view rendering after the ViewModel content changes.
 
Take Angularjs, a typical MVVM framework, as an example. Angularjs updates View layer operations by checking dirty data. However, we do not analyze the mechanism of dirty data detection for a certain framework, because the implementation of mature frameworks considers many comprehensive things and is relatively complicated. What we need is to demonstrate the implementation principle of dirty data detection through concise and clear code.The implementation principle of dirty detection is to detect all elements related to a certain attribute value of the ViewModel object when the attribute value changes, and then compare the data changes. If the data changes, the Directive instruction is called to rescan and render the element.Use this method to implement the above example, the code is as follows
 
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>data-binding-dirty-check</title>
</head>
<body>
<input qg-event="value" qg-bind="value" type="text" id="input">
<span qg-event="text" qg-bind="value" id="el"></span>
<script >
    let elems = [document.getElementById('el'), document.getElementById('input')];
    let data = {
        value: 'hello'
    };

    // 定义Directive
    let directive = {
        text: function(str) {
            this.innerHTML = str;
        },
        value: function(str) {
            this.setAttribute('value', str);
        }
    };

    // 初始化扫描节点

    scan(elems);
    $digest('value');

    /**
     * 输入框数据绑定监听
     */
    if (document.addEventListener) {
        elems[1].addEventListener('keyup', function(e) {
            data.value = e.target.value;
            $digest(e.target.getAttribute('qg-bind'));
        }, false);
    } else {
        elems[1].attachEvent('onkeyup', function(e) {
            data.value = e.target.value;
            $digest(e.target.getAttribute('qg-bind'));
        }, false);
    }

    setTimeout(function() {
        data.value = 'hello world';
        $digest('value');
    }, 2000);

    function scan(elems) {
        // 扫描带指令的节点属性
        for ( let elem of elems){
            elem.directive = [];
        }
    }

    // 可以理解为数据劫持监听
    function $digest(value) {
        let list = document.querySelectorAll('[qg-bind='+ value + ']');
        digest(list);
    }

    // 脏数据循环检测
    function digest(elems) {
        for (let i = 0, len = elems.length; i < len; i ++){
            let elem = elems[i];
            for (let j = 0 ,len1= elem.attributes.length; j < len1; j++){
                let attr = elem.attributes[j];
                if (attr.nodeName.indexOf('qg-event') >= 0){
                    // 调用属性指令
                    let dataKey = elem.getAttribute('qg-bind') || undefined;
                    // 进行脏数据检测,如果数据改变,则重新执行指令,否则跳过
                    if ( elem.directive[attr.nodeValue] !== data[dataKey]){
                        directive[attr.nodeValue].call(elem,data[dataKey]); // 给DOM赋值
                        elem.directive[attr.nodeValue] == data[dataKey];
                    }
                }
            }
        }
    }
</script>
</body>
</html>
```
 
In fact, the method here is similar to the manual binding of scanning nodes. The difference is that dirty detection only scans elements that may be modified, which improves the efficiency of scanning view rendering after the ViewModel content changes.

### 1.3.3 Front-end data object hijacking (Hijacking) {#_1-3-3-前端数据对象劫持-hijacking}
 
 Data hijacking is currently a widely used method.The basic idea is to use `Object.defineProperty ` and `Object.defineProperies` Monitor the properties get() and set() of the ViewModel data object. When there are data reading and assignment operations, scan the element node and run the Directive instruction specifying the corresponding node. In this way, the ViewModel can use the common equal sign assignment.Specific examples are as follows.
 
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>data-binding-hijacking</title>
</head>
<body>
<input q-value="value" type="text" id="input">
<span q-text="value" id="el"></span>
<script >
    let elems = [document.getElementById('el'), document.getElementById('input')];
    let data = {
        value: 'hello'
    };

    // 定义Directive
    let directive = {
        text: function(text) {
            this.innerHTML = text;
        },
        value: function(text) {
            this.setAttribute('value', text);
        }
    };

    // 初始化扫描节点

    let bValue;
    scan(elems);

    // 可以理解为数据劫持监听
    defineGetAndSet(data, 'value');

    /**
     * 输入框数据绑定监听
     */
    if (document.addEventListener) {
        elems[1].addEventListener('keyup', function(e) {
            data.value = e.target.value;
        }, false);
    } else {
        elems[1].attachEvent('onkeyup', function(e) {
            data.value = e.target.value;
        }, false);
    }

    setTimeout(function() {
        data.value = 'hello world';
    }, 2000);

    function scan() {
        // 扫描带指令的节点属性
        for ( let elem of elems) {
            elem.directive = [];
            for ( let attr of elem.attributes) {
                if (attr.nodeName.indexOf('q-') >=0 ){
                    // 调用属性指令
                    directive[attr.nodeName.slice(2)].call(elem, data[attr.nodeValue]);
                    elem.directive.push(attr.nodeName.slice(2));
                }
            }
        }
    }

    // 定义对象属性调协劫持
    function defineGetAndSet(obj,propName){
        Object.defineProperty(obj,propName, {
            get: function () {
                return bValue;
            },
            set: function (newValue) {
                bValue = newValue;
                scan();
            },
            enumerable: true,
            configurable: true
        });
    }
</script>
</body>
</html>
```

It should be noted that defineProperty only supports standard browsers such as Internet Explorer 8 or above and Chrome, and the Internet Explorer 8 browser needs to use es5-shim to provide support.Firefox browser does not support this method. You need to use `__defineGetter__` and `__defineSetter__` instead. In order to let everyone understand the principle, defineProperty is directly used to implement it.

### 1.3.4 ECMAScript 6 Proxy

Proxy can be used to define an object based on an existing object and redefine the methods on the object prototype, including the get() method and set() method. At the same time, we can also compare it with defineProperty to learn by ourselves. Let's take a look at how to use Proxy to detect data changes.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>data-binding-proxy</title>
</head>
<body>
<input q-value="value" type="text" id="input">
<span q-text="value" id="el"></span>
<script >

    'use strict';
    let elems = [document.getElementById('el'), document.getElementById('input')];

    // 定义Directive
    let directive = {
        text: function(text) {
            this.innerHTML = text;
        },
        value: function(text) {
            this.setAttribute('value', text);
        }
    };
    
    // 设置data的访问Proxy
    let data = new Proxy({}, {
        get: function(target, key, receiver) {
          return target.value;
        },
        set: function(target, key, value, receiver) {
          target.value= value;
          scan();
          return target.value;
        }
    });
    
    data['value'] = 'hello';
    scan();
    /**
     * 输入框数据绑定监听
     */
    if (document.addEventListener) {
        elems[1].addEventListener('keyup', function(e) {
            data.value = e.target.value;
        }, false);
    } else {
        elems[1].attachEvent('onkeyup', function(e) {
            data.value = e.target.value;
        }, false);
    }

    setTimeout(function() {
        data.value = 'hello world';
    }, 2000);

    function scan() {
        // 扫描带指令的节点属性
        for ( let elem of elems){
            elem.directive = [];
            for ( let attr of elem.attributes) {
                if (attr.nodeName.indexOf('q-') >= 0 ){
                    // 调用属性指令
                    directive[attr.nodeName.slice(2)].call(elem, data[attr.nodeValue]);
                    elem.directive.push(attr.nodeName.slice(2));
                }
            }
        }
    }
</script>
</body>
</html>
```

## 1.4 Virtual DOM interactive mode {#_1-4-virtual-dom-交互模式}

### 1.4.1 Virtual DOM design concept {#_1-4-1-virtual-dom设计理念}

The front-end interaction mode of MVVM greatly improves the efficiency of programming. Automatic two-way data binding allows us to transfer the core of page logic implementation to the modification operation of the data layer, instead of directly operating the DOM in the page.But in fact, as can be seen from all the above content, although MVVM has changed the logic of front-end development, the final rendering and changes of the data layer to the View layer on the page are still completed through corresponding instructions to perform DOM operations, and usually a change in ViewModel may trigger changes in multiple instructions on the page to operate the DOM, resulting in a large number of page structure layer DOM operations or renderings.Let’s first look at the following application scenario

```html

    <li q-repeat="list">
        <span q-text="value"></span>
        <span>固定文本</span>
    </li>
</ul>
```

```javascript

    $el: document.getElementById('root'),
    data: {
        list: [{value: 1}, {value: 2}, {value: 3}]
    }

```

When using the MVVM framework, a list of numbers is generated. At this time, if the content to be displayed becomes `[{value:0},{value:1},{value:2},{value:3}]`, the entire list will generally be re-rendered in the MVVM framework, including the parts of the list that do not need to be changed.But in fact, if you directly change the DOM, you only need to insert a new `<li>` element before the `<ul>` child element.But in the general MVVM framework, we usually don't do this.There is no doubt that in this case, the View layer update mode of MVVM consumes more unnecessary performance.

So how to improve the ViewModel so that the browser knows that only one element has been added?By comparing the two arrays, we found that there is only one `{value:0}`, so how to reflect this data to the View layer?We can think of it this way, comparing the new Model data with the old Model data, and then recording the mode and position of the ViewModel, we will know how the View layer should be updated this time, which is much more efficient than re-rendering the entire list directly.

It can actually be understood here that the data in the ViewModel is another data structure identifier that describes the content of the page View, but it needs to be compiled with a specific MVVM description syntax to generate a complete DOM structure.According to the differentially described objects, the changed DOM structure can be created on the spot to complete the modification of the HTML DOM structure instead of directly re-rendering the entire updated table.

Virtual DOM is a JavaScript object that can directly describe a piece of HTML DOM. The browser can create a unique HTML DOM based on its structure and certain rules.Overall, Virtual DOM's interactive mode reduces the number of DOM scans or operations in MVVM or other frameworks, and only minimizes page DOM operations based on JavaScript objects in appropriate places after data changes, avoiding a large number of re-renderings.

## 1.5 MNV* mode {#_1-5-mnv-模式}

If Virtul DOM reduces the number of DOM interactions, then `MNV*` One thing I want to do is to completely abandon the use of DOM, but the operation of interactive data can still be used `ViewModel、Virtual DOM` Or implement it directly with Model.This mode is currently only applicable to mobile Hybrid applications, because it requires native application control call support, and only this special application scenario meets the conditions.

We know javaScriptYou can use the general protocol to call the native application method, and then encapsulate the Model and Directive into the protocol string `jsbridge://DOMRender:success/createView?{"text":"hello","element":"TextView"}` according to the standard JSBridge protocol, through Prompt (android), IOS uses iframe to send to the client. What is called here is to parse the creatView method of DOMRender to create a TextView. TextView is a base class of a built-in text control on the native Android system. It is similar to the `<p>` tag of HTML and can be used to create a text field on the mobile terminal to display a piece of text.At this time, the client will parse this protocol string and call the native application to dynamically create the interface content fragment of the text space TextView (similar to the HTML document fragment documentFragment or an XML fragment). Here, the control content description of the TextView in Android passes the XML specification.

On the whole, it is not difficult to design and implement a Native rendering mechanism idea, but it is more difficult to implement the encapsulation of JavaScript side and Native side.The main task of the MNV* framework is to parse the Model, ViewModel or Virtual DOM to form the JSBridge protocol serial connection. The implementation of the Native side will be more complicated and must handle the parsing of different tag elements. For example, when encountering the `<TextView>` tag, a TextView space will be created. When the `<Layout>` tag is encountered, a Layout space will be created. It may also need to handle event binding, etc., that is, JavaScript events will be implemented through Native events.On the whole, it is like using the native method of the mobile terminal to parse the functions that need to be implemented in HTML.

`MNV* ` The basic principle is to combine the JSBridge and DOM transformation methods, so that the front end can quickly build and develop applications with native interfaces, thereby breaking away from the DOM interaction mode.Current MNV *The development model is also at the extreme of promotion and application, and I believe it will become more popular in the future.

```
- 在接收到用户输入的网址后，浏览器会开启一个线程来处理这个请求，对用户输入的URL地址进行分析判断，如果是HTTP协议就按照HTTP方式来处理。
```
