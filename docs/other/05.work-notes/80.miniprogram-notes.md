## 1\. Early preparation stage (easy to underestimate, but very critical) {#一、前期准备阶段-容易被低估-但很关键}

### 1️⃣ Mini Program Account & Qualifications {#_1️⃣-小程序账号-资质}

**Key Node**

* Register a WeChat public platform mini program account
* Subject type: individual/enterprise/government/other organization
* Do you need **category qualifications** (e-commerce, medical, education, content, etc.)

**Notes**

* ❗ **The category determines whether you can go online**, it is not something you can make up later.
* Many personal subject restrictions (payment, some APIs, promotion)
* Business entity:

  * WeChat Pay
  * Subscribe to news
  * Live broadcast/advertisement
* The name can only be changed twice a year (be careful)


### 2️⃣ Technology selection (determines your future development experience) {#_2️⃣-技术选型-决定你未来的开发体验}

**Common solutions**

| Type | Solution | Applicable scenarios |
| -- | ---------- | -------------- |
| Native | Native applet | Lightweight, performance first |
| Framework | Taro | React / Vue cross-end |
| Framework | uni-app | Vue system |
| Framework | mpvue (deprecated) | ❌ Not recommended |

**Notes**

* Native ≠ slow, but **high maintenance cost**
* Cross-end framework:

  * Debugging is complex
  * There are pitfalls in API differences
* ❗**Don’t sacrifice the mini program experience for “cross-terminal”**


## 2\. Project initialization stage {#二、项目初始化阶段}

### 3️⃣ Create project {#_3️⃣-创建项目}

**Key Node**

* WeChat Developer Tools
* Bind AppID
* Choose whether to enable cloud development

**Notes**

* Cloud development is suitable for:

  * Quick MVP
  * small team
* Cloud development is not suitable for:

  * High concurrency
  * Strong business logic
  * private deployment


### 4️⃣ Directory structure design (very important) {#_4️⃣-目录结构设计-非常重要}

**Suggested Structure**

```
/pages
  /home
  /detail
/components
  /NavBar
  /List
/services
  api.js
/store
  index.js
/utils
  request.js
  auth.js
```

**Notes**

* ❌ Don’t write all your business in the page
* Componentization = performance + maintainability
* Plan "public components/business components" in advance


## 3\. Core development stage (key points) {#三、核心开发阶段-重点}

### 5️⃣ Page & Route Design {#_5️⃣-页面-路由设计}

**Key Node**

* `app.json`
* The page path is fixed and cannot be dynamically registered.

**Notes**

* Once the page path is online, **do not change it casually**
* Page count > 100 will have performance and maintenance issues
* tabBar page = resident memory (caution)


### 6️⃣ Data communication & network requests {#_6️⃣-数据通信-网络请求}

**Key Node**

* `wx.request`
* backend interface
* Login state maintenance

**Notes**

* ❗ WeChat request **Skip browser cookies**
* Login process:

```
wx.login → code → 后端换 openid / session_key
```

* Be sure to do:

  * Token expiration processing
  * Idempotent processing
* Request concurrency limit (default 10)


### 7️⃣ Status management {#_7️⃣-状态管理}

**Common solutions**

* Page data
* GlobalApp.globalData
* MobX/Redux (rare)
* Encapsulate the store yourself

**Notes**

* Mini program setData is a **performance bottleneck**
* ❌ Large objects frequently setData
* Suggestions:

  * Page local state
  * Only necessary information (user/token) is stored globally


### 8️⃣ Life cycle & page stack {#_8️⃣-生命周期-页面栈}

**Key Node**

* App life cycle
* Page life cycle
* Page stack maximum 10 levels

**Notes**

* `onShow` ≠ page reload
* `onHide` is not destroyed
* Page return may not trigger `onLoad`
* ❗Memory leak: timer/listener not cleaned


## 4\. Performance & experience optimization (must be done before going online) {#四、性能-体验优化-上线前必做}

### 9️⃣ Key points in performance optimization {#_9️⃣-性能优化关键点}

**Key Directions**

* setData frequency
* Image loading
* Packet volume

**Notes**

* Main package ≤ 2MB
* Subpackage loading (very important)
* Picture:

  * webp
  * CDN
* List:

  * virtual list
  * Throttle/anti-shake


### 🔟 Permissions & Authorization (very easy to be rejected) {#🔟-权限-授权-非常容易被拒审}

**Key Node**

* User authorization (avatar, mobile phone number, location)

**Notes**

* ❌ You cannot ask for authorization as soon as you come in.
* You must "request it when you need it"
* There must be an authorization pop-up window **clear statement of purpose**
* The mobile phone number must be in WeChat official capacity


## 5\. Security & Compliance (the review is now very strict) {#五、安全-合规-现在审核非常严}

### 1️⃣1️⃣ Safe {#_1️⃣1️⃣-安全}

**Key Points**

* https
* Interface signature
* Anti-brush

**Notes**

* ❌ Don’t write the secret in the front end
* Don’t trust any parameters passed by the front end
* Payment must be made through the server


### 1️⃣2️⃣ Compliance {#_1️⃣2️⃣-合规}

**Key Points**

* privacy policy
* User data description

**Notes**

* Must have:

  * Privacy Policy Page
  * Data usage description
* Used:

  * Positioning
  * Mobile phone number
  * photo album
    → All should be reflected in the privacy agreement


## 6\. Testing & Release Phase {#六、测试-发布阶段}

### 1️⃣3️⃣ Test {#_1️⃣3️⃣-测试}

**Key Node**

* Real machine test (low-end machine)
* Different WeChat versions
* Network abnormality

**Notes**

* Simulator ≠ real machine
* iOS / Android behave differently
* Abnormal networks must be revealed


### 1️⃣4️⃣ Submit for review & publish {#_1️⃣4️⃣-提交审核-发布}

**Key Node**

* Trial version
* Audit version
* Officially released

**Notes**

* Audit failures are common, don’t panic
* Common reasons for rejection:

  * induced authorization
  * Category does not match
  * Function description is unclear
* The description should **clearly describe the core functions**


## 7\. Long-term precautions after going online {#七、上线后的长期注意事项}

### 1️⃣5️⃣ Operation & Maintenance {#_1️⃣5️⃣-运营-维护}

**Key Points**

* Data burying point
* Abnormal monitoring
* Version rollback

**Notes**

* Mini program ≠ one-time project
* User path is very short
* First screen experience > All features
