## 1\. Let’s talk about the conclusion first (how to learn with the least pain) {#一、先说结论-怎么学最不痛苦}

> - **The order must be: Docker → Kubernetes (K8s)**
> - Docker is "how to put programs into boxes"
> - K8s is "how to manage a bunch of boxes"

Without Docker, K8s is basically incomprehensible.


## 2\. Docker Tutorial (Getting Started → Practical Combat) {#二、docker-教程-入门-→-实战}

### 1️⃣ What is Docker (one sentence version) {#_1️⃣-docker-是啥-一句话版}

* Package the program + running environment into an **Image**
* It runs as **Container**
* No longer afraid of "it can run on my computer"


### 2️⃣ Docker must learn core concepts (interview & practical) {#_2️⃣-docker-必学核心概念-面试-实战}

| Concept | One sentence |
| ---------- | ---------------- |
| Image | The "installation package" of the program |
| Container | Running Image |
| Dockerfile | How to build Image |
| Volume | Data persistence |
| Network | Communication between containers |
| Registry | Mirror Warehouse (Docker Hub) |


### 3️⃣ Getting started with Docker (must type by yourself) {#_3️⃣-docker-入门实操-必须自己敲}

```bash
# 1. 拉镜像
docker pull nginx

# 2. 运行容器
docker run -d -p 8080:80 nginx

# 3. 看运行状态
docker ps

# 4. 停止容器
docker stop <container_id>
```

Browser access 👉 `http://localhost:8080`


### 4️⃣ Dockerfile (Key Points‼️) {#_4️⃣-dockerfile-重点-️}

**Minimal usable example (Python)**

```dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]
```

Build & Run:

```bash
docker build -t myapp .
docker run -p 5000:5000 myapp
```

👉 **This step is a watershed for Docker**


### 5️⃣ Docker advanced (learn this and you can already work) {#_5️⃣-docker-进阶-学到这已经能干活}

* Multiple containers: `docker-compose`
* Data persistence: `volume / bind mount`
* Image optimization: multi-stage build
* Common pitfalls:

  * The port is not exposed
  * The container exits as soon as it starts
  * Image is too large (>1GB)


## 3\. Kubernetes (K8s) Tutorial (Key Points🔥) {#三、kubernetes-k8s-教程-重点🔥}

### 1️⃣ What is K8s used for? {#_1️⃣-k8s-是干嘛的}

In one sentence:

> **Automatic deployment, expansion and contraction, restart, and load balancing of Docker containers**

When you have:

* multiple servers
* multiple services
* High availability requirements
  👉 K8s only makes sense


### 2️⃣ K8s core concepts (must memorize) {#_2️⃣-k8s-核心概念-一定要背}

| Concept | Human explanation |
| ---------- | -------------- |
| Pod | Minimum deployment unit (1 ~ multiple containers) |
| Node | A machine |
| Cluster | A bunch of Node |
| Deployment | Manage Pods (replicas, upgrades) |
| Service | Give Pod a stable entrance |
| ConfigMap | Configuration |
| Secret | Password |
| Ingress | HTTP entry |


### 3️⃣ Local learning environment (recommended) {#_3️⃣-本地学习环境-推荐}

✅ **First choice for newbies:**

* `minikube` or `kind`

```bash
brew install minikube
minikube start
```


### 4️⃣ The first K8s application (very important) {#_4️⃣-第一个-k8s-应用-超重要}

**deployment.yaml**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 2
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: myapp
        image: nginx
        ports:
        - containerPort: 80
```

```bash
kubectl apply -f deployment.yaml
kubectl get pods
```


### 5️⃣ Service (allowing external access) {#_5️⃣-service-让外部能访问}

```yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  type: NodePort
  selector:
    app: myapp
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30007
```


### 6️⃣ K8s capabilities you really need to master {#_6️⃣-你真正需要掌握的-k8s-能力}

* Why does the Pod hang?(`kubectl describe pod`)
* What do you think of the log?(`kubectl logs`)
* rolling update
* HPA automatic expansion
* Health check (liveness/readiness)
* Configuration and key management


## 4\. Docker + K8s learning route (follow it) {#四、docker-k8s-学习路线-照着走}

### 🟢 Phase 1 (3–5 days) {#🟢-第一阶段-3–5-天}

* Docker basic commands
* Dockerfile
* Run your own web service

### 🟡Phase 2 (5–7 days) {#🟡-第二阶段-5–7-天}

* K8s basic concepts
* Deployment + Service

### 🔵 The third stage (advanced) {#🔵-第三阶段-进阶}

* Helm
* CI/CD（GitHub Actions）
* K8s on the cloud (EKS / GKE / ACK)
