## 1\. Project goals (preliminarily set design principles) {#一、工程目标-先定设计原则}

The goals of this set of templates are:

* ✅ **Thin pages and centralized logic**
* ✅ **Testable and scalable**
* ✅ **Avoid setData performance pit**
* ✅ **Comply with WeChat review & specifications**
* ✅ **Does not rely on heavy frameworks (native + light packaging)**

> Suitable for: native applet / Taro / uni-app, all thinking can be applied

## 3\. Page “slimming” mode (very important) {#三、页面-瘦身-模式-非常重要}

#### ❌ Wrong approach {#❌-错误做法}

```js
Page({
  data: {},
  onLoad() {
    wx.request(...)
  },
  onTap() {
    // 一堆业务逻辑
  }
})
```

#### ✅ Correct approach: Page + Logic separation {#✅-正确做法-page-logic-分离}

##### `pages/home/index.js`

```js
import logic from './index.logic'

Page({
  ...logic
})
```

##### `pages/home/index.logic.js`

```js
import { getHomeData } from '../../services/home.api'

export default {
  data: {
    list: []
  },

  async onLoad() {
    const data = await getHomeData()
    this.setData({ list: data })
  },

  onItemTap(e) {
    const id = e.currentTarget.dataset.id
    wx.navigateTo({ url: `/pages/detail/index?id=${id}` })
  }
}
```

👉 Benefits:

* The page is just a "shell"
* Logic is testable
* Can be migrated to Taro / React later


## 4\. Request layer design (the most critical) {#四、请求层设计-最关键}

### 1️⃣ request package {#_1️⃣-request-封装}

#### `services/request.js`

```js
import { getToken } from './auth'

const BASE_URL = 'https://api.xxx.com'

export function request(options) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: {
        Authorization: getToken()
      },
      success(res) {
        if (res.statusCode === 200) {
          resolve(res.data)
        } else {
          reject(res)
        }
      },
      fail(err) {
        reject(err)
      }
    })
  })
}
```


### 2️⃣ API sub-module {#_2️⃣-api-分模块}

#### `services/user.api.js`

```js
import { request } from './request'

export function getUserInfo() {
  return request({
    url: '/user/info'
  })
}
```

👉 It is forbidden to write `wx.request` in Page


## 5\. Global state management (lightweight) {#五、全局状态管理-轻量}

#### `store/index.js`

```js
const store = {
  user: null,
  setUser(user) {
    this.user = user
  }
}

export default store
```

#### Use {#使用}

```js
import store from '../../store'

store.setUser(res)
```

👉 Mini programs are not suitable for Redux-heavy solutions
👉 **"If you can't use the global system, don't use it"**


## 6\. setData performance specifications (must be written into team specifications) {#六、setdata-性能规范-必须写进团队规范}

#### ❌ Prohibited {#❌-禁止}

```js
this.setData({ bigList })
this.setData({ count })
```

#### ✅ Recommended {#✅-推荐}

```js
this.setData({
  'bigList[3].title': 'xxx'
})
```

#### Agreement {#约定}

* setData ≤ **1 times/event**
* Large object split fields
* List loading in pages


## 7\. Component design specifications {#七、组件设计规范}

#### Component structure {#组件结构}

```
ProductCard/
├─ index.js
├─ index.wxml
├─ index.wxss
└─ index.json
```

#### Component communication {#组件通信}

* parent → child: properties
* child → parent: triggerEvent
* ❌ Do not directly operate the parent data


## 8\. Configuration & Environment Isolation {#八、配置-环境隔离}

#### `config/env.js`

```js
export const ENV = 'prod'
```

#### `config/api.config.js`

```js
export const API_HOST = {
  dev: 'https://dev.api.com',
  prod: 'https://api.com'
}
```


## 9\. Subcontracting design (must be done before going online) {#九、分包设计-上线前必做}

```json
{
  "subpackages": [
    {
      "root": "subpackages/profile",
      "pages": ["index"]
    }
  ]
}
```

👉 Main package ≤ 2MB
👉 Full advance subcontracting of non-first-screen pages

- ✅ Page + logic separation
- ✅ API layer concentration
- ✅ Business code is prohibited from entering Page
- ✅ Subcontracting
- ✅ setData specification
- ✅ Delay in permission application
