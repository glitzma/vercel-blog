## 1\. Same-Origin Policy ⭐⭐⭐⭐⭐ {#一、同源策略-same-origin-policy-⭐⭐⭐⭐⭐}

### 1️⃣ What is "Origin" {#_1️⃣-什么是-源-origin}

- **Protocol + Domain Name + Port** The three are exactly the same

```text
https://example.com:443
```

As long as there is one difference, it is **different source**

| URL | Whether it has the same origin |
| ---------------------------------------------------- | ----- |
| [https://example.com/a](https://example.com/a)       | ✅     |
| [http://example.com](http://example.com) | ❌(agreement) |
| [https://sub.example.com](https://sub.example.com) | ❌(domain name) |
| [https://example.com:8080](https://example.com:8080) | ❌(port) |


### 2️⃣What are the limitations of the same-origin policy? {#_2️⃣-同源策略限制了什么}

#### ❌ Restricted (emphasis) {#❌-被限制的-重点}

1️⃣ **DOM access**

```js
iframe.contentWindow.document // 不同源直接报错
```

2️⃣ **Cookie / LocalStorage / IndexedDB**

* Can't read
* Can't write

3️⃣ **AJAX read response**

```js
fetch('https://api.com') // 请求发得出，结果读不到
```

⚠️ Note: **The request itself can be sent!**


#### ✅ Unlimited {#✅-不受限制的}

| Behavior | Description |
| -------------- | -------- |
| `<img src>` | Common tips |
| `<script src>` | JSONP basics |
| `<link>`       | CSS      |
| `<iframe>` | Just can't access the content |


### 3️⃣ Why do we need a same-origin policy? {#_3️⃣-为什么要有同源策略}

In one sentence:

- **Prevent malicious websites from reading your private data on other websites**

If there is no same-origin policy:

* Website A can directly read the cookies of website B
* The bank/mailbox is directly dragged to the database


### 4️⃣ One sentence version that must be tested in interviews {#_4️⃣-面试必考一句话版}

- The same-origin policy is a browser security mechanism used to restrict resource access between different sources and prevent malicious websites from stealing user data.


## 2\. CORS (Cross-Origin Resource Sharing) ⭐⭐⭐⭐⭐ {#二、cors-跨域资源共享-⭐⭐⭐⭐⭐}

- **CORS is "the back-end actively opens the door" to allow the front-end to cross domains**

It’s not front-end technology, it’s **browser + server negotiation rules**


### 1️⃣ Why do you need CORS? {#_1️⃣-为什么需要-cors}

Because:

* Same Origin Policy **Restricted Reading**
* But modern front-ends must call APIs across domains


### 2️⃣ Simple request vs preflight request (Ultra High Frequency) {#_2️⃣-简单请求-vs-预检请求-超高频}

#### ✅ Simple request (will not trigger preflight) {#✅-简单请求-不会触发预检}

Meet **all conditions**:

* Method: `GET / POST / HEAD`
* Content-Type：

  * `text/plain`
  * `application/x-www-form-urlencoded`
  * `multipart/form-data`
* no custom header

```js
fetch('https://api.com/data')
```


#### 🚨 Non-simple request → Preflight (OPTIONS) {#🚨-非简单请求-→-预检-options}

```js
fetch('https://api.com/data', {
  method: 'PUT',
  headers: {
    'X-Token': 'xxx'
  }
})
```

Browser first:

```http
OPTIONS /data
Origin: https://web.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: X-Token
```

Server response:

```http
Access-Control-Allow-Origin: https://web.com
Access-Control-Allow-Methods: PUT
Access-Control-Allow-Headers: X-Token
```

Only after passing the request will the actual request be made.


### 3️⃣ CORS common response headers (must be memorized) {#_3️⃣-cors-常见响应头-必须背}

```http
Access-Control-Allow-Origin: https://web.com
Access-Control-Allow-Credentials: true
Access-Control-Allow-Headers: Content-Type, X-Token
Access-Control-Allow-Methods: GET, POST
```

#### ⚠️ Deadly combination {#⚠️-致命组合}

```http
Allow-Origin: *
Allow-Credentials: true ❌
```

The browser directly rejects


### 4️⃣Cookie cross-domain correct posture {#_4️⃣-cookie-跨域的正确姿势}

#### front end {#前端}

```js
fetch(url, {
  credentials: 'include'
})
```

#### backend {#后端}

```http
Access-Control-Allow-Credentials: true
Access-Control-Allow-Origin: https://web.com
Set-Cookie: sid=xxx; SameSite=None; Secure
```


### 5️⃣ CORS interview high-frequency pitfalls {#_5️⃣-cors-面试高频坑}

❓ **Why am I getting an error even though I have allowed cross-domain?**

👉 Common reasons:

* Preflight request not processed OPTIONS
* Forgot to return Allow-Headers
* Used `*` + credentials
* The actual response does not have a CORS header (it is only included in OPTIONS)


## 3\. CSP (Content Security Policy) ⭐⭐⭐⭐⭐ {#三、csp-内容安全策略-⭐⭐⭐⭐⭐}

- **CSP is the ultimate weapon to prevent XSS**


### 1️⃣ What is CSP doing? {#_1️⃣-csp-在干什么}

In one sentence:

- **Restrict the resource sources that can be loaded/executed on the page**


### 2️⃣ Basic writing method {#_2️⃣-基本写法}

```http
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  img-src 'self' https:;
```

Meaning:

* All resources are only allowed to yourself by default
* JS can only come from yourself
* Image allowed https


### 3️⃣ What can CSP protect against? {#_3️⃣-csp-能防什么}

| Risk | CSP protection and limits |
| ------- | ---- |
| XSS | Can restrict injection; still requires encoding and sanitization |
| eval injection | Restricts string execution unless unsafe-eval is allowed |
| Compromised third-party scripts | Restricts sources but may allow malicious code from an allowed source |
| CSRF | Does not replace server-side CSRF protection |


### 4️⃣ Key instructions of CSP (must know) {#_4️⃣-csp-的关键指令-必会}

#### script-src {#script-src}

```http
script-src 'self' 'nonce-abc123'
```

```html
<script nonce="abc123">合法脚本</script>
```


#### Disable risky behavior {#禁用危险行为}

```http
script-src 'self';
object-src 'none';
base-uri 'none';
```


### 5️⃣ CSP Report (must be used for production) {#_5️⃣-csp-report-生产必用}

```http
Content-Security-Policy-Report-Only:
  default-src 'self';
  report-uri /csp-report
```

👉 **Only report without interception to prevent accidental killing**


### 6️⃣ Framework + CSP practical notes {#_6️⃣-框架-csp-实战注意}

#### Vue / React {#vue-react}

* Disable `eval` (affects devtool)
* `inline script` requires nonce
* Dynamically inserting scripts must cooperate with nonce


## 4\. A picture of the relationship between the three (the most points for the interview) {#四、三者关系一张图-面试最加分}

```
同源策略：默认全禁
     ↓
CORS：服务器放行“读”
     ↓
CSP：限制“能执行什么”
```


## 5\. Final summary {#五、终极总结}

- The same-origin policy is the basic security mechanism of browsers, restricting access to resources between different sources;
- CORS means that the server declares which cross-domain requests can be read by the browser through response headers;
- CSP limits page executable resources through a whitelist mechanism to defend against injection attacks such as XSS.
