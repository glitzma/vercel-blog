# 1\. What is Layout Thrashing (one sentence version) {#一、什么是-layout-thrashing-一句话版}

> **In a JS execution, repeatedly alternate "write style → read layout",
> Forcing the browser to continuously synchronize the calculation of layout, resulting in a sharp decline in performance.**

Keywords:

* ❌ Repeat Layout
* ❌ Synchronous blocking
* ❌ FPS plummets


# 2\. The most typical Layout Thrashing code {#二、最典型的-layout-thrashing-代码}

```js
for (let i = 0; i < 1000; i++) {
  el.style.width = el.offsetWidth + 1 + 'px'
}
```

### It seems harmless, but what actually happened? {#看似无害-实际上发生了什么}

```
写 width → 布局脏了
读 offsetWidth → 强制 Layout
写 width → 布局脏了
读 offsetWidth → 强制 Layout
……
```

👉 **Repeated reads/writes can force Layout; the count depends on invalidation and browser optimization.**


# 3\. Why is this happening?(Underlying principles of browser) {#三、为什么会这样-浏览器底层原理}

### 1️⃣ Browser’s “lazy layout strategy” {#_1️⃣-浏览器的-惰性布局策略}

The browser will not re-layout every time the style is changed:

* Modify style → **mark dirty**
* until:

  * to render
  * Or **JS reads layout information**

### 2️⃣ Which operations will "force synchronization of Layout"? {#_2️⃣-哪些操作会-强制同步-layout}

#### 📏 Read geometric information (must memorize) {#📏-读取几何信息-必背}

```js
offsetWidth / offsetHeight
offsetTop / offsetLeft
clientWidth / clientHeight
scrollTop / scrollHeight
getComputedStyle()
getBoundingClientRect()
```

Read these:

> **The browser must figure out the real layout immediately**


# 4\. DevTools in practice: See Layout Thrashing with your own eyes {#四、devtools-实战-亲眼看-layout-thrashing}

### 1️⃣ Use this Demo {#_1️⃣-用这个-demo}

```html
<button id="btn">Run</button>
<div id="box" style="width:100px;height:100px;background:red"></div>

<script>
  const box = document.getElementById('box')
  btn.onclick = () => {
    for (let i = 0; i < 300; i++) {
      box.style.width = box.offsetWidth + 1 + 'px'
    }
  }
</script>
```


### 2️⃣Performance panel analysis {#_2️⃣-performance-面板分析}

You will see:

```
Task
 ├── Function Call
 │    ├── offsetWidth
 │    ├── Layout
 │    ├── offsetWidth
 │    ├── Layout
 │    ├── ...
```

📌 **Yellow JS + Purple Layout appear alternately**

👉 This is the ironclad proof of Layout Thrashing


# 5\. How to solve it?(Engineering level solution) {#五、如何解决-工程级方案}

## ✅ Solution 1: Separation of reading and writing (the most important) {#✅-方案一-读写分离-最重要}

```js
let width = box.offsetWidth

for (let i = 0; i < 300; i++) {
  width += 1
}

box.style.width = width + 'px'
```

👉 **Separating reads/writes reduces repeated layout without guaranteeing exactly one Layout.**


## ✅ Solution 2: Batch writing (DOM batch processing) {#✅-方案二-批量写入-dom-批处理}

```js
box.style.cssText += 'width:200px;height:200px'
```


## ✅ Option 3: Use transform instead of layout attributes {#✅-方案三-使用-transform-替代布局属性}

```js
// ❌
box.style.left = '200px'

// ✅
box.style.transform = 'translateX(200px)'
```

✔️ Transforms can reduce Layout/Paint with reusable layers; verify actual behavior.


## ✅ Solution 4: requestAnimationFrame scheduling {#✅-方案四-requestanimationframe-调度}

```js
let width = box.offsetWidth

function step() {
  width += 1
  box.style.width = width + 'px'
  requestAnimationFrame(step)
}

step()
```

📌 **Spread multiple modifications to multiple frames**


## ✅ Solution 5: Virtual DOM/batch update {#✅-方案五-虚拟-dom-批量更新}

This is one of the reasons why **React/Vue** is fast:

```
多次 setState
   ↓
合并
   ↓
一次真实 DOM 更新
```


# 6\. Advanced: How does the browser "account"? {#六、进阶-浏览器是怎么-记账-的}

Browser internal maintenance:

* **Style dirty**
* **Layout dirty**
* **Paint dirty**

Only if necessary:

* Style Recalc
* Layout
* Paint

👉 **JS read layout = forced clearing**


# 7\. High-frequency interview questions {#七、面试高频问法}

### Q: What is Layout Thrashing? {#q-什么是-layout-thrashing}

> During JS execution, layout information and styles are frequently read and modified alternately.
> As a result, the browser is forced to execute Layout multiple times synchronously, seriously affecting performance.

### Q: How to avoid it? {#q-如何避免}

* Read and write separation
* Merge DOM operations
* Use transform
* Using rAF (requestAnimationFrame)
* Using the framework’s batch update mechanism
