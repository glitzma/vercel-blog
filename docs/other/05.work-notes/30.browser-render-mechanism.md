## 1\. The overall architecture of the browser (macro cognition) {#一、浏览器整体架构-宏观认知}

Modern browsers (take **Chrome/Chromium** as an example) are **multi-process architecture**:

```
浏览器主进程
 ├── 网络进程
 ├── GPU 进程
 ├── 渲染进程（每个 Tab / iframe）
 │     ├── JS 引擎（V8）
 │     ├── 渲染引擎（Blink）
 │     ├── 事件循环
 │     └── Web API
 └── 插件进程
```

### Why multiple processes? {#为什么要多进程}

- ✅ **SAFE** (Sandbox Isolation)
- ✅ **Stable** (the crash of one page does not affect the others)
- ✅ **Performance** (parallel execution)


## 2\. From input URL to page display (complete link) {#二、从输入-url-到页面显示-完整链路}

This is the main line of **must be tested in interviews**.

### 1️⃣ URL parsing {#_1️⃣-url-解析}

* Completion Agreement
* Determine whether it is a search or a URL
* DNS resolution → IP

### 2️⃣ Network request (Network) {#_2️⃣-网络请求-network}

* TCP three-way handshake
* HTTPS: TLS handshake
* HTTP request/response
* Cache strategy (strong cache / negotiate cache)

### 3️⃣ Build DOM & CSSOM (rendering preconditions) {#_3️⃣-构建-dom-cssom-渲染前置条件}

```
HTML ──> DOM Tree
CSS  ──> CSSOM Tree
```

- ⚠️ **CSS blocks rendering**
- ⚠️ **JS will block DOM parsing**


## 3\. Key: Browser rendering pipeline (core) {#三、关键-浏览器渲染流水线-核心}

### 🌈 Five stages of browser rendering {#🌈-浏览器渲染五大阶段}

```
DOM + CSSOM
   ↓
Render Tree
   ↓
Layout（回流 / 重排）
   ↓
Paint（重绘）
   ↓
Composite（合成）
```

Let’s break it down one by one.


## 4\. Render Tree {#四、render-tree-渲染树}

**Rendering tree ≠ DOM tree**

Features:

* Contains only **visible nodes**
* `display: none` ❌
* `visibility: hidden` ✅ (placeholder)

```
DOM + CSSOM → Render Tree
```


## 5\. Layout (reflow/rearrangement) {#五、layout-回流-重排}

👉 **Calculate geometric information of elements**

* location
* width and height
* box model

### Operations that trigger reflow (⚠️ performance killer) {#触发回流的操作-⚠️-性能杀手}

* Change:

  * width / height
  * padding / margin
  * position / display
* Read:

  * `offsetTop`
  * `clientHeight`
  * `getBoundingClientRect()`

📌 **Reflow will definitely cause redraw**


## 6\. Paint (redraw) {#六、paint-重绘}

👉 Draw pixels to bitmap

Trigger redraw but not reflow:

* color
* background
* box-shadow
* outline

📌 **Redrawing does not necessarily mean reflow**


## 7\. Composite (synthesis/GPU acceleration) {#七、composite-合成-gpu-加速}

👉 Multiple layers are handed over to the GPU for compositing

### Can trigger the composition layer (key point) {#能触发合成层-重点}

* `transform`
* `opacity`
* `will-change`
* `position: fixed`
* `video / canvas`

✨ **Only use Composite, the best performance**


## 8\. The relationship between JS and rendering (event loop) {#八、js-与渲染的关系-事件循环}

### JS is single-threaded {#js-是单线程的}

* JS execution time
* Rendering will be blocked

### Event Loop simplified model {#event-loop-简化模型}

```
宏任务（script / setTimeout）
   ↓
微任务（Promise / MutationObserver）
   ↓
渲染（layout / paint）
```

📌 **Microtasks will not be rendered until they are cleared**


## 9\. Browser Optimization Strategy (Engineering Practice) {#九、浏览器优化策略-工程实践}

### 1️⃣ Reduce backflow {#_1️⃣-减少回流}

```js
// ❌ 多次回流
el.style.width = '100px'
el.style.height = '100px'

// ✅ 合并
el.style.cssText = 'width:100px;height:100px'
```

### 2️⃣ Separation of reading and writing {#_2️⃣-读写分离}

```js
// ❌
el.style.width = el.offsetWidth + 10 + 'px'

// ✅
const w = el.offsetWidth
el.style.width = w + 10 + 'px'
```

### 3️⃣ Use transform instead of top/left {#_3️⃣-使用-transform-替代-top-left}

```css
/* ❌ */
left: 100px;

/* ✅ */
transform: translateX(100px);
```


## 10\. High-frequency interview questions related to browser rendering {#十、浏览器渲染相关高频面试题}

### ❓ Why is CSS placed in the head and JS placed in the body? {#❓-为什么-css-放在-head-js-放在-body}

* CSS rendering blocking
* JS blocks DOM parsing

### ❓ async vs defer

| Properties | Whether to block | Execution time |
| ----- | ---- | --------- |
| async | ❌ | Execute immediately after downloading |
| defer | ❌ | After DOM parsing is completed |

### ❓ requestAnimationFrame

* **Executed before rendering the next frame**
* Suitable for animation
