## 1\. Summary of file upload methods {#一、文件上传方式总结}

### 1️⃣ Form upload (the most basic method) {#_1️⃣-表单上传-最基础方式}

```html
<form action="/upload" method="POST" enctype="multipart/form-data">
  <input type="file" name="file" />
  <button type="submit">上传</button>
</form>
```

✅ Features:

* Browser native support
* Suitable for simple file uploads (no JS required)
* Form `enctype` must be `multipart/form-data`

❌ Disadvantages:

* The page will refresh (not asynchronously)
* Difficult to control upload progress


### 2️⃣ Ajax asynchronous upload (mainstream front-end method) {#_2️⃣-ajax-异步上传-前端主流方式}

Use fetch method
```javascript
const formData = new FormData();
formData.append('file', fileInput.files[0]);
// 关于formData不得不说一下，formData.append的参数只有三个，当设置value时只支持字符串类型和Blob类型
// The field's value. This can be a string or Blob (including subclasses such as File). If none of these are specified the value is converted to a string.

fetch('/upload', {
  method: 'POST',
  body: formData
}).then(res => res.json());
```
Using XMLHttpRequest method
```js
// 检查是否支持FormData
if(window.FormData) {　
　　var formData = new FormData();

　　// 建立一个upload表单项，值为上传的文件
　　formData.append('upload', document.getElementById('upload').files[0]);
　　var xhr = new XMLHttpRequest();
　　xhr.open('POST', $(this).attr('action'));
　　// 定义上传完成后的回调函数
　　xhr.onload = function () {
　　　　if (xhr.status === 200) {
　　　　　　console.log('上传成功');
　　　　} else {
　　　　　　console.log('出错了');
　　　　}
　　};
　　xhr.send(formData);
}
```

✅ Advantages:

* No need to refresh the page
* Support display progress and resume downloading from breakpoints
* Can be accompanied by token or additional fields

📌 Backend receiving:

```js
// Node + Express
app.post('/upload', upload.single('file'), (req, res) => {
  res.json({ success: true });
});
```


### 3️⃣ Use third-party upload SDK (cloud storage) {#_3️⃣-使用第三方上传-sdk-云存储}

| Cloud vendor | Upload method | Features |
| ------- | --------------- | -------------- |
| Alibaba Cloud OSS | `ali-oss` SDK | Supports multi-part upload and signature direct upload |
| Tencent Cloud COS | `cos-js-sdk-v5` | Supports temporary keys, breakpoint resumption |
| Qiniu Cloud | `qiniu-js` | Base64 upload, form upload |

✅ Advantages:

* Reduce back-end pressure (front-end direct transmission to the cloud)
* Supports multi-part upload and instant transfer of large files

📌 Direct transfer process:

1. The front end requests the back end to upload credentials (signature)
2. Front-end uploads signature to cloud storage
3. Callback/notify backend after success


### 4️⃣ Large file upload in chunks (chunk upload) {#_4️⃣-大文件分片上传-chunk-upload}

```javascript
// 切片
const chunkSize = 5 * 1024 * 1024; // 5MB
const file = input.files[0];
const chunks = [];

for (let i = 0; i < file.size; i += chunkSize) {
  chunks.push(file.slice(i, i + chunkSize));
}
```

Upload:

```javascript
chunks.forEach((chunk, index) => {
  const formData = new FormData();
  formData.append('file', chunk);
  formData.append('index', index);
  fetch('/upload', { method: 'POST', body: formData });
});
```

Merge (backend):

```js
// 接收到所有切片后合并
fs.appendFileSync('target.mp4', chunk);
```

✅ Advantages:

* Support breakpoint resume download
* Can display progress and speed up parallel uploads


### 5️⃣ Base64 upload (small file scenario) {#_5️⃣-base64-上传-小文件场景}

```javascript
const reader = new FileReader();
reader.onload = () => {
  const base64 = reader.result;
  fetch('/uploadBase64', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ data: base64 })
  });
};
reader.readAsDataURL(file);
```

✅ Advantages:

* Simple to implement
* Can be directly used to store avatars, QR codes, etc.

❌ Disadvantages:

* Volume increased by approximately 33%
* Not suitable for large files


## 🧭 Upload function optimization points (interview focus) {#🧭-上传功能优化点-面试重点}

| Directions | Instructions |
| ------ | ------------------------------ |
| ✅ Multipart upload | Suitable for large files, supports resumed uploads |
| ✅ Parallel upload | Upload multiple shards at the same time, saving time |
| ✅ Instant transfer | Check whether file exists through hash |
| ✅ Upload progress | Using `XMLHttpRequest.onprogress` |
| ✅ Retry if failed | Automatically retransmit if network abnormality occurs |
| ✅ Front-end verification | File size/type restrictions |
| ✅ Signature direct transfer | Improve security |


## 2\. Summary of file download methods {#二、文件下载方式总结}

### 1️⃣ Direct download link (browser behavior) {#_1️⃣-直接下载链接-浏览器行为}

```html
<a href="https://example.com/file.pdf" download>下载文件</a>
```

✅ Simple and straightforward, no JS required.
⚠️ Under the same origin restriction, cross-domain may be restricted.


### 2️⃣ The backend returns a file stream (most common) {#_2️⃣-后端返回文件流-最常见}

```javascript
fetch('/api/download').then(res => res.blob()).then(blob => {
  const url = window.URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'report.pdf';
  a.click();
  URL.revokeObjectURL(url);
});
```

You can also download files in form (only replace the dom-related operation code in the middle of the above code)

```js
let myForm = document.createElement('form')
myForm.style.display = 'none'
myForm.setAttribute('target', '')
myForm.setAttribute('method', 'get')
myForm.setAttribute('action', url)
document.body.append(myForm);
myForm.submit();
```

📌 Backend:

```js
res.setHeader('Content-Disposition', 'attachment; filename="report.pdf"');
res.sendFile(filePath);
```

✅ Advantages:

* Controllable permissions
* Support cross-domain downloads


By the way, download the image with the desired specifications

```js
function downloadImgURL(url, name) { 
  let image = new Image(); 
  image.setAttribute("crossOrigin", "anonymous"); 
  image.src = url; 
  image.onload = () => { 
    let canvas = document.createElement("canvas"); 
    canvas.width = image.width; 
    canvas.height = image.height; 
    let ctx = canvas.getContext("2d"); 
    ctx.drawImage(image, 0, 0, image.width, image.height); 
    canvas.toBlob(blob => { 
      let url = URL.createObjectURL(blob); 
      let a = document.createElement("a"); 
      a.download = name; 
      a.href = url; 
      a.click(); 
      a.remove(); // 用完释放URL对象 
      URL.revokeObjectURL(url); 
      }); 
    }; 
  }
```

### 3️⃣ Blob download + file name resolution (recommended method) {#_3️⃣-blob-下载-文件名解析-推荐方式}

```javascript
fetch('/api/download').then(async (res) => {
  const blob = await res.blob();
  const filename = decodeURI(
    res.headers.get('Content-Disposition').split('filename=')[1]
    // 'Content-Type': 'application/octet-stream',// 这是一个二进制文件
  );
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  a.click();
});
```
By the way:

In a regular HTTP response, the Content-Disposition response header indicates in what form the response content should be displayed, whether in inline form (that is, a web page or part of a page), or downloaded and saved locally as an attachment.

Syntax:

```js
Content-Disposition: inline
Content-Disposition: attachment
Content-Disposition: attachment; filename="filename.jpg"
```

Its first parameter can be inline or attachment.If the first parameter is inline (default value), it means to display it on the web page or as a web page.If the first parameter is an attachment indicating that it should be downloaded, most browsers will display a save as dialog box and will fill in the file name of the dialog box with filename if filename is provided.

```
Content-Disposition: attachment; filename="filename.jpg"
```

Content-Disposition can trigger the "Save As" dialog box

```
200 OK
Content-Type: text/html; charset=utf-8
Content-Disposition: attachment; filename="cool.html"
Content-Length: 22

<HTML>Save me!</HTML>
```

The above response will not be processed as simple html. Most browsers will attempt to save the file as `cool.html`

Send `Content-Type:multipart/form-data` through POST request in HTML page. Here is an example

```js
POST /test.html HTTP/1.1
Host: example.org
Content-Type: multipart/form-data;boundary="boundary"

--boundary
Content-Disposition: form-data; name="field1"

value1
--boundary
Content-Disposition: form-data; name="field2"; filename="example.txt"

value2
--boundary--

```

Everyone still needs to know how to customize headers.

In essence, it is similar to the above `Content-Disposition`, except that we do not use the default header here. We customize a `response header` ourselves, decide the encoding method with the backend and return it. The frontend directly obtains this custom `header`, and then uses the corresponding decoding, such as using `decodeURIComponent`.
But we all need to know that in the case of cross-domain, the header obtained by the front end only has the default 6 basic fields: `Cache-Control`, `Content-Language`, `Content-Type`, `Expires`, `Last-Modified`, `Pragma`.
So if you want to get other headers, you need the backend to cooperate and set up

```js
Access-Control-Expose-Headers: Content-Disposition, custom-header
```

In this way, the front end can obtain the corresponding exposed header field. It should be noted that `Content-Disposition` also needs to be exposed.


### 4️⃣ Base64 file download {#_4️⃣-base64-文件下载}

```javascript
const base64 = 'data:application/pdf;base64,...';
const a = document.createElement('a');
a.href = base64;
a.download = 'file.pdf';
a.click();
```

✅ Suitable for small files (such as exported pictures, QR codes, etc.).


### 5️⃣ Streaming download (back-end chunked output) {#_5️⃣-流式下载-后端分块输出}

When used for large files or exporting reports (such as zip, excel):

* The backend uses streams to chunk output
* Frontend receives blob chunks in real time
* Can be downloaded and saved at the same time


## ⚙️ Download optimization direction {#⚙️-下载优化方向}

| Optimization points | Description |
| --------------------- | -------------- |
| ✅ Use Blob objects | Avoid memory explosion |
| ✅ Content-Disposition | The backend returns the file name |
| ✅ Content-Type | Ensure the file MIME type is correct |
| ✅ Asynchronous loading status | Prompt "File generating..." |
| ✅ Chunked streaming downloads | Prevent blocking for large files |


## 3\. High-frequency interview questions and answers {#三、面试高频问答}

**Q1:** How do you implement large file upload in your project?
👉 Sharding + parallel upload + breakpoint resume + file hash verification.

**Q2:** How to display the upload progress?
👉 Use `xhr.upload.onprogress` or `fetch + progress event`.

**Q3:** How to achieve instant transmission?
👉 Calculate the file hash before uploading, and the backend determines whether the file already exists.

**Q4:** How to prevent direct browser preview when downloading files?
👉 Add response headers to the backend:

```js
res.setHeader('Content-Disposition', 'attachment; filename="xx.pdf"');
```

**Q5:** How to prevent security issues when uploading files?
👉 Front-end verification + back-end MIME checking + file isolation storage.
