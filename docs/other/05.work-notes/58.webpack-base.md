## 1️⃣ What is Webpack?What is the core concept? {#_1️⃣-webpack-是什么-核心理念是什么}

**Webpack is a static module bundler.**

Core idea:

* Treat all resources as modules (JS, CSS, images, fonts, etc.)
* Analyze the relationship between modules through dependency graph
* The final output is a bundle (or multiple chunks) that the browser can run.

One sentence explanation:

> Webpack modularizes all resources in the front-end project and finally packages and outputs them uniformly.


## 2️⃣ Core concepts of Webpack (very important) {#_2️⃣-webpack-的核心概念-非常重要}

### **① Entry** {#_1-entry-入口}

Tells Webpack which file to start analyzing the dependency graph from.

```js
entry: './src/index.js'
```

Can be multiple entries:

```js
entry: {
  main: './src/main.js',
  admin: './src/admin.js'
}
```


### **② Output** {#_2-output-出口}

Decide where to output the packaged file and what to call it.

```js
output: {
  filename: 'bundle.js',
  path: path.resolve(__dirname, 'dist')
}
```


### **③ Loader (module converter)** {#_3-loader-模块转换器}

Webpack can only handle JS and requires loader extension capabilities.

Common loaders:

| Resources | Corresponding loader |
| ---- | ----------------------------------------------- |
| CSS  | css-loader, style-loader                        |
| LESS | less-loader                                     |
| Image | url-loader/file-loader (Webpack5→asset module) |
| ES6  | babel-loader                                    |
| Vue  | vue-loader                                      |
| TS   | ts-loader                                       |

Example:

```js
module: {
  rules: [
    { test: /\.css$/, use: ['style-loader', 'css-loader'] }
  ]
}
```


### **④ Plugins (plug-in system, Webpack’s strongest capability)** {#_4-plugins-插件体系-webpack-最强能力}

Loader handles a type of file, and Plugin handles the entire build process.

Common plug-ins:

| Plug-in | Function |
| ---------------------------- | -------------------- |
| html-webpack-plugin | Generate HTML and automatically inject bundles |
| clean-webpack-plugin | Clean dist |
| mini-css-extract-plugin | Extract CSS |
| define-plugin | Inject environment variables |
| terser-webpack-plugin | Compress JS |
| css-minimizer-webpack-plugin | Compress CSS |


### **⑤ Mode** {#_5-mode-构建模式}

Two environments:

```js
mode: 'development'
// 或
mode: 'production'
```

Difference:

| mode | features |
| ----------- | -------------------------------- |
| development | No compression, source map included, module identifier readable |
| production | automatic compression, tree shaking, scope hoisting |


### **⑥ DevServer (development server)** {#_6-devserver-开发服务器}

Used for local development and supports hot updates (HMR).

```js
devServer: {
  hot: true,
  port: 8080,
  open: true
}
```


### **⑦ Source Map (location code error)** {#_7-source-map-定位代码错误}

Most common settings:

```js
devtool: 'source-map'
```


## 3️⃣ Webpack packaging process {#_3️⃣-webpack-打包流程}

**Webpack build process:**

1. Read configuration (entry)
2. Parse the entry file and build AST
3. Recursively build a dependency graph (module graph) layer by layer according to dependencies
4. Loader converts the corresponding file content
5. Plugin intervenes in the build life cycle (optimize, emit, etc.)
6. generate chunk → bundle
7. Output is generated to the output directory

If you could describe it in one sentence:

> Webpack recursively builds the dependency graph starting from the entry point, uses loader to process the module, then uses the plugin plug-in mechanism to extend the build process, and finally outputs the optimized bundle file.

## 🔥 **Real Interview Webpack High Frequency 20 Questions and Answers** {#🔥-真实面试-webpack-高频-20-问及答案}


### **1. What is Webpack?What is its core concept?** {#_1-webpack-是什么-它的核心概念是什么}

**Answer**:
Webpack is a static module packager that converts all resources in the project (JavaScript, CSS, images, fonts, etc.) into files (bundle) that can be run in the browser by parsing dependencies.
The core concepts of Webpack are:

* **Entry**: Entry file, tells Webpack where to start building the dependency graph.
* **Output**: Output file, specify the storage location of the packaged file.
* **Loader**: Allows Webpack to handle non-JavaScript resources (such as CSS, images, fonts, etc.).
* **Plugin**: Extend the functionality of Webpack through the plug-in system.


### **2. What is the difference between Loader and Plugin?** {#_2-loader-和-plugin-有什么区别}

**Answer**:

* **Loader**: Responsible for converting the content of files, usually used to process non-JavaScript files (such as CSS, images, TypeScript, etc.).It is a file level operation.
* **Plugin**: used to extend the functionality of Webpack and perform more complex tasks, such as compression, optimization, generation of HTML files, etc.It is a global level operation and handles the entire build process.


### **3. What is Tree Shaking in Webpack?** {#_3-webpack-中的-tree-shaking-是什么}

**Answer**:
Tree Shaking is a technique for eliminating unused code in JavaScript.Webpack statically analyzes ES6 modules (import/export) to determine which code is unused and removes it from the final bundle.It is typically enabled in production mode and relies on the static structure of ES modules.


### **4. What is Code Splitting?How to achieve?** {#_4-什么是-code-splitting-代码分割-如何实现}

**Answer**:
Code Splitting refers to splitting code into multiple files so that they can be loaded on demand.It improves the initial loading speed of your app.Webpack provides three ways to implement code splitting:

* **Entry Point Segmentation**: Implement different entry files through multiple entries.
* **On-demand loading (Dynamic Import)**: Use `import()` to dynamically import modules, and Webpack will automatically split the code according to needs.
* **SplitChunksPlugin**: A plug-in provided by Webpack that automatically analyzes the code and extracts common modules into independent files.


### **5. What is `devServer` in Webpack?** {#_5-什么是-webpack-中的-devserver}

**Answer**:
`devServer` is a development server for Webpack that provides hot module replacement (HMR) and live reloading capabilities.It helps developers quickly preview projects when developing locally, and provides functions similar to HTTP servers.
Common configurations:

```js
devServer: {
  contentBase: './dist',
  hot: true,
  open: true,
  port: 8080
}
```


### **6. What are `contenthash` and `chunkhash` in Webpack?** {#_6-什么是-webpack-中的-contenthash-和-chunkhash}

**Answer**:

* **`chunkhash`**: Hash value generated based on chunk content, often used in file names for cache control.
* **`contenthash`**: A hash value generated based on the file content. It is recommended to be used in a production environment to ensure that the file name will also change when the file content changes.

```js
output: {
  filename: '[name].[contenthash].js'
}
```


### **7. How does Webpack handle dependencies?** {#_7-webpack-如何处理依赖}

**Answer**:
Webpack recursively builds module dependency graphs by statically analyzing `import` or `require` in the code.During the build process, Webpack loads each module one by one and processes them, ultimately generating one or more bundled files.


### **8. How does Webpack 5 handle Node.js core modules?** {#_8-webpack-5-如何处理-node-js-的核心模块}

**Answer**:
Webpack 5 removes automatic polyfill for Node.js core modules.If you need to use Node core modules (such as `crypto`, `path`, etc.), you need to configure it manually or use `resolve.fallback` configuration to provide browser-side polyfill.

```js
resolve: {
  fallback: {
    "crypto": require.resolve("crypto-browserify"),
    "stream": require.resolve("stream-browserify"),
  }
}
```


### **9. Why does Webpack use `source map` and what is its role?** {#_9-为什么-webpack-使用-source-map-它的作用是什么}

**Answer**:
`source map` is a technology that maps compressed code back to source code, helping developers view the original source code and locate errors during browser debugging.
Common configurations:

```js
devtool: 'source-map'
```


### **10. What is `hot module replacement (HMR)` in Webpack?** {#_10-webpack-中的-hot-module-replacement-hmr-是什么}

**Answer**:
HMR is a feature provided by Webpack that allows only the changed modules to be updated after code modifications without refreshing the entire page.This greatly improves development efficiency and avoids loss of application state.


### **11. How does Webpack optimize packaging performance?** {#_11-webpack-如何优化打包性能}

**Answer**:

* **Cache Optimization**: Enable persistent caching (Webpack 5 default).
* **Reduce module parsing time**: Use `include` and `exclude` to limit the application scope of Loader.
* **Code Splitting**: Split code through dynamic import or SplitChunksPlugin.
* **Tree Shaking**: Remove unused code.
* **Parallel processing**: Use `thread-loader` to enable multi-process builds.


### **12. What is the `externals` configuration item in Webpack?** {#_12-什么是-webpack-中的-externals-配置项}

**Answer**:
`externals` is used to configure to exclude external dependencies from packaging so that they are not packaged by Webpack.Often used to exclude common libraries (such as React, Vue), etc., to reduce the size of packaged files.

```js
externals: {
  react: 'React',
  'react-dom': 'ReactDOM'
}
```


### **13. What is the `publicPath` configuration item in Webpack?** {#_13-webpack-中的-publicpath-配置项是什么}

**Answer**:
`publicPath` specifies the public URL path of the resource.It can be a CDN address, a relative path, or an absolute path.`publicPath` is usually used to specify the storage location of packaged resource files.

```js
output: {
  publicPath: '/assets/'
}
```


### **14. How to implement Webpack’s persistent cache?** {#_14-如何实现-webpack-的持久化缓存}

**Answer**:
In Webpack 5, subsequent builds can be accelerated by configuring a persistent cache (`cache`).The file system cache is used by default.

```js
cache: {
  type: 'filesystem'
}
```


### **15. What are the `module.rules` configuration items in Webpack?** {#_15-webpack-中的-module-rules-配置项是什么}

**Answer**:
`module.rules` is used to define how to handle different types of files (modules), and configure Loader to convert modules.Each `rule` can specify `test` (matching files) and `use` (loader to use).

```js
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    }
  ]
}
```


### **16. What does `resolve.alias` in Webpack do?** {#_16-webpack-中的-resolve-alias-有什么作用}

**Answer**:
`resolve.alias` is used to set the module path alias and simplify the module introduction path.For example, map a folder or module to an alias to reduce the trouble of writing long paths.

```js
resolve: {
  alias: {
    '@components': path.resolve(__dirname, 'src/components/')
  }
}
```


### **17. Why use `html-webpack-plugin`?** {#_17-为什么要使用-html-webpack-plugin}

**Answer**:
`html-webpack-plugin` is used to automatically generate HTML files and automatically inject all resources packaged by Webpack (such as JS and CSS files) into HTML to avoid manual updates.

```js
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html'
    })
  ]

```


### **18. What are the main improvements of Webpack 5 compared to Webpack 4?** {#_18-webpack-5-相比-webpack-4-有哪些主要改进}

**Answer**:

* **Module Federation**: Supports micro front-end architecture.
* **Persistent Cache**: Greatly improves build speed.
* **Remove polyfill** of Node.js core module: reduce packaging size.
* **Better Tree Shaking support**: Improve packaging performance.


### **19. What are `file-loader` and `url-loader`?What's the difference?** {#_19-什么是-file-loader-和-url-loader-它们的区别是什么}

## Webpack application summary two {#webpack应用总结二}

### Differences between `module`, `chunk` and `bundle` {#module、chunk、bundle区别}
- module --> Each source code file is a module, and everything in webpack is a module.
- chunk --> Merged from multiple modules, such as entry, import, splitChunk.Similar to a block of code in memory that has not yet been produced
- The final output file of the bundle, each chunk will generate a bundle file

Entry is the entry file of webpack and can generate chunk names by key names.
import can generate a chunk, which is introduced into html by default.
Define splitChunks in optimization to cache groups and name chunks through cacheGroups, and then introduce or exclude a chunk file in htmlWebpackPlugin.

### The difference between loaders and plugins {#loader和plugins的区别}
- Both are intended to extend the functionality of webpack.The loader only focuses on the field of converting files (transform), completing compression, packaging, and language translation; while the plugin is not only limited to packaging and loading of resources, it can also package optimization and compression, redefine environment variables, etc.
- The loader runs before packaging files (loader is a preprocessing file when the module is loaded); plugins work throughout the compilation cycle
- A loader has a single responsibility and only needs to complete one conversion.A loader is actually a Node.js module.When multiple loaders need to be called to convert a file, each loader will be executed sequentially in a chain.
- Many events will be broadcast during the life cycle of webpack running. The plugin will listen to these events and change the output results at the appropriate time through the API provided by webpack.
- Loader module converter, such as less --> css, identifying image formats
- plugins extension plug-ins, such as htmlWebpackPlugin, friendlyLoaderWebpackPlugin, bundleAnalyzerPlugin, CleanWebpackPlugin, MiniCssExtractPlugin, ParallelUglifyPlugin, `webpack.IgnorePlugin`, `webpack.DefinePlugin`

What are the commonly used loaders [https://www.webpackjs.com/loaders/](https://www.webpackjs.com/loaders/)
What are the commonly used plugins [https://www.webpackjs.com/plugins/](https://www.webpackjs.com/plugins/)

### Optimize babel-loader {#优化babel-loader}

```js
module: {
  rules: [
    {
      test: /\.js$/,
      // loader: ['babel-loader?cacheDirectory'], // 没有修改的es6代码不会重新编译
      use: {
        loader: 'babel-loader',
        options: {
          presets: [
            ["@babel/preset-env"],
            {
              useBuiltIns: 'entry', 
              corejs: 3,
              targets: 'last 2 Chrome versions', // 指定兼容性
              //  use3rBuiltIns: 'false' 不对polyfill做操作。如果引入@babel/polyfill，则无视配置的浏览器兼容性，引入所有polyfill
              // use3rBuiltIns: 'entry' 根据浏览器的兼容性，引入浏览器不兼容的polyfill。兼容的就不会引入了
              // use3rBuiltIns: 'usage',根据配置的浏览器兼容性，以及代码中用到的api来进行polyfill的按需添加
              // 'corejs':2的时候需要在入口文件中手动添加import '@babel/polyfill'，会自动动根据browserlistrc替换成浏览器不兼容的所有polyfill
              // 这里需要指定core-js版本，如果”corejs“：3，则import `@babel/polyfill` 需要改成 import 'core-js/stable'; import 'regenerator-runtime/runtime'
              // core-js@2 分支中已经不会再添加新特性，新特性都会被添加到core-js@3,比如，Array.prototype.flat()
            }
          ]
        }
      },
      include: srcPath,
      // exclude: /node_modules/
    },
  ]
}

```

When configuring babe-loader, write an include and exclude to reduce unnecessary code.

- cache-loader generates cacheKey as the file name based on the version number file name to see if the file exists. If it exists, it compares mtime (modify time). If the same return cache is used, if the following loader is not used, it is lightweight and does not compare the content.
- babel-loader generates cacheKey as the file name through the file, option, and version number. It reads whether the file already exists. If it exists, it uses the cache. If it does not exist, babel-core escapes, zlib compression, and fs are written to the cache. It caches according to the file content.It does not affect other loaders.

### happyPack

- js single thread, enable multi-process packaging
- Improve build speed (especially multi-core CPUs)

```js
const HappyPack = require('happypack')

modles:{
    rules: [
            // js
            {
                test: /\.js$/,
                // 把对 .js 文件的处理转交给 id 为 babel 的 HappyPack 实例
                use: ['happypack/loader?id=babel'],
                include: srcPath,
                // exclude: /node_modules/
            }]
}

// plugins中
// happyPack 开启多进程打包
new HappyPack({ 
    // 用唯一的标识符 id 来代表当前的 HappyPack 是用来处理一类特定的文件
    id: 'babel',
    // 如何处理 .js 文件，用法和 Loader 配置中一样
    loaders: ['babel-loader?cacheDirectory']
})


```

### ParallelUglifyPlugin

- webpack's built-in Uglify tool compresses js
- js single thread, enabling multi-threading is faster
- Same as happyPack

```js
// 引用
const ParallelUglifyPlugin = require('webpack-parallel-uglify-plugin')


// plugins中配置
// 使用 ParallelUglifyPlugin 并行压缩输出的 JS 代码
new ParallelUglifyPlugin({
    // 传递给 UglifyJS 的参数
    // （还是使用 UglifyJS 压缩，只不过帮助开启了多进程）
    uglifyJS: {
        output: {
            beautify: false, // 最紧凑的输出
            comments: false, // 删除所有的注释
        },
        compress: {
            // 删除所有的 `console` 语句，可以兼容ie浏览器
            drop_console: true,
            // 内嵌定义了但是只用到一次的变量
            collapse_vars: true,
            // 提取出出现多次但是没有定义成变量去引用的静态值
            reduce_vars: true,
        }
    }
})

```

### About starting multiple processes {#关于开启多进程}
If the project is large and packaging is slow, enabling multiple processes can improve the speed.However, if the project is small and the packaging is fast, turning on multiple processes will reduce the speed (process overhead), so use it as needed.

### Auto refresh {#自动刷新}

After modifying the code, the changed code is displayed in the browser. If webpack-dev-server is used, watch will automatically turn on automatic refresh.

```js
 watch: true, // 开启监听，默认为 false
 watchOptions: {
     ignored: /node_modules/, // 忽略哪些
     // 监听到变化发生后会等300ms再去执行动作，防止文件更新太快导致重新编译频率太高
     // 默认为 300ms
     aggregateTimeout: 300,
     // 判断文件是否发生变化是通过不停的去询问系统指定文件有没有变化实现的
     // 默认每隔1000毫秒询问一次
     poll: 1000
 }
 
```

### Hot update {#热更新}

Normal refresh, the entire page is refreshed, the speed is relatively slow, and the status will be lost.In the case of hot update, the web page will not be refreshed, the new code will take effect, and the status will not be lost.

```js
// 第一步引入
const HotModuleReplacementPlugin = require('webpack/lib/HotModuleReplacementPlugin');

// 第二步
 entry: {
         // index: path.join(srcPath, 'index.js'),
         index: [
             'webpack-dev-server/client?http://localhost:8080/',
             'webpack/hot/dev-server',
             path.join(srcPath, 'index.js')
         ]
     },
 
// 第三步 在devServer中设置 开启
hot:true
```

The above enables hot update. When modifying the css style, it can be hot updated without refreshing the page. However, modifying the js will still refresh the page.

```js
// // 开启热更新之后的代码逻辑
// if (module.hot) {
//     module.hot.accept(['./math'], () => {
//         const sumRes = sum(10, 30)
//         console.log('sumRes in hot', sumRes)
//     })
// }
```

The above means that when the specified math module code is modified, the callback function will be returned and the results will be displayed.Others will refresh the page.

If the page is really complex and has many statuses, hot update can be enabled.

### DllPlugin dynamic link library {#dllplugin动态链接库}

- Front-end frameworks such as Vue and React are large and slow to build.
- Relatively stable, version upgrades are infrequent
- The same version only needs to be built once and does not need to be built multiple times.
- webpack has built-in DllPlugin support
- (1) DllPlugin --> Package the dll file (prepackage first)
- (2) DllReferencePlugin --> Use dll files (no matter how many changes and upgrades are made, as long as the version is not upgraded and the file remains unchanged, the result will always be used)

::: tip
Regardless of whether the dllPlugin is configured or not, it has no impact on the source code of the program.
:::

(1) First configure webpack.dll.js and package the dll file through the dll plug-in

<details>

<summary>Click to expand the configuration example</summary>

```js
const path = require('path')
const DllPlugin = require('webpack/lib/DllPlugin')
const { srcPath, distPath } = require('./paths')

module.exports = {
  mode: 'development',
  // JS 执行入口文件
  entry: {
    // 把 React 相关模块的放到一个单独的动态链接库
    react: ['react', 'react-dom']
  },
  output: {
    // 输出的动态链接库的文件名称，[name] 代表当前动态链接库的名称，
    // 也就是 entry 中配置的 react 和 polyfill
    filename: '[name].dll.js',
    // 输出的文件都放到 dist 目录下
    path: distPath,
    // 存放动态链接库的全局变量名称，例如对应 react 来说就是 _dll_react
    // 之所以在前面加上 _dll_ 是为了防止全局变量冲突
    library: '_dll_[name]',   // lib全局变量名
  },
  plugins: [
    // 接入 DllPlugin
```

### The difference between es6 module and commonjs {#es6-module和commonjs的区别}

- The commonly used front-end is es6 module, and the commonly used nodejs is commonjs.
- es6 module is statically introduced and introduced during compilation
- commonjs is introduced dynamically and is introduced during execution
- Only es6 module static references can perform static analysis and implement tree-shaking.

- The commonjs module outputs a copy of the value, and the es6 module outputs a reference to the value.
- The commonjs module is loaded at runtime, and the es6 module is the compile-time output interface.

commonjs module loading is an object that will only be generated after the script is completed.\
The es6 module is not an object. Its external interface is just a static fix, which is generated during the static analysis phase of the code.

```js
// commonjs方式引入
let apiList = require('../config/api.js')

if(isDev){
  // 可以执行时动态引入
  apiList = require('../config/api_dev.js')
}

// es6 module方式引入

import apiList from '../config/api.js'

if(isDev) {
  // 编译时报错，因为只能静态引入
  import apiList from '../config/api.js'
}
```

### tree shaking
- A module can have multiple methods. As long as one of the methods is used, the entire file will be put into the bundle. Tree shaking means that only the used methods are put into the bundle and the useless ones will be deleted in the `uglify` stage.
- The principle is to take advantage of the characteristics of the es6 module. It can only appear as a top-level statement of the module. The module name of the import can only be a character constant.

- Webpack supports it by default and is enabled by default in production mode.
    - "sideEffects": false All code has no side effects (all can perform `tree-shaking`)
    - It is possible to delete the css and `@babel/polyfill` files and set "sideEfffectes:`['css']`"

### scope Hosting

Put the content of multiple js into one function, so that the number of scopes is smaller, less memory is consumed, and there is no need to make frequent cross-scope calls.\
The principle of scope hositing is to place all modules in a function scope in order of reference, and then rename some variables appropriately to prevent naming conflicts.\
This feature is enabled by default when mode is production.The development environment requires the webpack.optimizeModuleConcatenationPlugin plug-in

- Smaller code size
- Create function scopes with less scope
- Code is more readable

Configuration:

```js
const ModuleConcatenationPlugin = require('webpack/lib/optimize/ModuleConcatenatoinPlugin')

module.exports = {
  resolve:{
    // 针对npm中的第三方模块优先采用jsnext：main中指向的es6 module模块化语法文件
    mainFields: ['jsnext:main','browser', 'main']
  },
  plugins:[
    // 开启scope hosting
    new ModuleConcatenationPlugin(),
  ]
}
 
```
