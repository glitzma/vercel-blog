## 1\. Problem cause analysis {#一、问题原因分析}

1. **The time returned by the server may be UTC time**

   * For example, the backend returns `"2024-09-25T09:00:00Z"`
   * `Z` represents UTC time
   * The front-end `new Date("2024-09-25T09:00:00Z")` will automatically switch to local time display

2. **The front-end environment uses the local time zone by default**

   * `new Date()` generates the local time of the current browser by default
   * If the browser is at **UTC+8** and the server is at **UTC+0**, there will be a difference of 8 hours

3. **JSON time string without time zone identifier**

   * Such as `"2024-09-25 09:00:00"`
   * JS will treat it as **local time**, which may be inconsistent with the server time zone


## 2\. Common solutions {#二、常用解决方案}

### 1️⃣ The unified time is UTC {#_1️⃣-统一时间为-utc}

```javascript
// 服务器返回 UTC 时间
const utcTime = "2024-09-25T09:00:00Z";
const date = new Date(utcTime); 

console.log(date.toUTCString());  // UTC 格式
console.log(date.toISOString());   // ISO 格式
```

* Use `toISOString()` to ensure consistency (UTC time) across different clients.


### 2️⃣ Switch to local time display {#_2️⃣-转为本地时间显示}

```javascript
const date = new Date("2024-09-25T09:00:00Z");
console.log(date.toLocaleString());      // 本地格式
console.log(date.toLocaleString('zh-CN')); // 中文格式
```

✅ `toLocaleString()` will automatically convert the display according to the time zone of the browser.


### 3️⃣ Use libraries such as `moment.js` / `dayjs` {#_3️⃣-使用-moment-js-dayjs-等库}

* **Recommended dayjs + utc + timezone plug-in**

```javascript
import dayjs from 'dayjs';
import utc from 'dayjs/plugin/utc';
import timezone from 'dayjs/plugin/timezone';

dayjs.extend(utc);
dayjs.extend(timezone);

const serverTime = "2024-09-25T09:00:00Z";

// 转为本地时区
const localTime = dayjs.utc(serverTime).tz(dayjs.tz.guess()).format('YYYY-MM-DD HH:mm:ss');

console.log(localTime); // 根据浏览器时区显示正确时间
```

* Advantages:

  1. Support any time zone conversion
  2. Avoid `new Date()` differences when parsing strings directly


### 4️⃣ The front and back ends agree on a unified time format {#_4️⃣-前后端约定统一时间格式}

1. The backend uniformly returns **UTC time ISO format**

   * `"2024-09-25T09:00:00Z"`
2. The front end uniformly resolves to local time or specified time zone

> Avoid returning `"2024-09-25 09:00:00"` directly (without time zone information)


### 5️⃣ Simple manual time zone correction {#_5️⃣-简单的手动时区校正}

```javascript
const serverDate = new Date("2024-09-25T09:00:00"); // 假设服务器时间 UTC
const offset = serverDate.getTimezoneOffset() / 60; // 获取本地时区差（小时）
const localDate = new Date(serverDate.getTime() - offset * 3600 * 1000);

console.log(localDate.toLocaleString());
```

⚠️ This method is not as safe as using dayjs/moment and is error-prone.


## 3\. Summary of interview perspective {#三、面试角度总结}

* **Core points**:

  1. `new Date()` defaults to local time zone
  2. ISO 8601 string with `Z` for UTC
  3. Strings without time zone may be parsed as local time
  4. Unifying the front-end and back-end time formats is the key

* **Practical Solution**:

  * Return to UTC → The front end uses `dayjs.utc().tz()` or `toLocaleString()` to display locally
  * Or unify all front-end processing to UTC (both backend and front-end use UTC)


## Appendix {#附录}
### 1\. What is UTC time? {#一、utc-时间是什么}

**UTC（Coordinated Universal Time）**

* Chinese name: **Coordinated Universal Time**
* It is a standard time that does not change with time zone changes.
* Similar to "World Unified Time", consistent globally
* Used in networks, servers and cross-time zone systems to avoid local time differences

📌 Features:

1. Not affected by daylight saving time
2. Almost the same as GMT (Greenwich Mean Time)
3. Standard format: `YYYY-MM-DDTHH:mm:ssZ`, the `Z` at the end represents UTC


### 2\. Examples of common formats {#二、常见格式示例}

| Format | Meaning | Description |
| --------------------------- | ------ | ----------------------- |
| `2024-09-25T09:00:00Z` | UTC time | `Z` represents UTC |
| `2024-09-25T09:00:00+08:00` | East Eighth District Time | `+08:00` means 8 hours ahead of UTC |
| `2024-09-25 09:00:00` | No time zone | Default resolved to local time (dangerous) |


### 3\. The relationship between UTC and local time {#三、utc-与本地时间的关系}

```javascript
const utcDate = new Date("2024-09-25T09:00:00Z"); // UTC
console.log(utcDate.toUTCString()); // Thu, 09 Nov 2025 09:00:00 GMT
console.log(utcDate.toLocaleString()); // 根据浏览器时区转换显示
```

Assuming that the browser is in **East Eighth District (UTC+8)**, it displays:

```
2024-09-25 17:00:00
```

✅ UTC+8 → add 8 hours


### 4\. Why use UTC {#四、为什么使用-utc}

1. **Sync across time zones**

   * The front-end, back-end, and database are all saved in UTC.
   * Avoid time confusion caused by daylight saving time or different time zones

2. **Unified display on the front end**

   * The server uniformly returns UTC
   * The front end displays local time according to user time zone conversion

3. **Log, scheduling, scheduled tasks**

   * Recorded in UTC, consistent for global users and convenient for statistics


### 5\. Common front-end operations {#五、前端常见操作}

#### 1️⃣ Convert to local time {#_1️⃣-转本地时间}

```javascript
const utcTime = "2024-09-25T09:00:00Z";
const localTime = new Date(utcTime).toLocaleString();
console.log(localTime); // 浏览器本地时区显示
```

#### 2️⃣ Display UTC time in ISO format {#_2️⃣-显示-iso-格式-utc-时间}

```javascript
const now = new Date();
console.log(now.toISOString()); // 2024-09-25T09:00:00.000Z
```

#### 3️⃣ Use dayjs / moment to convert time zone {#_3️⃣-使用-dayjs-moment-转换时区}

```javascript
import dayjs from 'dayjs';
import utc from 'dayjs/plugin/utc';
import timezone from 'dayjs/plugin/timezone';

dayjs.extend(utc);
dayjs.extend(timezone);

const serverTime = "2024-09-25T09:00:00Z";
const localTime = dayjs.utc(serverTime).tz(dayjs.tz.guess()).format('YYYY-MM-DD HH:mm:ss');

console.log(localTime);
```

✅ Automatically displays the correct time based on the browser time zone.


### 6\. Interview summary points {#六、面试总结点}

1. **UTC is unified time and is not affected by time zones**
2. **The server returns UTC uniformly, and the front end displays it according to the local time zone**
3. **Avoid using time strings without time zones, as they may cause parsing errors**
4. **JS `Date` objects default to the local time zone, but can be handled via UTC methods**
