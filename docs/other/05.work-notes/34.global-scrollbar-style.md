## 1\. Give a conclusion first {#一、先给结论}

- There will be an impact, but in most cases it will be small;
- The real performance risks are:
- "A lot of `overflow: scroll` + custom scroll bar style + high frequency scrolling"

In other words:

* **Native Scrollbars**: Almost nothing to worry about
* **Custom scroll bars (especially WebKit style)**: need to control the number


## 2\. Why “many scroll bars” may affect performance? {#二、为什么-很多滚动条-可能影响性能}

we start from **Browser underlying implementation** Come and see.


## 3\. How is scrolling implemented in the browser? {#三、滚动在浏览器里是怎么实现的}

### 1️⃣ Native scrolling (best case scenario) {#_1️⃣-原生滚动-最佳情况}

* Scroll ≠ Re-Layout
* In most cases it is:

  ```
  Composite（GPU 位移）
  ```
* The browser will treat the scrollable area as an **independent scrolling layer**

👉 **Extremely fast**


### 2️⃣ What does `overflow: scroll` do? {#_2️⃣-overflow-scroll-做了什么}

* Create a **scroll container**
* The browser needs maintenance:

  * scroll offset
  * clipping area
  * scroll event dispatch

📌 **scroll itself is cheap**


## 4\. Where does the performance problem really occur? {#四、性能问题真正出现在哪}

### 🔥 Focus: Customize scroll bar style {#🔥-重点-自定义滚动条样式}

```css
::-webkit-scrollbar
::-webkit-scrollbar-thumb
::-webkit-scrollbar-track
```

### What happens after customization? {#自定义后会发生什么}

* The scroll bar becomes:

  * **Part of normal DOM drawing**
* During scrolling:

  * Participation required **Paint**
  * Can’t completely follow the native synthesis path

📉 **Paint times ↑**


## 5\. Many scroll bars + custom styles = risk points {#五、很多滚动条-自定义样式-风险点}

### Typical high-risk scenarios {#典型高风险场景}

```text
页面上有 50~100 个
overflow: scroll 的容器
并且：
- 都使用了 ::-webkit-scrollbar 样式
- 同时滚动（如列表、拖拽）
```

May cause:

* Paint frequently
* Too many compositing layers
* Stuttering in scrolling (especially on low-end devices)


## 6\. How to verify DevTools? {#六、devtools-怎么验证}

### 1️⃣ Open Paint flashing {#_1️⃣-打开-paint-flashing}

```
DevTools → Rendering → Paint flashing
```

### 2️⃣Scroll the page {#_2️⃣-滚动页面}

#### Native scroll bar: {#原生滚动条}

* Almost no green flicker

#### Custom scroll bars: {#自定义滚动条}

* The scroll bar area frequently flashes green
* FPS drop

👉 **This is Paint’s proof**


## 7\. Will setting the scroll bar style globally affect "all scrolling"? {#七、全局设置滚动条样式-会不会影响-所有滚动}

### CSS example: {#css-示例}

```css
* {
  scrollbar-width: thin;            /* Firefox */
}

::-webkit-scrollbar {
  width: 6px;
}
```

### Browser behavior: {#浏览器行为}

* **Only works on scrollable containers**
* Scrollbars are not created in vain
* But:

  * Each scroll container will have styles applied

📌 **The style itself is not expensive, the cost is the painting when scrolling**


## 8\. Under what circumstances can it be used with confidence? {#八、什么情况下可以放心用}

### ✅Safety scenarios {#✅-安全场景}

* Small number of scroll containers (< 10)
* Low scrolling frequency
* Mainly desktop
* No scrolling in animation/drag


### ⚠️ Need to be cautious {#⚠️-需要谨慎}

* Large backend system
* virtual list
* Multiple nested scroll areas
* Mobile WebView


## 9\. Engineering-level best practices {#九、工程级最佳实践}

### 1️⃣ If you can use scroll, don’t use it. {#_1️⃣-能不用-scroll-就不用}

* Page-level scrolling is better than local scrolling
* Reduce nested scroll areas


### 2️⃣ Only customize “key areas” {#_2️⃣-只给-关键区域-自定义}

```css
/* ❌ 全局 */
::-webkit-scrollbar {}

/* ✅ 指定容器 */
.list::-webkit-scrollbar {}
```


### 3️⃣ Use `overflow: auto` instead of scroll {#_3️⃣-使用-overflow-auto-而非-scroll}

```css
/* ❌ 永远显示滚动条 */
overflow: scroll;

/* ✅ 需要时才显示 */
overflow: auto;
```

Reduce:

* scroll container quantity
* Synthetic layer pressure


### 4️⃣ Avoid scroll bar animation {#_4️⃣-避免滚动条动画}

```css
/* ❌ */
::-webkit-scrollbar-thumb {
  transition: all 0.3s;
}
```

repaint is triggered when scrolling


### 5️⃣ Use “virtual scrolling” for large lists {#_5️⃣-大列表用-虚拟滚动}

(React/Vue scenario)

* react-window
* vue-virtual-scroller


## 10\. Summary {#十、总结}

- The browser's native scrolling can often be done in the compositing stage, with good performance.
- But if you customize the style of the scroll bar, the scroll bar will participate in the drawing.
- In a large number of `overflow: scroll` containers and high-frequency scrolling scenarios,
- May increase paint and compositing overhead.
- Therefore, global custom scroll bar styles should be avoided in projects.
- And reduce the number of nested scrolling containers.
