## 1\. Understanding Composite Layer {#一、理解-composite-layer}

- **The browser splits the page into multiple layers, and each layer is drawn separately,**
- **Finally, it is handed over to the GPU to do only the "displacement/transparency/transformation" synthesis.**

Core points:

* Layers **Only Paint Once**
* Only follow **Composite**
* No more Layout/Paint


## 2\. Why is there a Composite Layer? {#二、为什么要有-composite-layer}

#### ❌ Problems with traditional processes {#❌-传统流程的问题}

```
JS → Layout → Paint → Composite
```

Each frame of the animation:

* Recalculate layout
* redraw pixels

👉CPU explodes, FPS drops to 20+


#### ✅ The process after introducing the synthesis layer {#✅-引入合成层后的流程}

```
首次：
Layout → Paint（生成位图）

动画中：
Composite（GPU 位移）
```

👉 **Only do matrix operations on GPU**


## 3\. Browser internal perspective (very critical) {#三、浏览器内部视角-非常关键}

#### The essence of each Composite Layer is: {#每个-composite-layer-本质是}

* A **Bitmap (Rasterized Bitmap)**
* Have your own:

  * displacement matrix
  * Transparency
  * Z order

The GPU only does:

```text
matrix * bitmap → screen
```

⚡ Extremely fast


## 4\. Under what circumstances will a Composite Layer be created?(must memorize) {#四、哪些情况会创建-composite-layer-必背}

### 🚀 Active creation (you have control) {#🚀-主动创建-你能控制}

```css
transform: translateZ(0);
transform: translate3d(0,0,0);
opacity < 1;
will-change: transform;
```


### 🌈 Automatically created by the browser {#🌈-浏览器自动创建}

* `position: fixed`
* `video / canvas / iframe`
* CSS 3D transform
* Animated transform / opacity
* `overflow: scroll` (some scenes)


### ❌ No composition layer will be created {#❌-不会创建合成层}

```css
left / top
width / height
margin / padding
background
color
```

These will return:
👉 Layout / Paint


## 5\. DevTools practical verification {#五、devtools-实战验证}

### 1️⃣ Open Layer Borders {#_1️⃣-打开-layer-borders}

```
DevTools → More Tools → Rendering
→ 勾选 Layer borders
```

* **Green Border**: Composition Layer


### 2️⃣ Demo comparison {#_2️⃣-demo-对比}

#### transform animation (Composite only) {#transform-动画-只-composite}

```css
.box {
  transition: transform 0.5s;
}
```

👉 Only the border is moving
👉 No Paint flickering


#### left animation (whole process) {#left-动画-全流程}

```css
.box {
  transition: left 0.5s;
  position: relative;
}
```

👉 Per frame:

* Layout
* Paint
* Composite


### 3️⃣Performance panel confirmation {#_3️⃣-performance-面板确认}

You will see:

* transform：🟦 Composite
* left：🟪 Layout + 🟩 Paint


## 6\. Price of Composite Layer {#六、composite-layer-的代价}

### ⚠️ More is not always better {#⚠️-不是越多越好}

#### Each composition layer: {#每个合成层}

* Occupies GPU memory
* Increase synthesis cost

#### Consequences of abusing will-change: {#滥用-will-change-的后果}

* Video memory surges
* The page becomes slower instead
* More obvious on mobile

📌 **Principle: Discard after use**

```css
.box {
  will-change: transform;
}
.box.done {
  will-change: auto;
}
```


## 7\. Why can opacity / transform "skip Paint"? {#七、为什么-opacity-transform-可以-跳过-paint}

#### Because: {#因为}

* Does not change pixel content
* Just change:

  * displacement matrix
  * alpha value

👉 Bitmap reuse


## 8\. The relationship between Composite Layer and Layout Thrashing {#八、composite-layer-与-layout-thrashing-的关系}

| Problem | Solution |
| --------- | --------- |
| Frequent Layout | transform |
| Frequent Paint | Composition Layers |
| Animation stuttering | GPU compositing |

📌 **Composite is the ultimate performance escape hatch**


## 9\. Frame Perspective {#九、框架视角}

### Why do React/Vue love transform? {#react-vue-为什么爱-transform}

```jsx
<div style={{ transform: `translateX(${x}px)` }} />
```

* Does not affect other nodes
* Interruptible/resumable
* non-blocking rendering

👉 Perfectly adapted to Fiber / Scheduler


### The convergence of React Fiber and Composite {#react-fiber-和-composite-的契合点}

* Fiber: Split JS
* Composite: split rendering

👉 **CPU / GPU each perform their own duties**


## 10\. Summary {#十、总结}

- Composite Layer is a layer mechanism introduced by browsers to improve rendering performance.
- The page will be split into multiple independent bitmap layers.
- If only transform or opacity is changed during animation,
- Browsers can skip Layout and Paint,
- Compositing directly from the GPU for higher frame rates.
- However, more compositing layers are not always better. Too many compositing layers will cause graphics memory and compositing overhead.
