The core value of Virtual List/Windowing, **The essence is:**

> 👉 **Let the browser "think" the list is very large, but in fact there are very few nodes participating in Layout/Paint**


## 1\. What exactly is the virtual list “avoiding”? {#一、虚拟列表到底在-避免-什么}

#### If a virtual list is not used (disaster scene) {#如果不用虚拟列表-灾难现场}

```
10,000 条 DOM
↓
每次滚动：
- Layout（全部参与）
- Paint（大量节点）
- Style Recalc
```

📉 FPS crashes directly


#### After using virtual list {#使用虚拟列表后}

```
可视区 20 条 + buffer 10 条 = 30 条 DOM
↓
滚动：
- 少量 transform
- 少量 style 更新
- 几乎不 Layout
```

✔️Performance linear → constant level


## 2\. Three "pitfall points" of virtual lists (core principles) {#二、虚拟列表的三大-避坑点-核心原理}

### ① DOM quantity control (most important) {#_1-dom-数量控制-最重要}

> **Complexity of Layout / Paint ≈ Number of DOM**

Virtual lists only render:

```
[ startIndex, endIndex ]
```

Rest:

* DOM does not exist
* Not participating in Render Tree
* Not participating in Layout/Paint


### ② Use "displacement" instead of "rearrangement" for scrolling {#_2-滚动用-位移-而不是-重排}

#### ❌ Wrong approach (knowing Layout) {#❌-错误做法-会-layout}

```js
item.style.top = index * itemHeight + 'px'
```

* top → affects layout
* Each item may trigger layout calculations


#### ✅ Correct approach (Composite only) {#✅-正确做法-只-composite}

```js
container.style.transform = `translateY(${offset}px)`
```

* transform → compositing layer
* Skip Layout/Paint

📌 **This is the key to a smooth virtual list**


### ③ Taking place but not rendering (scroll illusion) {#_3-占位但不渲染-scroll-illusion}

#### core structure {#核心结构}

```html
<div class="viewport">
  <div class="phantom"></div>
  <div class="content"></div>
</div>
```

```css
.viewport {
  overflow-y: auto;
  height: 400px;
}
.phantom {
  height: 100000px; /* 总高度 */
}
.content {
  position: absolute;
  transform: translateY(2000px);
}
```

#### browser perspective {#浏览器视角}

* phantom: only participate in Layout once
* content: a small amount of DOM + transform

👉 **The scroll bars are real, but the DOM is minimal**


## 3\. Comparison of complete rendering processes (very important) {#三、完整渲染流程对比-非常重要}

### Normal list scrolling {#普通列表滚动}

```
scroll
 → Layout（全部子节点）
 → Paint（大量）
 → Composite
```


### Virtual list scrolling {#虚拟列表滚动}

```
scroll
 → JS 计算 startIndex
 → transform 位移
 → Composite
```

📌 **Skip Layout/Paint directly**


## 4\. Why does scrolling itself not layout frequently? {#四、为什么滚动本身不会频繁-layout}

#### Browser optimization points {#浏览器优化点}

* scroll ≠ recalculate layout
* Just:

  * Change scroll offset
  * Crop visible area

#### But the problem is: {#但问题在于}

👉 **When there are too many child nodes, Paint and Composite are still expensive**

Virtual list directly:

* don't let them exist


## 5\. What to do with Variable Height? {#五、变高列表-variable-height-怎么办}

This is an advanced level.

#### Option 1: Fixed height (fastest) {#方案一-固定高度-最快}

* Best performance
* The simplest implementation


#### Solution 2: Highly cached (mainstream solution) {#方案二-高度缓存-主流方案}

```js
heightMap[index] = realHeight
```

* first measurement
* Use cache directly later
* Avoid repeated `getBoundingClientRect`

📌 **Prevent Layout Thrashing**


#### Solution three: IntersectionObserver (modern solution) {#方案三-intersectionobserver-现代方案}

* Asynchronous measurement
* Reduce forced layout
* Async-aware visibility


## 6\. How does DevTools verify "there is really no Layout/Paint"? {#六、devtools-怎么验证-真的没-layout-paint}

#### 1️⃣Performance panel {#_1️⃣-performance-面板}

* During scrolling:

  * Almost no Layout
  * Small amount of Composite

#### 2️⃣ Paint flashing

* Very little flicker in the visible area

#### 3️⃣ FPS meter

* Stable 60


## 7\. Why do React/Vue recommend virtual lists? {#七、react-vue-为什么都推荐虚拟列表}

#### React（react-window）

* Use transform
* Merge setState
* rAF scheduling

#### Vue（vue-virtual-scroller）

* Absolute positioning + translate
* cache height
* Reduce watcher triggers

👉 **The essence is:**

> Controlling the DOM + using compositing layers


## 8\. A minimalist "virtual list core algorithm" (for understanding) {#八、一个极简-虚拟列表核心算法-理解用}

```js
const itemHeight = 40
const visibleCount = Math.ceil(viewportHeight / itemHeight)

function onScroll(scrollTop) {
  const start = Math.floor(scrollTop / itemHeight)
  const end = start + visibleCount + buffer

  content.style.transform =
    `translateY(${start * itemHeight}px)`

  render(items.slice(start, end))
}
```


## 9\. Summary {#九、总结}

- The virtual list renders only a small amount of DOM near the visible area.
- Significantly reduce the number of nodes participating in Layout and Paint.
- Also use transform for displacement,
- Let the rolling process mainly occur in the Composite phase,
- This maintains stable rendering performance in lists with large data volumes.
