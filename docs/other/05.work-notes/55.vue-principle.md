## Overview of the template compilation process {#模板编译过程概述}

1. Compile templates into abstract syntax trees
    [You can see what an abstract syntax tree looks like here](https://astexplorer.net/) Just select the vue option
    The parsing template obtains tags, attributes, expressions, etc. through regular expressions. When it encounters a start tag, it is put into the stack. When it encounters an end tag, it is popped out of the stack and spliced into an AST abstract syntax tree. The optimizer then traverses the AST to mark static nodes. It is mainly used for virtual DOM rendering optimization.
2. Generate code based on the abstract syntax tree to generate a render function. The vue template compiler compiles the template into a render function and executes the render function to generate a vnode.Perform patch and diff based on vnode.

Use vue-loader to compile the template in the development environment.

## Responsive {#响应式}

Implementation principle:\
Monitor data changes through `Object.defineProperty`, and trigger set to update the view when the data changes.When encountering an object object, continue deep traversal to implement deep monitoring of the object. When encountering an array, redefine the array object, extend new methods, and implement data monitoring.

Disadvantages of `Object.defineProperty`:
- Deep monitoring requires recursion to the end at one time, which requires a large amount of calculation.If the data is too large, it will get stuck.
- Unable to monitor new attributes/deleted attributes (can be solved through vue.set, vue.delete)
- Arrays cannot be monitored natively and require special processing.

```js

// 触发更新视图
function updateView() {
    console.log('视图更新')
}

// 重新定义数组原型
const oldArrayProperty = Array.prototype
// 创建新对象，原型指向 oldArrayProperty ，再扩展新的方法不会影响原型
const arrProto = Object.create(oldArrayProperty);
['push', 'pop', 'shift', 'unshift', 'splice'].forEach(methodName => {
    arrProto[methodName] = function () {
        updateView() // 触发视图更新
        oldArrayProperty[methodName].call(this, ...arguments)
        // Array.prototype.push.call(this, ...arguments)
    }
})

// 重新定义属性，监听起来
function defineReactive(target, key, value) {
    // 深度监听
    observer(value)

    // 核心 API
    Object.defineProperty(target, key, {
        get() {
            return value
        },
        set(newValue) {
            if (newValue !== value) {
                // 深度监听
                observer(newValue)

                // 设置新值
                // 注意，value 一直在闭包中，此处设置完之后，再 get 时也是会获取最新的值
                value = newValue

                // 触发更新视图
                updateView()
            }
        }
    })
}

// 监听对象属性
function observer(target) {
    if (typeof target !== 'object' || target === null) {
        // 不是对象或数组
        return target
    }

    // 污染全局的 Array 原型
    // Array.prototype.push = function () {
    //     updateView()
    //     ...
    // }

    if (Array.isArray(target)) {
        target.__proto__ = arrProto
    }

    // 重新定义各个属性（for in 也可以遍历数组）
    for (let key in target) {
        defineReactive(target, key, target[key])
    }
}

// 准备数据
const data = {
    name: 'zhangsan',
    age: 20,
    info: {
        address: '北京' // 需要深度监听
    },
    nums: [10, 20, 30]
}

// 监听数据
observer(data)

// 测试
// data.name = 'lisi'
// data.age = 21
// // console.log('age', data.age)
// data.x = '100' // 新增属性，监听不到 —— 所以有 Vue.set
// delete data.name // 删除属性，监听不到 —— 所有已 Vue.delete
// data.info.address = '上海' // 深度监听
data.nums.push(4) // 监听数组

```

vue2.x

- Core API - object.defineProperty
- When the listening object needs to deeply traverse and monitor the array, special processing needs to be done on the array attributes. Process the array data and redefine the array prototype to trigger the view update.
- Deep monitoring of complex objects will be problematic because it requires recursion to the end when processing monitoring, which requires a large amount of calculation at one time.
- Unable to monitor new and deleted properties (vue.set, vue.delete)

vue3

- Core API proxy, reflect
- Deep monitoring performance is better
- Can monitor to add and delete attributes
- Can monitor array changes
- Proxy can circumvent the problem of object.defineProperty, but proxy is not compatible with all browsers

```js
// proxy创建响应式
function reactive(target = {}) {
    if (typeof target !== 'object' || target == null) {
        // 不是对象或数组，则返回
        return target
    }

    // 代理配置
    const proxyConf = {
        get(target, key, receiver) {
            // 只处理本身（非原型的）属性
            const ownKeys = Reflect.ownKeys(target)
            if (ownKeys.includes(key)) {
                console.log('get', key) // 监听
            }
    
            const result = Reflect.get(target, key, receiver)
        
            // 深度监听
            // 性能如何提升的？
            return reactive(result)
        },
        set(target, key, val, receiver) {
            // 重复的数据，不处理
            if (val === target[key]) {
                return true
            }
    
            const ownKeys = Reflect.ownKeys(target)
            if (ownKeys.includes(key)) {
                console.log('已有的 key', key)
            } else {
                console.log('新增的 key', key)
            }

            const result = Reflect.set(target, key, val, receiver)
            console.log('set', key, val)
            // console.log('result', result) // true
            return result // 是否设置成功
        },
        deleteProperty(target, key) {
            const result = Reflect.deleteProperty(target, key)
            console.log('delete property', key)
            // console.log('result', result) // true
            return result // 是否删除成功
        }
    }

    // 生成代理对象
    const observed = new Proxy(target, proxyConf)
    return observed
}
```

## vdom {#vdom}

vdom uses js to simulate the dom structure, calculate the smallest changes, and operate the dom

Why is there vdom?
- Normal DOM operation is very performance-intensive. In the past, using jQuery to operate DOM required manual adjustment, which was very laborious.Error-prone and difficult to maintain.
- When the program has a certain complexity, it is difficult to reduce the number of calculations. Using js to describe the dom nodes, calculating the smallest changes and then operating the dom has higher performance.
- vdom can implement data-driven views and control dom operations

```html
<!-- html -->
<div id="div1" class="container">
    <p>vdom</p>
    <ul style="font-size:20px">
        <li>a</li>
    </ul>
</div>
```

```js
// 翻译成vdom
{
    tag: 'div',
    props: {
        className: 'container',
        id: 'div1'
    },
    children: [
        {
            tag: 'p',
            children: 'vdom'
        },
        {
            tag: 'ul',
            props: {
                style: 'font-size:20px'
            },
            children: [{
                tag: 'li',
                children: 'a',
            }]
        }
    ]
}
```
## Overview of diff algorithm {#diff算法概述}

The following is the implementation principle of snabbdom

- The diff algorithm is the core part of vdom.
- The diff algorithm is a relatively broad concept, such as: linux diff, git diff
- Two js objects can also be diffed, and two trees can also be diffed.
- Vue dom diff mainly compares at the same level. If the tag is different, it will be deleted and rebuilt directly without further comparison. If the tag and key are the same, they are considered to be the same node (the condition of sameVnode).
- Unkeyed lists use in-place patching rather than unconditional recreation. Stable unique keys identify nodes for movement and state preservation; matching vnodes are patched.[Vue 2 list updates](https://v2.vuejs.org/v2/guide/list.html#Maintaining-State).
- patchVnode.Both old and new children perform updateChildren.Whether the old and new children have values, if the old ones have values, if the new ones do not, delete the node (revmoeVnodes).If there is no old one in the new one, create a new one (addVnodes)
- The updateChildren rules are start vs. start, end vs. end, start vs. end, end vs. start.If they all miss, check whether the key of the new node can correspond to a certain key of the old node. If not, create a new node. If they are correct, check whether the tags are the same. If they are different, create a new node and patchVnode if they are the same.This reflects the importance of key.

## Component rendering and update process {#组件的渲染更新过程}

1. first render

- Parse template into render function
- Bind responsively and monitor the data attribute through getter setter
- Execute the render function, generate vnode, and then patch (elem, vnode)

::: tip Note
Executing the render function will trigger the getter
:::

2. Update process

- Modify the data to trigger the setter (the getter that has been collected and monitored before)
- Re-execute the render function to generate newVnode
- patch（vnode,newVnode)

flowchart

When the render function is executed, the getter in the data will be touched and triggered. After the trigger, dependencies will be collected (which variable's getter is triggered, which variable will be observed). Once the data is modified, re-render is triggered, and then re-rendered to regenerate the virtual dom tree.

3. Asynchronous rendering

- $nextTick will be called back after the DOM is rendered.
- Data modifications will be integrated when the page is rendered, and multiple data modifications will only be rendered once.
- Reduce the number of DOM operations and improve performance.

::: tip Note
Requests may start in created. Vue 2 calls it synchronously after instance creation; asynchronous DOM updates do not retry it. Use mounted for work needing mounted DOM. Handle SSR, instance recreation and repeated events separately.[Lifecycle documentation](https://v2.vuejs.org/v2/api/#created).
:::

## hash mode {#hash模式}

- The hash change will trigger the browser to jump, but will not refresh the page.
- Hash changes are never committed to the server

```js
// hash 变化，包括：
// a. JS 修改 url
// b. 手动修改 url 的 hash
// c. 浏览器前进、后退
window.onhashchange = (event) => {
    console.log('old url', event.oldURL)
    console.log('new url', event.newURL)

    console.log('hash:', location.hash)
}

// 页面初次加载，获取 hash
document.addEventListener('DOMContentLoaded', () => {
    console.log('hash:', location.hash)
})

// JS 修改 url
document.getElementById('btn1').addEventListener('click', () => {
    location.href = '#/user'
})
```

The page is not refreshed when history jumps, mainly through window.pushState and window.onpopState.

To implement vue-router in vue, you need to pass the install method of the component. In the method, you may register the global $route by calling object.defineProperty.Register routerLink and routerView components through Vue.component.

```javascript
import View from './components/view'
import Link from './components/link'

export let _Vue

export function install (Vue) {
  if (install.installed && _Vue === Vue) return
  install.installed = true

  _Vue = Vue

  const isDef = v => v !== undefined

  const registerInstance = (vm, callVal) => {
    let i = vm.$options._parentVnode
    if (isDef(i) && isDef(i = i.data) && isDef(i = i.registerRouteInstance)) {
      i(vm, callVal)
    }
  }

  Vue.mixin({
    beforeCreate () {
      if (isDef(this.$options.router)) {
        this._routerRoot = this
        this._router = this.$options.router
        this._router.init(this)
        Vue.util.defineReactive(this, '_route', this._router.history.current)
      } else {
        this._routerRoot = (this.$parent && this.$parent._routerRoot) || this
      }
      registerInstance(this, this)
    },
    destroyed () {
      registerInstance(this)
    }
  })

  Object.defineProperty(Vue.prototype, '$router', {
    get () { return this._routerRoot._router }
  })

  Object.defineProperty(Vue.prototype, '$route', {
    get () { return this._routerRoot._route }
  })

  Vue.component('RouterView', View)
  Vue.component('RouterLink', Link)

  const strats = Vue.config.optionMergeStrategies
  // use the same hook merging strategy for route hooks
  strats.beforeRouteEnter = strats.beforeRouteLeave = strats.beforeRouteUpdate = strats.created
}
```
