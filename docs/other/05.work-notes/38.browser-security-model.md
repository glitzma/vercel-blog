## 1\. Overview of browser security models (overview of the overall situation first) {#一、浏览器安全模型总览-先有全局}

Think of the browser as a **sandbox operating system**:

```
用户数据（Cookie / 本地文件 / 摄像头）
        ↑
   浏览器安全边界
        ↑
网页 JS（不可信）
```

Three sentences of core goals:

- 1️⃣ **Web pages cannot attack each other**
- 2️⃣ **Web pages cannot access user privacy and system resources at will**
- 3️⃣ **When a vulnerability occurs, the scope of impact should be as small as possible**


## 2\. Core security boundary (most frequently asked in interviews) {#二、核心安全边界-面试最常问}

### 1️⃣Origin-based Isolation {#_1️⃣-同源隔离-origin-based-isolation}

This is the most basic security boundary of the browser.

#### Restricted objects {#限制的对象}

* DOM
* Cookie / Storage
* JS execution environment

```text
不同 Origin = 不同安全域
```

#### Why not "domain name"? {#为什么不是「域名」}

Because:

* Different protocols (http/https) have different security levels
* Different ports → may be different services


### 2️⃣ Process Isolation ⭐⭐⭐⭐⭐ {#_2️⃣-进程隔离-process-isolation-⭐⭐⭐⭐⭐}

> **The most important security upgrade for modern browsers**

#### Early (unsafe) {#早期-不安全}

* Multiple pages share one process
* One XSS → All fell

#### Modern browsers (represented by Chrome) {#现代浏览器-chrome-为代表}

* **Site Isolation**
* One site ≈ one rendering process

```
Browser Process
 ├── Renderer (site A)
 ├── Renderer (site B)
 └── Network Process
```

#### Benefits {#好处}

* Even if JS is compromised, it is still trapped in the process
* Prevent Specter hardware vulnerabilities


### 3️⃣ Sandbox ⭐⭐⭐⭐⭐ {#_3️⃣-沙箱-sandbox-⭐⭐⭐⭐⭐}

> JS ≠ system permissions

#### What can JS do? {#js-能做什么}

- ✅ Manipulate DOM
- ✅ Send network request
- ❌ Read file system
- ❌Access system API
- ❌ Execute local program

#### Ground floor {#底层}

* OS-level sandbox
* seccomp / AppContainer / seatbelt


## 3\. Resource access control model {#三、资源访问控制模型}

### 1️⃣ Network request model {#_1️⃣-网络请求模型}

#### JS sends request {#js-发请求}

```js
fetch(url)
```

Limitations:

* Same Origin Policy (Read Response)
* CORS (server release)
* Mixed Content (HTTPS pages cannot request HTTP)


### 2️⃣ Cookie security model {#_2️⃣-cookie-安全模型}

```http
Set-Cookie:
  HttpOnly;
  Secure;
  SameSite
```

#### The function of each field {#各字段作用}

| Field | What to guard against |
| -------- | ------ |
| HttpOnly | Anti-XSS |
| Secure | Anti-Middleman |
| SameSite | CSRF prevention |


### 3️⃣ Storage isolation {#_3️⃣-storage-隔离}

| Storage | Isolation Dimensions |
| -------------- | ------------ |
| localStorage   | origin       |
| sessionStorage | tab + origin |
| IndexedDB      | origin       |

⚠️ iframe completely isolated from different sources


## 4\. Code execution security (JS execution model) {#四、代码执行安全-js-执行模型}

### 1️⃣ JS is single-threaded, but not single-environment {#_1️⃣-js-是单线程-但不是单环境}

```
Main Thread
 ├── JS
 ├── DOM
 └── Layout
```

#### Why is it important? {#为什么重要}

* blocking ≠ safe
* Worker execution environment is cleaner


### 2️⃣ Web Worker Security {#_2️⃣-web-worker-安全}

| Capabilities | Allowed |
| ----------- | ---- |
| DOM         | ❌    |
| Cookie      | ❌    |
| fetch       | ✅    |
| postMessage | ✅    |

👉 Worker is an **isolated computing sandbox**


### 3️⃣ eval / new Function (high risk) {#_3️⃣-eval-new-function-高危}

Reason:

* Bypass static analysis
* Bypass CSP
* Perform user input

```js
eval(userInput) // ❌
```


## 5\. Cross-document communication security (postMessage) {#五、跨文档通信安全-postmessage}

### Correct usage (high-frequency test points) {#正确用法-高频考点}

```js
window.addEventListener('message', e => {
  if (e.origin !== 'https://trusted.com') return
})
```

#### Error example {#错误示例}

```js
window.addEventListener('message', e => {
  // 不校验 origin
})
```


## 6\. Permissions Model (Permissions API) {#六、权限模型-permissions-api}

Browser sensitive capabilities **explicit authorization**:

| Capabilities | Whether to pop up a window |
| --- | ---- |
| Camera | ✅ |
| Microphone | ✅ |
| Positioning | ✅ |
| Clipboard | Section |

👉 And it is:

* by site
* Can be revoked at any time


## 7\. HTTPS and transmission security {#七、https-与传输安全}

### Why is HTTPS part of the security model? {#为什么-https-是安全模型的一部分}

No HTTPS:

* Same origin policy ≈ invalid
* Cookies can be hijacked
* CSP can be tampered with

#### HSTS

```http
Strict-Transport-Security: max-age=31536000
```


## 8\. The “position” of common attacks in the security model {#八、常见攻击在安全模型中的-位置}

| Attack | Which level to break through |
| ------------ | ----------- |
| XSS | JS execution layer |
| CSRF | Cookie automatically sent |
| Clickjacking | UI Layer |
| Specter | Process Isolation |
| Supply Chain Attacks | Executing the Chain of Trust |


## 9\. The ultimate summary of the interview “security model” {#九、面试-安全模型-终极总结}

- The browser security model limits untrusted web page code to the minimum permissions through the same-origin policy, process isolation, and sandbox mechanisms; it also combines CORS, CSP, permission systems, and HTTPS to prevent data leaks, code injection, and unauthorized access.
